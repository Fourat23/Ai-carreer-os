## 🎯 Objectif du jour
Répondre en citant les sources.

## 📖 Cours approfondi
**Modèle mental : le générateur est un rédacteur sous contrainte, pas un oracle.** Ton pipeline sait retrouver les bons chunks ; l'étape finale consiste à faire rédiger une réponse par le LLM en le CONFINANT aux sources fournies. Le prompt de génération RAG a trois pièces :
1. **Le contrat** (system) : « Tu réponds UNIQUEMENT à partir des extraits fournis. Chaque affirmation cite sa source [1], [2]. Si les extraits ne permettent pas de répondre, dis-le explicitement. »
2. **Les sources numérotées** : les k chunks, chacun avec son identifiant et ses métadonnées (`[1] (guide-rh.md, §3) : ...`) — les métadonnées du jour 216 paient ici.
3. **La question.**

Les citations ne sont pas cosmétiques — elles sont le mécanisme de CONFIANCE du RAG : l'utilisateur peut vérifier, et TOI tu peux auditer (une affirmation sans source est un signal d'hallucination résiduelle). Car le RAG réduit les hallucinations, il ne les élimine pas : le modèle peut mal lire un chunk, mélanger deux sources, ou compléter un trou avec du plausible. D'où le cas le plus important à construire : **le refus honnête**. Quand le retrieval ne rapporte rien de pertinent (scores faibles, jour 219), la bonne réponse est « les documents fournis ne permettent pas de répondre » — et cette phrase vaut de l'or, car un RAG qui répond TOUJOURS est un RAG qui hallucine parfois avec des citations décoratives. Tes 2 questions hors corpus (écrites au jour 215) deviennent aujourd'hui tes tests de refus.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : le RAG bout-en-bout — question → top-k → réponse citée (ou refus).

**Raisonnement** : assembler retrieval + génération, puis tester les trois régimes : réponse trouvable, réponse partiellement trouvable, réponse absente.

**Assemblage** :
```python
def repondre(question: str, k=3) -> str:
    resultats = top_k(question, k)
    sources = "\n\n".join(
        f"[{i+1}] ({c['source']}, pos. {c['position']}) : {c['texte']}"
        for i, (score, c) in enumerate(resultats)
    )
    return llm_call(                     # ton composant du jour 214 !
        system=CONTRAT_RAG,              # sources uniquement + citations + refus
        prompt=f"Extraits :\n{sources}\n\nQuestion : {question}",
        temp=0,
    )
```

**Les trois régimes à tester** :
```
1. 5 questions dont la réponse est dans le corpus → réponse correcte,
   citations [n] présentes ET pointant vers les bons extraits (vérifie à la main)
2. 1 question dont la réponse est répartie sur 2 chunks → les deux cités ?
3. Tes 2 questions hors corpus → refus explicite, PAS de réponse inventée
   avec citations décoratives (le piège n°1 du RAG)
```

**Explication** : réutiliser `llm_call` du jour 214 te donne gratuitement retry, log et coût par question — l'architecture paie. **Variante** : pose une question dont la réponse est dans le corpus mais formulée TRÈS différemment (synonymes) — si le retrieval la rate, tu viens de rencontrer ta première limite du vectoriel pur (le lexical arrivera au jour 245).

## 🏢 Cas métier
Deux assistants documentaires en démo : l'un répond à tout avec assurance, l'autre répond avec citations cliquables et sait dire « ce n'est pas dans la documentation ». Le premier impressionne 10 minutes ; le second obtient le budget, parce que le juriste/le support/le RSSI peut VÉRIFIER. La citation + le refus honnête sont ce qui rend un RAG déployable en entreprise.

## 🎤 Question d'entretien
**« Comment fais-tu pour que ton RAG ne réponde pas n'importe quoi avec aplomb ? »** → Trois mécanismes : un contrat de génération strict (sources uniquement, citation par affirmation, refus explicite si les extraits ne suffisent pas), des scores de retrieval regardés (scores faibles → refus plutôt que génération forcée), et des tests des trois régimes — trouvable, partiel, absent. Le cas « hors corpus » est testé au même titre que le cas nominal.
