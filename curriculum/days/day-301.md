### Synthèse de la semaine
La semaine 43 a bouclé le mois 10 par la sécurité systémique d'une app IA : audit contre l'OWASP LLM Top 10 (jour 295), politique de données avec le point critique « ce qui part vers les APIs LLM externes » (296), observabilité par logs structurés et correlation id (297), gestion professionnelle des secrets — révoquer et non supprimer une clé compromise (298), threat model priorisé par le risque (299), et consolidation prouvée par 3 vraies failles corrigées (300). ### Plan de remédiation (si un critère échoue)
- **OWASP LLM flou** : rejoue le jour 295 en centrant sur le moindre privilège — du contexte (pas de données d'autrui) ET des outils (un agent injecté sans outil dangereux est inoffensif). Ce sont les deux angles morts les plus fréquents.
- **Politique de données incomplète** : le point qui bloque un déploiement entreprise est « quelles données partent vers les APIs LLM ». Reprends le jour 296 : garanties fournisseur, masquage du sensible, option modèle local.
- **Observabilité absente** : sans correlation id, un incident IA est indébuggable. Refais le jour 297 et teste : peux-tu reconstituer une session complète et diagnostiquer retrieval vs génération a posteriori ?
- **Secrets mal gérés** : c'est BLOQUANT — une clé LLM fuitée a une valeur monétaire directe. Rejoue le jour 298 : scanne l'historique git, révoque toute clé committée, centralise, sépare par environnement.

### Questions d'entretien de la semaine
1. **« Comment sécurises-tu une application LLM de bout en bout ? »** Attendu : audit OWASP LLM (injection/fuite/excès d'autonomie), moindre privilège (contexte + outils), défense en profondeur avec ancrage de sortie, observabilité, gestion des secrets, threat model priorisé.
2. **« Quelles données de tes utilisateurs partent vers des services externes ? »** Attendu : le contexte envoyé aux APIs LLM ; garanties no-training/non-rétention, masquage du sensible, modèle local pour l'ultra-confidentiel.
3. **« Une clé API a été committée par erreur : que fais-tu ? »** Attendu : la RÉVOQUER et régénérer (elle est compromise même après suppression — git a une mémoire), puis auditer l'historique et centraliser.
4. **« Comment priorises-tu tes efforts de sécurité ? »** Attendu : threat model — acteurs, surfaces, menaces, priorisation par risque (probabilité × impact), contre-mesures aux menaces prioritaires, résiduel assumé.
