## 🎯 Objectif du jour
Reconnaître les biais de données.

## 📖 Cours approfondi
**Modèle mental : un modèle apprend le monde que ses DONNÉES lui montrent — si l'échantillon est biaisé, le modèle reproduit et AMPLIFIE ce biais, quelle que soit sa sophistication. « Garbage in, garbage out » n'est pas un cliché, c'est la limite fondamentale : aucun algorithme ne corrige un échantillon qui ne représente pas la réalité qu'on veut prédire.** Avant de choisir un modèle, la vraie question est : « mes données représentent-elles la population sur laquelle le modèle sera utilisé ? ». La réponse détermine si le modèle sera juste ou systématiquement trompeur.

Les biais d'échantillonnage les plus courants :
1. **Le biais de sélection** : l'échantillon n'est pas tiré au hasard de la population cible. Un modèle entraîné sur les clients actuels pour prédire de nouveaux prospects apprend les clients CONVERTIS, pas la population visée.
2. **Le biais du survivant** : on n'observe que ce qui a « survécu », en ignorant ce qui a disparu. Analyser les entreprises qui ont réussi pour trouver « la recette » ignore toutes celles qui ont appliqué la même recette et échoué.
3. **Le biais historique / d'étiquetage** : les données reflètent des décisions passées, elles-mêmes biaisées. Un modèle de recrutement entraîné sur les embauches historiques apprend les préférences (et discriminations) passées et les perpétue.
4. **Le déséquilibre de classes** : la cible rare (fraude, churn, maladie) est sous-représentée — le modèle apprend surtout la classe majoritaire (lien direct avec les métriques, jour 162).

Ce qui rend ces biais DANGEREUX : ils sont INVISIBLES dans les métriques d'entraînement. Un modèle biaisé peut avoir d'excellentes performances SUR SES DONNÉES et échouer en production, parce que sa réalité d'entraînement diffère de la réalité réelle. On ne les détecte pas en regardant l'accuracy ; on les détecte en INTERROGEANT la provenance des données : qui/quoi est représenté, qui/quoi manque, quelles décisions ont produit ces étiquettes.

Les parades : comprendre le processus de collecte, comparer la distribution de l'échantillon à la population cible, sur/sous-échantillonner ou repondérer les classes rares, documenter les limites de représentativité (comme une carte de données). On ne « corrige » pas toujours un biais, mais on l'ASSUME et on borne les conclusions.

La règle du jour : **interroge d'abord la représentativité de tes données (sélection, survivant, historique, déséquilibre) avant de faire confiance à un modèle ; un biais d'échantillonnage invalide silencieusement les prédictions et aucune sophistication algorithmique ne le corrige**.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : identifier 3 types de biais dans des jeux de données réels et proposer des corrections.

**Exemple simple** : le biais du survivant en une image — analyser les avions REVENUS de mission pour blinder les zones touchées est une erreur : il faut blinder les zones INTACTES sur les revenants, car les avions touchés là ne sont jamais revenus. On ne voit que les survivants.

**Raisonnement pas-à-pas** : pour chaque jeu de données, se demander COMMENT il a été collecté → identifier qui/quoi manque → nommer le biais → proposer une correction ou une limite assumée.

**Mini-quiz** : (a) Pourquoi un biais d'échantillonnage est-il invisible dans les métriques d'entraînement ? (b) Qu'est-ce que le biais du survivant ? (c) Un meilleur algorithme corrige-t-il un échantillon biaisé ?
→ (a) le modèle est évalué sur les mêmes données biaisées : il « réussit » sur sa réalité faussée ; le biais n'apparaît qu'en production ou en comparant à la vraie population ; (b) ne conclure qu'à partir de ce qui a « survécu », en ignorant ce qui a disparu (les avions abattus, les startups échouées) ; (c) non — aucun algorithme ne corrige un échantillon non représentatif ; c'est la limite « garbage in, garbage out ».

**Variante** : sur ton dataset, écris une « fiche de données » (data card) : source, période, population couverte, ce qui MANQUE, et les conclusions que ces limites interdisent. C'est le livrable qui rend une analyse honnête et défendable.

## ⚠️ Erreurs fréquentes
- Se fier aux métriques d'entraînement : un biais d'échantillonnage y est invisible, il réussit sur sa réalité faussée.
- Confondre biais d'algorithme et biais de données : ici la cause est les DONNÉES, un meilleur modèle n'y change rien.
- Ignorer le biais du survivant : conclure à partir des seuls « survivants » (clients convertis, projets réussis).
- Traiter un déséquilibre de classes comme un détail : la cible rare est sous-apprise et l'accuracy trompe (jour 162).

## 🏢 Cas métier
Les biais d'échantillonnage causent les échecs de ML les plus coûteux et médiatisés : modèles de recrutement discriminants (entraînés sur des embauches historiques biaisées), modèles médicaux sous-performants sur des populations sous-représentées dans les données d'entraînement, systèmes de crédit qui perpétuent des inégalités passées. Dans chaque cas, les métriques d'entraînement étaient bonnes — le biais était dans les DONNÉES, pas dans l'algorithme. Les équipes matures auditent la représentativité AVANT de modéliser (fiches de données, comparaison à la population cible) ; celles qui foncent sur l'algorithme livrent des modèles injustes ou faux. Savoir interroger la provenance des données et documenter leurs limites est une compétence d'éthique ET de fiabilité directement valorisée.

## 🎤 Question d'entretien
**« Comment t'assures-tu qu'un modèle n'est pas biaisé par ses données d'entraînement ? »** → Je pars du principe qu'un modèle apprend le monde que ses données lui montrent, donc j'interroge la REPRÉSENTATIVITÉ avant de modéliser. Je cherche les biais classiques : sélection (l'échantillon n'est pas tiré au hasard de la population cible), survivant (on n'observe que ce qui a « survécu »), historique/étiquetage (les labels reflètent des décisions passées biaisées), et déséquilibre de classes. Le danger est qu'ils sont INVISIBLES dans les métriques d'entraînement — le modèle réussit sur sa réalité faussée et échoue en production. Je compare la distribution de l'échantillon à la population visée, je documente ce qui manque dans une fiche de données, et j'assume les limites. Aucune sophistication algorithmique ne corrige un échantillon non représentatif.
