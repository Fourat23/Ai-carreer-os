# Correction / Grille — Jour 7 : Revue de la semaine 1

[← Retour au jour 7](../days/day-007.md)

> Une revue ne « se corrige » pas : elle s'ÉVALUE. Voici l'attendu, la grille et les critères de passage.

## 🎯 Attendu de la semaine
Thème : **Terminal, Git, premiers programmes JavaScript**. Premier contact avec l'environnement de travail réel : terminal, Git, Node. Es-tu capable de créer un dossier, un fichier JS, l'exécuter, le committer, sans chercher la commande ?

## ✅ Grille d'évaluation (note chaque axe de 0 à 5)
- **Test pratique réussi** dans le temps imparti : En 45 min chrono, sans notes : crée un dossier projet, initialise Git, écris un script JS qui affiche les nombres de 1 à 100 avec 'Fizz' pour les multiples de 3, commite en 3 commits logiques, crée une branche 'test', modifie le script, merge-la.
- **Test théorique** (réponds de mémoire puis auto-corrige) : 10 questions à écrire de mémoire : rôle de `cd`, `ls`, `mkdir` ; différence working directory/staging/commit ; que fait `git clone` ; qu'est-ce qu'une variable ; différence `let`/`const` ; que retourne une fonction sans `return` ; types primitifs JS ; que fait `===` vs `==` ; qu'est-ce que Node.js ; à quoi sert un `.gitignore`.
- **Mini-projet / livrable** conforme : Script 'profil.js' : un objet qui te décrit (nom, objectif, compétences[]), et des fonctions qui l'affichent joliment dans le terminal.
- **Exercice d'architecture** fait sérieusement : Dessine (papier) ce qui se passe quand tu tapes `node script.js` : où est le fichier, qui le lit, qui l'exécute, où va la sortie. Pas besoin d'être exact — l'objectif est de te forcer à formuler un modèle mental.

## 📋 Checklist de validation
- [ ] Je navigue au terminal sans GUI
- [ ] Je fais init/add/commit/log sans chercher
- [ ] Je sais lire un message d'erreur JS et trouver la ligne
- [ ] J'ai commité chaque jour cette semaine

## 🚦 Critères de passage à la semaine suivante
- [ ] Test pratique réussi en < 45 min
- [ ] Au moins 8/10 au test théorique
- [ ] Auto-éval ≥ 3/5 sur les jours 1-6

## ⚠️ Erreurs fréquentes en revue
- Se sur-noter (familiarité ≠ maîtrise) : ne compte que ce que tu produis SEUL et sais EXPLIQUER.
- Bâcler le test théorique en le relisant au lieu de répondre de mémoire (rappel actif).
- Avancer malgré des critères non atteints : mieux vaut consolider 2-3 jours que bâtir sur du sable.
- Oublier de mettre à jour ses scores de compétences dans l'application.
