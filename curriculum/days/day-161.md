## 🔁 Revue hebdomadaire

**Thème de la semaine :** Régression linéaire et logistique, train/test, métriques

### Bilan
Tes premiers modèles, compris et non subis : régression linéaire (prédire un nombre) et logistique (prédire une classe), avec une évaluation honnête.

### Test pratique
90 min : sur un dataset fourni — split train/test propre, baseline naïve (moyenne / classe majoritaire), régression linéaire puis logistique avec scikit-learn, métriques adaptées (MAE/RMSE ; accuracy/précision/rappel/F1), et 5 lignes de conclusion honnête vs baseline.

### Test théorique
Pourquoi une baseline ; pourquoi ne JAMAIS évaluer sur le train ; précision vs rappel avec un cas médical ; que signifie un coefficient de régression ; qu'est-ce que la fuite de données (leakage) ?

### Synthèse de la semaine
La semaine 23 a posé les fondations du machine learning supervisé : le workflow standard fit/predict/score et l'API uniforme de scikit-learn (jour 155), la régression linéaire et l'interprétation de ses coefficients (156), le train/test split, la baseline et surtout la DÉMONSTRATION du data leakage (157), le choix des métriques de régression selon le coût métier — MAE/RMSE/R² (158), la régression logistique qui classe via une probabilité et un seuil ajustable (159), et le rapport de modèle orienté décision (160). Le fil rouge : **le ML est un PROCESSUS rigoureux — split honnête, baseline, évaluation sans leakage, métrique choisie selon le métier, communication orientée décision — et l'algorithme n'est qu'un composant interchangeable de ce processus**. ### Plan de remédiation (si un critère échoue)
- **Évaluation sur le train / pas de baseline** : rejoue le jour 157 — réserve un test jamais vu, pose une baseline triviale que le modèle doit battre.
- **Data leakage** : jour 157 — splitte AVANT tout préprocessing, ajuste le préprocessing sur le train seul ; méfie-toi d'un score trop beau.
- **Coefficients mal interprétés** : jour 156 — effet par unité, toutes choses égales par ailleurs, attention à l'échelle des features.
- **Métrique mal choisie** : jour 158 — MAE (toutes erreurs égales), RMSE (grosses erreurs coûteuses), R² (relatif) ; relier au coût métier.
- **Logistique mal comprise** : jour 159 — elle prédit une probabilité (sigmoïde) puis applique un seuil ajustable ; matrice de confusion, pas taux global.
- **Rapport non actionnable** : jour 160 — question métier d'abord, vs baseline, limites assumées, recommandation.

### Questions d'entretien de la semaine
1. **« Décris le workflow d'un projet ML. »** Attendu : charger → split → fit (train) → predict/score (test) ; API uniforme ; évaluer la généralisation, pas la mémorisation.
2. **« Qu'est-ce que le data leakage ? »** Attendu : info du test/futur qui fuit dans l'entraînement, gonfle les scores sans erreur visible ; split d'abord, préprocessing sur le train seul.
3. **« MAE vs RMSE vs R² ? »** Attendu : MAE robuste en unités réelles, RMSE punit les grosses erreurs, R² relatif ; choisir selon le coût métier.
4. **« Pourquoi la régression logistique classe-t-elle ? »** Attendu : sigmoïde transforme un score linéaire en probabilité, seuil ajustable ; matrice de confusion.
5. **« Comment présentes-tu un modèle à un décideur ? »** Attendu : question métier, méthode reproductible, performance vs baseline traduite métier, limites assumées, recommandation.
