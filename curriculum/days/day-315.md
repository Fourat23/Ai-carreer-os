### Plan de remédiation (si un critère échoue)
- **Ingestion fragile** (plante sur un fichier moche, ou bouillie non détectée) : c'est le plafond de qualité de tout le projet. Rejoue le jour 309 : robustesse (journalise et continue) + INSPECTION du texte extrait sur les 5 PDF réels.
- **Config non justifiée** (valeurs par défaut au lieu de la config mois 9) : tu gaspilles ton mois d'évaluation. Reprends le jour 310 : applique la config MESURÉE, pas des défauts.
- **Hybride supposé** (pas re-validé sur DocSense) : un gain ne se transpose pas. Rejoue le jour 311 : re-mesure le rappel@k avec/sans sur le corpus DocSense.
- **Génération sans vérification/refus** : c'est ce qui rend DocSense déployable — sans ça, c'est un perroquet confiant dangereux. Reprends le jour 312 : citations vérifiées + refus calibré, testés sur les 3 régimes. BLOQUANT pour un usage professionnel.

### Questions d'entretien de la semaine
1. **« Quelle est la partie la plus déterminante d'un pipeline RAG ? »** Attendu : l'ingestion (plafonne la qualité) ; robustesse aux fichiers moches, inspection du texte extrait, métadonnées pour citations.
2. **« Tu réutilises un RAG déjà construit : qu'est-ce qui change pour le projet final ? »** Attendu : construire propre d'emblée (config mesurée + hexagonal), pas bricoler puis refactorer ; DocSense démontre la maîtrise, pas l'apprentissage.
3. **« Une technique de retrieval validée ailleurs : tu la gardes telle quelle ? »** Attendu : re-valider sur le corpus réel (un gain ne se transpose pas) ; arbitrage coût/latence.
4. **« Qu'est-ce qui rend un assistant documentaire digne de confiance ? »** Attendu : citations vérifiables + refus honnête + format soigné ; le refus est une feature ; déployable auprès d'un professionnel.
