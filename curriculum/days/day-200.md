## 🎯 Objectif du jour
Estimer et maîtriser les coûts.

## 📖 Cours approfondi
**Modèle mental : les tokens sont la devise, tu es le comptable.** Tout appel LLM se paie en tokens : le prix = (tokens d'entrée × tarif input) + (tokens de sortie × tarif output), et la sortie coûte typiquement 3 à 5× plus cher que l'entrée. Un token ≈ ¾ de mot en anglais, un peu moins en français. Ordres de grandeur à connaître PAR CŒUR : une page de texte ≈ 500 tokens ; un system prompt costaud ≈ 1 000-2 000 ; une conversation qui traîne ≈ 10 000+.

Les trois lois du coût :
1. **L'historique se re-paie à chaque tour.** La conversation renvoie TOUT le contexte à chaque appel : le tour 20 coûte bien plus que le tour 2. Le coût d'une conversation croît quadratiquement si on ne tronque rien.
2. **Le system prompt se paie à chaque appel.** 2 000 tokens de system prompt × 100 000 appels/mois = 200 M de tokens payés pour du texte identique (d'où le prompt caching en production).
3. **max_tokens borne le pire cas.** Sans plafond, une réponse-fleuve fait exploser le poste le plus cher.

L'exercice du jour — chiffrer une app à l'échelle — est EXACTEMENT ce qu'un CTO demande avant tout feu vert : « ça coûte combien à 10 000 utilisateurs ? ». Savoir répondre avec un calcul posé (hypothèses explicites, fourchette) vaut plus qu'une démo.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : chiffrer le coût mensuel d'un assistant support à l'échelle.

**Raisonnement** : décomposer en unités (l'échange), chiffrer l'unité, multiplier, PUIS chercher les leviers.

**Calcul type** :
```
Hypothèses (à écrire noir sur blanc) :
- 1 000 utilisateurs, 5 conversations/mois, 6 échanges/conversation
- system prompt : 1 500 tk ; message user : 100 tk ; réponse : 300 tk
- historique moyen renvoyé par échange : 1 200 tk

Par échange : input ≈ 1500 + 1200 + 100 = 2 800 tk ; output ≈ 300 tk
Mensuel : 30 000 échanges → 84 M tk input, 9 M tk output
Coût (tarifs du modèle choisi, ex. 3 $/M in, 15 $/M out) :
84 × 3 + 9 × 15 = 252 + 135 ≈ 390 $/mois

Leviers, par ordre d'impact :
1. modèle plus petit pour les échanges simples (÷5 à ÷10)
2. prompt caching sur le system prompt (÷~10 sur ce poste)
3. tronquer l'historique aux N derniers tours
4. max_tokens serré sur les réponses
```

**Explication** : le résultat compte moins que la MÉTHODE : hypothèses posées → unité chiffrée → échelle → leviers. **Variante** : refais le calcul avec un modèle 10× moins cher sur 80 % des échanges (routage simple/complexe) — c'est l'architecture réelle de beaucoup de produits.

## 🏢 Cas métier
Une startup lance un assistant IA gratuit, 50 000 utilisateurs arrivent, la facture API dépasse le salaire de l'équipe. Ce scénario est un CLASSIQUE de 2023-2025. Le dev qui sait estimer AVANT le lancement — et proposer les leviers — évite à l'entreprise ce mur. C'est une compétence business portée par un calcul de CM2.

## 🎤 Question d'entretien
**« Notre feature IA coûterait combien à 10 000 utilisateurs ? »** → Je pose les hypothèses (appels/utilisateur, tokens in/out par appel), je chiffre l'unité, je multiplie, je donne une fourchette. Puis les leviers : modèle adapté à chaque tâche, caching du system prompt, troncature d'historique, max_tokens. L'important : montrer la méthode, pas un chiffre magique.
