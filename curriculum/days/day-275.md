# Jour 275 — Modes d'échec des agents

[← Dashboard](../../) · [Semaine 40](../week-40.md) · [Mois 10](../month-10.md) · [Correction](../solutions/day-275-solution.md)

## 🎯 Objectif du jour
Reconnaître les dérives.

## 📖 Cours approfondi
**Modèle mental : un agent échoue de façons SPÉCIFIQUES et reconnaissables — les nommer, c'est pouvoir les diagnostiquer au lieu de les subir.** Un agent qui « ne marche pas » ne dit rien ; « l'agent est en boucle car il ne reconnaît pas que sa sous-tâche est finie » est un diagnostic actionnable. Aujourd'hui tu PROVOQUES et documentes les trois modes d'échec canoniques — la démarche du red teaming (jour 260) appliquée au comportement des agents.

Les trois modes d'échec fondamentaux :
1. **La boucle** : l'agent répète la même action (ou un cycle d'actions) sans progresser vers l'objectif. Causes typiques : il ne reconnaît pas qu'une étape est accomplie, il ré-interprète la même observation, ou deux actions s'annulent. Symptôme dans les traces : les mêmes appels d'outils reviennent. Le budget d'itérations (jour 274) BORNE le dégât mais ne corrige pas la cause.
2. **La dérive d'objectif** : l'agent s'éloigne progressivement de la tâche initiale — happé par un sous-problème, une observation intéressante mais hors sujet, ou une reformulation qui glisse. Symptôme : les dernières actions n'ont plus de lien clair avec l'objectif de départ. Cause : l'objectif se dilue dans un historique long (le « lost in the middle » des agents).
3. **Le mauvais usage d'outil** : l'agent appelle le bon outil avec de mauvais arguments, le mauvais outil pour la tâche, ou un outil quand aucun n'était nécessaire. Cause : descriptions d'outils ambiguës (jour 213) ou observation mal interprétée.

Pourquoi c'est LE jour qui rend les agents utilisables : ces modes d'échec sont INHÉRENTS à l'autonomie — plus un agent est libre de décider, plus il peut mal décider. Les reconnaître dans les traces (d'où l'importance des traces, jour 274) permet les parades : détection de boucle (répétition d'action → arrêt ou changement de stratégie), rappel périodique de l'objectif dans le contexte, descriptions d'outils durcies, validation des arguments. Un ingénieur d'agents ne cherche pas à empêcher TOUS les échecs (impossible avec de l'autonomie) mais à les DÉTECTER et LIMITER — la même posture que la sécurité (jour 265).

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : provoquer et documenter les 3 modes d'échec sur ton agent du jour 274.

**Exemple simple** : force une boucle en donnant un objectif dont l'agent ne peut pas reconnaître l'accomplissement (« assure-toi que le fichier est parfait ») — il tournera jusqu'au budget. Tu VOIS la boucle dans les traces.

**Raisonnement pas-à-pas** : provoquer chaque mode délibérément, l'identifier dans les traces, en décrire la cause, esquisser une parade.

**Protocole** :
```
1. BOUCLE : objectif au critère d'accomplissement flou, ou deux outils qui
   s'annulent. Traces attendues : mêmes actions répétées jusqu'au budget.
   Parade : détection de répétition (même action 2-3x → stop/changer).
2. DÉRIVE D'OBJECTIF : objectif large + un outil qui renvoie une observation
   « intéressante » hors sujet. Traces : les derniers tours n'ont plus de lien
   avec l'objectif. Parade : réinjecter l'objectif à chaque tour (ou périodiquement).
3. MAUVAIS USAGE D'OUTIL : deux outils aux descriptions proches, ou une tâche
   sans outil adapté. Traces : appel du mauvais outil / arguments erronés.
   Parade : descriptions durcies (jour 213) + validation des arguments.
Pour CHAQUE mode : trace annotée + cause + parade testée.
```

**Mini-quiz** : (a) Le budget d'itérations corrige-t-il la cause d'une boucle ? (b) Quelle est la cause typique de la dérive d'objectif ? (c) Peut-on empêcher TOUS les modes d'échec d'un agent ?
→ (a) non, il borne le dégât mais pas la cause ; (b) l'objectif se dilue dans un historique long ; (c) non — l'autonomie implique le risque d'erreur ; on DÉTECTE et LIMITE, on n'élimine pas.

**Variante** : après avoir ajouté tes parades (détection de boucle, rappel d'objectif), re-provoque les mêmes échecs — combien sont maintenant détectés/évités ? La parade se PROUVE par la re-mesure, comme une défense de sécurité (jour 261).

## 🏢 Cas métier
Les échecs d'agents en production sont ces trois modes, à l'échelle : un agent support qui boucle sur une demande qu'il ne sait pas résoudre (coût qui explose), un agent qui dérive et exécute une action hors périmètre, un agent qui appelle le mauvais outil (envoie un email au mauvais destinataire). Les équipes qui ont CATALOGUÉ ces modes les détectent et les bornent ; celles qui découvrent en production paient en incidents et en factures. Savoir nommer et provoquer les modes d'échec est une compétence de fiabilité d'agents directement valorisée.

## 🎤 Question d'entretien
**« Quels sont les modes d'échec typiques d'un agent, et comment les gères-tu ? »** → Trois : la boucle (répète sans progresser — cause : ne reconnaît pas l'accomplissement ; parade : détection de répétition), la dérive d'objectif (s'éloigne de la tâche — cause : objectif dilué dans un historique long ; parade : réinjection de l'objectif), le mauvais usage d'outil (mauvais outil/arguments — cause : descriptions ambiguës ; parade : descriptions durcies + validation). Ces modes sont inhérents à l'autonomie : je ne cherche pas à les éliminer mais à les DÉTECTER dans les traces et les LIMITER — même posture que la sécurité.

## 🚀 Pourquoi ça comptera plus tard
- **Bankable** : un catalogue des modes d'échec d'agents AVEC traces vécues et parades mesurées est un artefact rare — il prouve une expérience concrète de la fiabilité d'agents, pas une lecture.
- Ces modes justifient les garde-fous du jour 274 et la doctrine agent/workflow (jour 278) : si un workflow déterministe suffit, il n'a AUCUN de ces modes.
- Le réflexe « provoquer, nommer, détecter, limiter » se réapplique à tout système autonome — agents, pipelines, orchestrations.

## 🧩 Questions de réflexion (à faire seul)
- Ton agent tourne en boucle sans jamais conclure : quel garde-fou l'aurait arrêté, et pourquoi la boucle est-elle le mode d'échec le plus courant d'un agent ?
- Un agent « dérive » de son objectif initial au fil des tours : comment le repères-tu dans les traces, et qu'est-ce qui distingue une dérive d'une exploration légitime ?
- Pourquoi documenter tes propres échecs d'agent (vécus, avec traces) vaut-il mieux, en entretien, que réciter une liste de modes d'échec lue en ligne ?
