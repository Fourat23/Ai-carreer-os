## 🎯 Objectif du jour
Diagnostiquer avec les courbes.

## 📖 Cours approfondi
**Modèle mental : l'overfitting est une mémorisation, la régularisation une gêne salutaire.** Quand le réseau a trop de capacité pour trop peu de données, il apprend les exemples PAR CŒUR (bruit compris) au lieu d'apprendre le motif. Symptôme sur les courbes : loss train qui plonge, loss validation qui remonte — le grand écart.

Les trois remèdes du jour : le **dropout** (éteindre aléatoirement des neurones à l'entraînement — chaque neurone doit devenir utile SANS compter sur ses voisins, ce qui interdit les mémorisations fragiles) ; l'**early stopping** (s'arrêter quand la validation cesse de s'améliorer — pourquoi continuer à mémoriser ?) ; et la **réduction de capacité** (moins de neurones = moins de place pour le par-cœur). La méthode expérimentale du mois 6 s'applique intégralement : UNE variable à la fois, seed fixée, tableau de résultats. Aujourd'hui tu PROVOQUES un overfitting (petit sous-ensemble de MNIST, gros réseau), puis tu le soignes, mesures à l'appui.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : provoquer puis corriger un overfitting.

**Raisonnement** : réduire les données amplifie la mémorisation ; on soigne ensuite par dropout et early stopping, en comparant les courbes.

**Protocole** :
```python
petit_train = Subset(train_ds, range(1000))       # 1000 images seulement
gros_modele = nn.Sequential(nn.Flatten(), nn.Linear(784, 512), nn.ReLU(),
                            nn.Linear(512, 512), nn.ReLU(), nn.Linear(512, 10))
# Run A : tel quel, 40 epochs → courbes train/val divergent (overfit VISIBLE)
# Run B : + nn.Dropout(0.5) après chaque ReLU → l'écart se réduit
# Run C : + early stopping (garder le modèle à la meilleure val_acc)
```

**Explication** : A est le témoin ; B et C changent UNE chose chacun. Le dropout ne s'active qu'en mode train (model.eval() le coupe — d'où l'importance du rituel d'hier). **Variante** : run D avec le modèle RÉDUIT (784→64→10) sans dropout — souvent aussi efficace : la capacité est un levier, pas un détail.

## 🏢 Cas métier
Le fine-tuning d'un modèle sur un petit corpus d'entreprise (500 documents) est un terrain d'overfitting idéal : sans ces réflexes, le modèle récite le corpus au lieu de généraliser. Les remèdes d'aujourd'hui sont exactement ceux qu'on applique alors.

## 🎤 Question d'entretien
**« Comment détectes-tu et corriges-tu l'overfitting en deep learning ? »** → Détection : l'écart croissant entre loss train et validation. Remèdes, dans l'ordre de coût : plus de données, moins de capacité, dropout, early stopping — en changeant une variable à la fois et en comparant les courbes.
