## 🎯 Objectif du jour
Cadrer LivreAPI : schéma SQLite, contrat d'API, plan de tests Postman.

## 📖 Cours approfondi
**Concepts abordés :** Modélisation · Contrat d'API · Tests planifiés · Backlog.

Le cadrage d'un projet backend commence par les DONNÉES : un mauvais schéma condamne l'API (requêtes tortueuses, incohérences, migrations douloureuses). Les emprunts sont une table de LIAISON : elle relie livre + membre et porte ses propres données (dates). C'est le pattern à reconnaître partout (inscriptions, participations, commandes).

Le CONTRAT d'API s'écrit AVANT le code : endpoints, verbes, statuts, corps — c'est une promesse que Postman vérifiera. Coder d'abord et documenter ensuite produit des APIs incohérentes ; promettre d'abord force la cohérence.

Question de robustesse du modèle à te poser systématiquement : « et si un livre a plusieurs auteurs ? » — si la réponse casse ton schéma, il faut une table de liaison de plus. Anticiper UNE évolution probable est du bon design ; en anticiper dix est de la sur-ingénierie.
