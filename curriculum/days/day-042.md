### Synthèse de la semaine
La semaine 6 a fait passer du code « qui marche » à du code SÛR et LISIBLE. TypeScript (jour 36) : un contrat vérifié à la compilation qui déplace les bugs de type de la production vers l'éditeur ; `any` désactive, `unknown` force la vérification. Les types avancés (jour 37) : rendre les états illégaux irreprésentables — unions littérales, interfaces, génériques, exhaustivité vérifiée par le compilateur. La POO (jour 38) : programmer contre un CONTRAT (interface) pas une implémentation, le polymorphisme comme pilier central, composition > héritage. Les design patterns (jour 39) : des NOMS sur des solutions récurrentes, un vocabulaire — et la sur-ingénierie comme anti-pattern. Le clean code (jour 40) : optimiser pour le lecteur futur, un bon nom rend un commentaire inutile. Le débogage méthodique (jour 41) : une enquête (reproduire → isoler → prouver → corriger la cause), pas une loterie. Le fil rouge : **on ne se contente plus de faire fonctionner le code — on le rend vérifiable par le compilateur, extensible par des contrats, lisible pour le prochain, et diagnosticable par une méthode.** Ces réflexes de qualité conditionnent tout le Projet 1 (semaine 7) et la crédibilité de ton portfolio.
