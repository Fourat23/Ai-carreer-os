## 🎯 Objectif du jour

## 📖 Cours approfondi
**Modèle mental : l'ingestion est la douane des documents — ce qui entre sale ressort sale dans toutes les réponses.** Jusqu'ici ton RAG mangeait du texte propre. Les vrais corpus sont des PDF (mise en page, colonnes, en-têtes/pieds de page, tableaux) et du Markdown (titres, code, listes). La qualité de l'extraction borne tout le reste : un PDF mal extrait produit des chunks illisibles, donc des embeddings flous, donc un retrieval qui rate — et tu chercheras le bug partout sauf au bon endroit.

Les leçons du terrain :
1. **Le PDF est un format d'AFFICHAGE, pas de contenu.** L'extraction (pypdf, pdfplumber) récupère du texte positionné, pas une structure : les colonnes peuvent s'entremêler, les tableaux deviennent de la bouillie, les en-têtes/pieds se répètent dans chaque page. RÈGLE : inspecter le texte extrait AVANT de chunker (les 20 chunks lus du jour 216, appliqués à l'extraction).
2. **Le Markdown est ton meilleur ami** : la structure (titres, sections) est explicite et GRATUITE. Conserve-la dans les métadonnées (`section: "Installation > Prérequis"`) — le chunking par structure (jour 240) et le filtrage (jour 229) s'en nourriront.
3. **Les métadonnées s'enrichissent** : chaque chunk porte désormais source, page (PDF) ou section (Markdown), type de document. C'est ce qui transforme une citation vague en citation VÉRIFIABLE (« guide.pdf, page 12 »).
4. **Le nettoyage est un pipeline assumé** : suppression des en-têtes répétés, normalisation des espaces, gestion des pages vides — chaque règle de nettoyage est écrite, testée sur un cas, et documentée (car chaque règle peut aussi DÉTRUIRE du contenu légitime).

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : ingérer PDF et Markdown avec métadonnées par chunk.

**Raisonnement** : un extracteur par format qui produit le MÊME format pivot, puis inspection comparative.

**Implémentation** :
```python
# ingest.py — chaque extracteur produit le format pivot :
# [{texte, meta: {source, type, page|section}}]

def extraire_markdown(chemin) -> list[dict]:
    sections = decouper_par_titres(lire(chemin))     # regex sur ^#{1,3}
    return [{"texte": s.contenu,
             "meta": {"source": chemin.name, "type": "md",
                      "section": s.chemin_titres}}    # "Install > Prérequis"
            for s in sections]

def extraire_pdf(chemin) -> list[dict]:
    pages = pypdf_extraire(chemin)
    pages = [nettoyer(p) for p in pages]              # en-têtes, espaces
    return [{"texte": p.texte,
             "meta": {"source": chemin.name, "type": "pdf", "page": p.num}}
            for p in pages if p.texte.strip()]
```

**Inspection comparative (le cœur du jour)** :
```
1. Extrais un PDF réel → lis les 3 premières pages extraites à côté de
   l'original : colonnes mélangées ? tableaux détruits ? en-têtes répétés ?
2. Documente ce qui est PERDU (tableaux, images, mise en forme) — la liste
   des limites vaut autant que le code.
3. Vérifie que les citations remontent : pose une question dont la réponse
   est dans le PDF → la réponse cite « source, page N » et la page est la bonne.
```

**Explication** : le format pivot (`{texte, meta}`) est ce qui permet d'ajouter un format demain (HTML, DOCX) sans toucher au reste du pipeline — le contrat du jour 221 en action. **Variante** : ingère un PDF avec un tableau important et observe ce que devient le tableau dans les chunks — tu comprendras pourquoi « question sur un tableau » est un cas d'échec classique du RAG naïf.

## 🎤 Question d'entretien
**« Quels problèmes pose l'ingestion de PDF dans un RAG ? »** → Le PDF est un format d'affichage : l'extraction donne du texte positionné, pas une structure — colonnes entremêlées, tableaux détruits, en-têtes répétés dans chaque page. Ma pratique : inspecter le texte extrait avant de chunker, nettoyer par règles documentées, conserver page/section en métadonnées pour des citations vérifiables, et documenter ce qui est perdu (tableaux complexes → traitement dédié si le besoin le justifie).
