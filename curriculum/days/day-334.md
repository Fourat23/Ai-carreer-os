## 🎯 Objectif du jour
Prouver la valeur.

## 📖 Cours approfondi
**Modèle mental : le rapport qualité v1.0 PROUVE la valeur de DocSense par les chiffres — la trajectoire baseline → v1.0 sur toutes les dimensions, et les 3 améliorations les plus rentables documentées.** Après la baseline (jour 319) et un mois d'améliorations, tu produis le rapport final : ce que DocSense valait au départ, ce qu'il vaut maintenant, et POURQUOI (quelles améliorations ont le plus payé). C'est le document qui transforme le travail de qualité en preuve démontrable — pour le portfolio, pour l'entretien, pour un manager.

Ce que le rapport qualité v1.0 contient :
1. **La trajectoire chiffrée baseline → v1.0** : sur toutes les dimensions (rappel@k, fidélité, pertinence, exactitude par type, latence, coût). « Exactitude globale 0,82 → 0,92 (+0,10) » est une preuve ; « c'est mieux » est une impression. La trajectoire multidimensionnelle montre aussi les arbitrages (une amélioration de qualité qui a coûté un peu de latence, assumée).
2. **Les 3 améliorations les plus rentables** : parmi tout ce que tu as fait, lesquelles ont apporté le plus de gain (par rapport à leur coût) ? Chacune documentée : le problème (issu de la baseline), le changement, l'effet mesuré (avant/après), la décision. C'est l'analyse de RENTABILITÉ des améliorations — le gain par unité d'effort, un raisonnement d'ingénieur.
3. **La méthode reproductible** : le rapport rappelle comment tout a été mesuré (golden set versionné, harnais, juge validé) pour qu'un lecteur puisse refaire. Chaque chiffre pointe vers une mesure reproductible — c'est ce qui rend le rapport crédible et défendable.

Pourquoi c'est le document qui vend le projet : un projet IA sans rapport chiffré est jugé sur une impression (« ça a l'air bien ») ; un projet avec un rapport qualité (baseline → final, améliorations rentables documentées, méthode reproductible) est jugé sur des PREUVES. C'est ce qui débloque les budgets en entreprise et impressionne les recruteurs. La phrase « j'ai fait passer l'exactitude de 0,82 à 0,92, voici les 3 améliorations qui ont le plus payé et le tableau reproductible » démontre que tu sais non seulement améliorer un système IA, mais PROUVER et COMMUNIQUER cette amélioration — la compétence complète qui distingue un ingénieur IA d'un bricoleur. C'est aussi la matière première de l'étude de cas projet (jour 339) et de la démo (jour 338).

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : le rapport qualité v1.0 de DocSense — trajectoire baseline → final, 3 améliorations les plus rentables.

**Exemple simple** : une ligne de trajectoire prouve — « exactitude sur les synthèses : 0,55 (baseline) → 0,78 (v1.0), grâce au prompt de synthèse structuré, mesuré sur le golden set ». Chiffre + cause + méthode.

**Raisonnement pas-à-pas** : compiler la trajectoire multidimensionnelle, identifier les 3 améliorations les plus rentables (gain/effort), rappeler la méthode reproductible.

**Structure du rapport** :
```markdown
# DocSense — Rapport qualité v1.0
## Méthode (reproductible)
  golden set v1 (40 questions), harnais, juge validé (kappa) — un tiers peut refaire
## Trajectoire baseline v0 → v1.0 (toutes dimensions)
  | dimension          | v0    | v1.0  | delta |
  | exactitude globale | 0,82  | 0,92  | +0,10 |
  | synthèses          | 0,55  | 0,78  | +0,23 |
  | rappel@3           | 0,84  | 0,90  | +0,06 |
  | latence p95        | 2,6s  | 2,9s  | +0,3s | ← coût assumé du reranking
## Les 3 améliorations les plus rentables (gain/effort)
  1. prompt de synthèse structuré → +0,23 sur les synthèses (effort faible)
  2. reranking → +0,06 rappel (effort moyen, +latence assumée)
  3. [3e amélioration mesurée]
## Limites assumées : ce qui plafonne encore, pistes futures
```

**Mini-quiz** : (a) Qu'est-ce qui distingue « +0,10 d'exactitude, voici le tableau » de « c'est mieux » ? (b) Que signifie « amélioration rentable » ? (c) Pourquoi rappeler la méthode dans le rapport ?
→ (a) une preuve chiffrée et reproductible vs une impression ; (b) le plus de gain par unité d'effort/coût ; (c) pour que le lecteur puisse refaire — c'est ce qui rend le rapport crédible et défendable.

**Variante** : classe TOUTES tes améliorations par rentabilité (gain/effort) — tu découvriras souvent que les plus rentables ne sont pas les plus impressionnantes techniquement (un prompt bien tourné bat parfois un reranking complexe). C'est une leçon sur où mettre l'effort.

## 🏢 Cas métier
Le rapport qualité chiffré est ce qui transforme un projet IA en preuve de valeur : en entreprise, un data scientist qui présente « exactitude +10 points, voici les améliorations rentables et le tableau reproductible » obtient la reconnaissance et le budget ; celui qui dit « le système est meilleur maintenant » ne convainc pas. Pour un portfolio, un rapport qualité v1.0 (baseline → final, améliorations documentées, méthode reproductible) est ce qui prouve à un recruteur que tu sais non seulement construire un système IA mais MESURER et COMMUNIQUER sa qualité — la compétence complète. « J'ai fait passer l'exactitude de 0,82 à 0,92, voici les 3 améliorations les plus rentables » est une histoire de valeur chiffrée qui distingue un ingénieur IA d'un bricoleur, et qui alimente directement l'étude de cas et la démo du projet.
