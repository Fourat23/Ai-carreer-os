## 🎯 Objectif du jour
Remplacer les boucles de transformation et de sélection par map/filter avec naturel, chaîner proprement, et savoir quand une boucle reste préférable.

## 📖 Cours approfondi
**Concepts abordés :** map : transformer 1-pour-1 · filter : sélectionner · Chaînage · Immutabilité de ces méthodes · Lisibilité déclarative vs impérative · Quand préférer la boucle.

Hier tu as ÉCRIT monMap et monFilter. Aujourd'hui tu utilises les vrais, en comprenant exactement ce qu'ils font (puisque tu les as faits).

- **map** : transformation 1-pour-1. n éléments entrent, n sortent, chacun transformé. `prix.map(p => p * 1.2)`. Si ta callback ne TRANSFORME pas (elle affiche, elle pousse ailleurs), map est le mauvais outil (forEach, ou boucle).
- **filter** : sélection. n entrent, 0 à n sortent, inchangés. La callback est un PRÉDICAT (retourne un booléen honnête).
- **Chaînage** : `employes.filter(e => e.service === "tech").map(e => e.nom)` se lit comme une phrase : « les employés tech, leurs noms ». C'est le style déclaratif : on dit QUOI, pas COMMENT (la boucle dit comment).
- Les deux retournent des tableaux NEUFS : l'original est intact — l'immutabilité du jour 8, gratuite.

**Quand garder une boucle** : arrêt anticipé (break), transformation + effet de bord mêlés, performance critique sur données énormes (chaque étage de chaîne reparcourt tout), ou logique d'index complexe. La maturité n'est pas « tout en map/filter » mais choisir l'outil qui rend le code le PLUS LISIBLE.

Ce style est universel : SQL (SELECT/WHERE), pandas (mois 5), les pipelines de données — partout, la même paire transformation/sélection.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : à partir d'employés, obtenir les noms de ceux du service "tech".

**Raisonnement** : filter (sélectionner) puis map (transformer) — ça se lit comme une phrase.

**Solution & explication** :
```js
const nomsTech = employes
  .filter((e) => e.service === "tech")  // garde les tech
  .map((e) => e.nom);                    // extrait le nom
```
« les employés tech, leurs noms » : le style déclaratif dit QUOI, pas COMMENT. Les deux méthodes retournent des tableaux NEUFS — l'original est intact.

**Variante — quand la boucle gagne** : pour trouver le PREMIER tech (arrêt anticipé), `filter().map()[0]` parcourt tout inutilement ; une boucle avec `break` (ou `.find`) est meilleure. La maturité n'est pas « tout en map/filter » mais choisir l'outil le plus LISIBLE.

## 🎤 Question d'entretien
**Mise en situation : « Voici une boucle `for` qui parcourt des articles, garde ceux dont le prix est positif, et construit une nouvelle liste avec ces prix doublés. Réécris-la avec `map`/`filter`. Puis donne-moi un cas où tu GARDERAIS plutôt une boucle. »**

*Ce que la question évalue :* la pensée en TRANSFORMATIONS (map) et SÉLECTIONS (filter), ET le discernement de ne pas les utiliser à tout prix.

**Réponse attendue :** `articles.filter(a => a.prix > 0).map(a => a.prix * 2)` — `filter` sélectionne, `map` transforme, on chaîne dans cet ordre. Je GARDE une boucle quand : je dois m'ARRÊTER en cours (`break`), gérer plusieurs accumulateurs en un seul passage, ou quand un `map`/`filter` imbriqué deviendrait moins lisible qu'une boucle claire.

**Débutant / correct / excellent :** débutant = réécrit mais met `map` avant `filter` (transforme des éléments qu'il jettera), ou ne voit aucun cas pour la boucle ; correct = filter puis map, chaîné, + un cas légitime de boucle ; excellent = note que `map`/`filter` renvoient de NOUVELLES listes (pas de mutation) et que l'ordre filter→map évite de transformer inutilement.

**Relance possible :** « pourquoi filter AVANT map ici ? » → pour ne pas doubler des prix qu'on va de toute façon éliminer (moins de travail, plus clair).

**À éviter :** utiliser `map` pour filtrer (en renvoyant `undefined`) ; croire que map/filter mutent la liste ; les employer partout même quand une boucle est plus lisible.

**Formulation orale naturelle :** « `filter(prix > 0)` puis `map(prix * 2)` — sélectionner d'abord, transformer ensuite ; et je garde une boucle quand je dois m'arrêter en cours ou gérer plusieurs accumulateurs. »
