## 📖 Cours approfondi
**Modèle mental : le golden set de DocSense est le mètre-étalon SPÉCIFIQUE à ce projet — il ne mesure quelque chose d'utile que s'il reflète le corpus réel et les cas d'usage de la SPEC, pas des questions génériques.** Tu as construit un golden set au mois 9 (jour 253) ; ici tu en construis un DÉDIÉ à DocSense : 40+ questions sur le corpus réel du projet, dérivées des cas d'usage de la SPEC (jour 302). Le golden set est ce qui rendra toutes les améliorations mesurables — sans lui, « DocSense s'améliore » reste une impression.

Ce qui rend le golden set de DocSense pertinent :
1. **Ancré dans le corpus réel** : les questions portent sur le VRAI corpus DocSense (celui ingéré au jour 309), avec sa vérité-terrain (document + passage exact). Un golden set sur un corpus jouet ne mesure pas la vraie qualité.
2. **Dérivé des cas d'usage de la SPEC** : les 5 cas d'usage définis au jour 302 (factuelle, reformulée, comparaison, hors corpus, ambiguë) structurent la distribution — le golden set mesure ce que DocSense PROMET de faire, pondéré selon l'usage visé (jour 253 : représentativité). La continuité SPEC → golden set → mesure est le fil de qualité du projet.
3. **Avec les cas difficiles ET les refus attendus** : des questions hors corpus (dont le refus est le comportement CORRECT), des reformulations (vocabulaire), des comparaisons multi-documents. Ce sont les cas difficiles qui DISCRIMINENT les versions du système.

Pourquoi c'est le socle du mois 12 de qualité : tout le travail d'amélioration de DocSense (jours 317-335) se mesurera contre CE golden set. Sa qualité (représentativité, vérité-terrain exploitable, cas difficiles) plafonne la qualité de toute l'évaluation. Un golden set bâclé donne des métriques qui rassurent sans garantir ; un golden set rigoureux permet d'améliorer en confiance. C'est aussi la preuve, en entretien, que tu évalues sérieusement : « mon golden set de 40 questions, dérivé des cas d'usage réels avec vérité-terrain, versionné » est un artefact que peu de candidats montrent.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : le golden set DocSense de 40+ questions, ancré corpus réel, dérivé de la SPEC.

**Exemple simple** : une question de golden set bien faite lie besoin et vérité-terrain — {question: "quel est le délai de X ?", type: "factuelle", reponse_attendue: "...", source_verite: {doc, passage}}. Chaque question est mesurable automatiquement.

**Raisonnement pas-à-pas** : partir des cas d'usage de la SPEC, écrire des questions RÉELLES sur le corpus, poser la vérité-terrain, équilibrer la distribution.

**Construction** :
```
40+ questions dérivées des 5 cas d'usage (SPEC, j.302), sur le corpus réel :
  - factuelles (40%) : réponse dans un chunk, vérité-terrain précise
  - reformulées (20%) : vocabulaire différent du document
  - synthèse/comparaison (15%) : réponse sur plusieurs documents
  - hors corpus (15%) : REFUS attendu (comportement correct)
  - ambiguës (10%) : demande de précision ou hypothèse explicite
Chaque question : {question, type, reponse_attendue, source_verite{doc, passage}, tags}
Versionné (golden-v1) et FIGÉ (ne sert jamais à développer, jour 253).
```

**Mini-quiz** : (a) Pourquoi le golden set doit-il être ancré dans le corpus RÉEL ? (b) D'où viennent les questions ? (c) Pourquoi inclure des questions hors corpus ?
→ (a) un golden set sur corpus jouet ne mesure pas la vraie qualité ; (b) des cas d'usage de la SPEC (ce que DocSense promet), pas du hasard ; (c) le refus est un comportement CORRECT à mesurer — un système qui répond à tout hallucine.

**Variante** : fais poser 5 questions par quelqu'un qui connaît le domaine mais pas DocSense — leurs formulations (plus courtes, plus floues) révèlent l'écart entre tes questions de concepteur et les vraies.

## ⚠️ Erreurs fréquentes
- Golden set sur corpus jouet ou générique : il ne mesure pas la vraie qualité perçue — ancrer dans le corpus réel.
- Questions tirées des documents (mémorisation) : elles testent la récupération d'un passage, pas l'usage réel — partir des cas d'usage.
- Pas de vérité-terrain avec passage exact : les métriques de retrieval redeviennent manuelles — poser doc + passage.
- Oublier les hors corpus : le refus est un comportement à mesurer ; un golden set sans hors-corpus ne teste pas la fiabilité.

## 🏢 Cas métier
Le golden set dédié au projet est ce qui permet aux équipes RAG d'améliorer en confiance : ancré dans leur corpus réel et leurs cas d'usage, il mesure la vraie qualité perçue par les utilisateurs. Les équipes qui évaluent sur un golden set générique (ou trop facile) optimisent un système qui brille en démo et déçoit en usage réel. Pour DocSense, un golden set de 40 questions dérivées de la SPEC, avec vérité-terrain et cas difficiles, est le socle de tout le travail de qualité du dernier mois — et « voici mon golden set versionné, dérivé de mes cas d'usage réels » est un signal de maturité d'évaluation rare en entretien.

## 🎤 Question d'entretien
**« Comment construis-tu le jeu d'évaluation d'un projet RAG concret ? »** → Ancré dans le corpus RÉEL et dérivé des cas d'usage de la SPEC : 40+ questions pondérées selon l'usage visé (factuelles, reformulées, synthèses, hors corpus, ambiguës), chacune avec sa vérité-terrain (document + passage exact, pour automatiser les métriques). J'inclus les cas difficiles (reformulations, comparaisons) et les hors corpus (dont le refus est le comportement correct). Il est versionné et figé (ne sert jamais à développer). Sa qualité plafonne toute l'évaluation — un golden set générique mesure un système que personne n'utilise ; un golden set dérivé des cas d'usage réels mesure la vraie valeur.
