## 🎯 Objectif du jour
Diagnostiquer et corriger l'overfitting.

## 📖 Cours approfondi
**Modèle mental : l'overfitting (surapprentissage), c'est apprendre le BRUIT des données d'entraînement au lieu du SIGNAL généralisable — il se reconnaît à l'ÉCART train/validation (excellent en train, médiocre en validation) et se combat en CONTRAIGNANT le modèle. C'est le compromis biais-variance en action : trop de liberté = variance (surapprentissage) ; trop peu = biais (sous-apprentissage).** Diagnostiquer et corriger l'overfitting est LA compétence centrale du ML : un modèle qui mémorise est inutile, un modèle trop simple aussi.

Les concepts, depuis les fondations :
1. **Signal vs bruit** : les données contiennent une régularité réelle (le signal, qui généralise) et des fluctuations aléatoires propres à cet échantillon (le bruit, qui ne généralise pas). Un modèle trop flexible « apprend » le bruit — il colle parfaitement au train mais échoue sur du neuf.
2. **Le diagnostic par l'écart train/validation** : 
   - Overfitting : score de train ÉLEVÉ, score de validation BAS (gros écart). Le modèle mémorise.
   - Underfitting : score de train ET de validation bas (petit écart, mais faible). Le modèle est trop simple pour capturer le signal.
   - Bon ajustement : train et validation proches et élevés.
3. **Le compromis biais-variance** : le biais est l'erreur d'un modèle trop simple (il rate le signal) ; la variance est la sensibilité aux fluctuations des données (il apprend le bruit). Augmenter la complexité baisse le biais mais augmente la variance, et inversement. L'optimum est entre les deux.
4. **Les parades (contraindre le modèle)** :
   - **Simplifier** : moins de complexité (profondeur d'arbre limitée, moins de features).
   - **Régulariser** : ajouter une pénalité sur la taille des coefficients — L2 (Ridge) les rétrécit, L1 (Lasso) en met certains à zéro (sélection de features). La régularisation décourage le modèle de trop coller aux données.
   - **Plus de données** : plus d'exemples rendent le bruit plus difficile à mémoriser (le signal ressort).

La démarche : on DÉMONTRE l'overfitting (écart train/validation), on identifie sa cause (modèle trop flexible pour la quantité de données), et on le corrige de plusieurs façons en MESURANT l'effet sur la validation (pas le train !). Corriger « au feeling » sans mesurer est aveugle.

La règle du jour : **l'overfitting = apprendre le bruit, diagnostiqué par l'écart train/validation ; on le corrige en contraignant le modèle (simplifier, régulariser, plus de données) et on MESURE l'effet sur la validation. C'est le compromis biais-variance : ni trop flexible (variance) ni trop simple (biais)**.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : démontrer l'overfitting (train vs validation), le corriger de 3 façons, mesurer.

**Exemple simple** : le diagnostic en deux chiffres — `train = 0,99, validation = 0,71` : gros écart = overfitting (le modèle mémorise). `train = 0,68, validation = 0,66` : proche mais bas = underfitting. L'écart raconte l'histoire.

**Raisonnement pas-à-pas** : mesurer train et validation → constater l'écart (overfitting) → appliquer 3 corrections (simplifier, régulariser, plus de données) → mesurer l'effet sur la VALIDATION.

**Implémentation** :
```python
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import cross_val_score

# Overfitting démontré : arbre profond -> train ≈ 1, validation basse
trop = DecisionTreeClassifier(random_state=42).fit(X_tr, y_tr)
print("arbre libre - train:", trop.score(X_tr, y_tr), "| val:", cross_val_score(trop, X, y, cv=5).mean())

# Correction 1 : SIMPLIFIER (limiter la profondeur)
simple = DecisionTreeClassifier(max_depth=4, random_state=42)
print("arbre limité - val:", cross_val_score(simple, X, y, cv=5).mean())

# Correction 2 : RÉGULARISER (pénalité L2 sur une régression logistique ; C petit = plus régularisé)
reg = LogisticRegression(C=0.1, max_iter=1000)
print("logreg régularisée - val:", cross_val_score(reg, X, y, cv=5).mean())

# Correction 3 : plus de données (si possible) -> le bruit devient plus dur à mémoriser.
```

**Mini-quiz** : (a) Comment reconnaît-on l'overfitting ? (b) Qu'est-ce que le compromis biais-variance ? (c) Sur quel score mesure-t-on l'effet d'une correction ?
→ (a) un gros écart train/validation (train élevé, validation basse) : le modèle a mémorisé le bruit ; (b) trop simple = biais (rate le signal), trop flexible = variance (apprend le bruit) ; l'optimum est entre les deux ; (c) sur la VALIDATION (jamais le train) : c'est la généralisation qu'on veut améliorer, pas la mémorisation.

**Variante** : sur la régression logistique, fais varier `C` (0,001 à 100) et trace la validation. Tu vois une cloche : trop régularisé = underfitting (biais), pas assez = overfitting (variance) ; l'optimum est au sommet.

## 🏢 Cas métier
Le diagnostic et la correction de l'overfitting est la compétence qui sépare un modèle déployable d'un modèle qui échoue en production : un modèle qui « fait 99 % » (en train) et s'effondre en réel a mémorisé le bruit. En entreprise, tout modèle sérieux est évalué sur son écart train/validation, et la régularisation est un levier quotidien (Ridge/Lasso pour les modèles linéaires, profondeur/min_samples pour les arbres, early stopping pour les réseaux). La compréhension du compromis biais-variance guide toutes les décisions de complexité de modèle. Un data scientist qui diagnostique l'overfitting par les courbes et le corrige en mesurant sur la validation est fiable ; celui qui ajuste au feeling sans mesurer produit des modèles imprévisibles. C'est un incontournable des entretiens ML.

## 🎤 Question d'entretien
**« Qu'est-ce que l'overfitting, comment le diagnostiques-tu et le corriges-tu ? »** → C'est apprendre le BRUIT des données d'entraînement (les fluctuations propres à cet échantillon) au lieu du SIGNAL généralisable. Je le diagnostique par l'ÉCART train/validation : train élevé et validation basse = overfitting (mémorisation) ; les deux bas = underfitting (trop simple) ; proches et élevés = bon ajustement. C'est le compromis biais-variance : trop de complexité = variance (apprend le bruit), trop peu = biais (rate le signal). Je le corrige en CONTRAIGNANT le modèle : simplifier (moins de profondeur/features), régulariser (pénalité L2/Ridge qui rétrécit les coefficients, L1/Lasso qui en annule), ou ajouter des données. Et je MESURE l'effet sur la VALIDATION, jamais sur le train — c'est la généralisation qu'on veut améliorer. Corriger sans mesurer est aveugle.
