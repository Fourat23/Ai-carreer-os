## 🎯 Objectif du jour

## 📖 Cours approfondi
**Modèle mental : un DataFrame pandas est un TABLEAU 2D ÉTIQUETÉ — des lignes indexées et des colonnes NOMMÉES et TYPÉES — et pandas manipule des COLONNES entières d'un coup (vectorisation), pas des cellules une par une avec des boucles. Charger des données, c'est d'abord les INSPECTER avant d'y toucher.** Si tu penses « boucle sur chaque ligne » (le réflexe JS/Python de base), tu écris du pandas lent et non idiomatique. Le bon réflexe : « quelle opération sur la colonne entière ? ». Un DataFrame ressemble à une table SQL chargée en mémoire, avec la puissance d'expression de Python.

Les notions du jour :
1. **Series et DataFrame** : une `Series` est une colonne (un tableau 1D étiqueté avec un dtype) ; un `DataFrame` est un ensemble de Series partageant le même index. Chaque colonne a un TYPE (`int64`, `float64`, `object` pour le texte, `datetime64`, `bool`) — et le type conditionne ce qu'on peut faire.
2. **Charger** : `pd.read_csv("data.csv")`, `pd.read_json(...)` — pandas infère les types, mais l'inférence peut se tromper (un code postal lu comme un nombre, une date comme du texte). D'où l'inspection.
3. **Inspecter AVANT d'agir** — le réflexe professionnel :
   - `df.shape` : combien de lignes/colonnes (l'ordre de grandeur).
   - `df.info()` : les colonnes, leurs TYPES, et le nombre de valeurs non-nulles (donc les manquants).
   - `df.describe()` : les statistiques (min/max/moyenne/quartiles) des colonnes numériques — révèle les valeurs aberrantes.
   - `df.head()` / `df.sample(5)` : à quoi ressemblent vraiment les données.
   - `df["col"].value_counts()` : la distribution d'une colonne catégorielle — révèle les catégories inattendues, les fautes de frappe, les déséquilibres.

Pourquoi inspecter d'abord : les données réelles sont TOUJOURS plus sales et surprenantes qu'annoncé. Sauter l'inspection, c'est construire une analyse sur des types faux, des manquants ignorés et des valeurs aberrantes invisibles — l'analyse sera fausse sans que rien ne plante. Inspecter, c'est se forger une compréhension AVANT de conclure.

La règle du jour : **charge, puis INSPECTE systématiquement (shape, info, describe, value_counts) et formule des observations, AVANT toute transformation ; pense colonnes vectorisées, pas boucles**. L'inspection n'est pas une formalité, c'est là que tu découvres ce que tes données sont réellement.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : charger un vrai dataset, l'inspecter (info/describe/value_counts) et formuler 5 observations.

**Exemple simple** : la première commande après tout chargement — `df.info()`. Elle te dit en une ligne par colonne : le nom, le type, et combien de valeurs manquent. Avant `info()`, tu ne sais pas ce que tu as ; après, tu sais où regarder.

**Raisonnement pas-à-pas** : charger → mesurer la taille (shape) → examiner types et manquants (info) → statistiques numériques (describe) → distributions catégorielles (value_counts) → écrire ce qu'on OBSERVE.

**Implémentation** :
```python
import pandas as pd
df = pd.read_csv("ventes.csv")

print(df.shape)                 # (10432, 8) — ordre de grandeur
df.info()                       # types + non-nuls : 'date' est object (→ à convertir !), 'prix' a 210 manquants
print(df.describe())            # prix : max=99999 (aberrant ?), min=-5 (impossible → donnée sale)
print(df["categorie"].value_counts())   # 'Livre' 4000, 'livre' 12 (faute de casse !), 'Jeu' 3000

# 5 observations (le vrai livrable de l'inspection) :
# 1. 'date' est typée object, pas datetime → conversion nécessaire avant analyse temporelle.
# 2. 'prix' a 210 valeurs manquantes (2%) et un min négatif (-5) → données à nettoyer (jour 128).
# 3. 'categorie' a des doublons de casse ('Livre'/'livre') → normalisation nécessaire.
# 4. describe montre un prix max de 99999 → valeur aberrante probable à investiguer.
# 5. 10432 lignes, 8 colonnes → volume modeste, tient en mémoire sans souci.
```

**Mini-quiz** : (a) Pourquoi inspecter AVANT de transformer ? (b) Que révèle `value_counts()` qu'un `describe()` ne montre pas ? (c) Pourquoi pandas est-il rapide sans boucles ?
→ (a) les données réelles sont plus sales qu'annoncé ; sauter l'inspection produit une analyse fausse sans plantage ; (b) la distribution d'une colonne catégorielle — catégories inattendues, fautes de casse, déséquilibres (describe ne couvre que le numérique) ; (c) il vectorise : les opérations s'appliquent à la colonne entière en code optimisé, pas cellule par cellule.

**Variante** : après l'inspection, écris `df.isna().sum()` pour compter les manquants par colonne — c'est la carte précise de ce que le jour 128 devra nettoyer.

## ⚠️ Erreurs fréquentes
- Transformer/analyser sans inspecter : une analyse fausse sur des types mal inférés et des manquants, SANS plantage.
- Se fier à l'inférence de type de pandas : une date peut être lue comme texte, un code postal comme un nombre.
- Ignorer les colonnes catégorielles (pas de value_counts) : on rate les fautes de casse et catégories inattendues.
- Boucler ligne par ligne au lieu de vectoriser : lent et non idiomatique.

## 🏢 Cas métier
L'inspection systématique avant toute analyse est ce qui sépare un analyste fiable d'un producteur de conclusions fausses : les données réelles arrivent avec des types mal inférés (dates en texte, codes en nombres), des manquants, des doublons de casse et des valeurs aberrantes — et une analyse construite dessus sans inspection est fausse SANS que rien ne plante, ce qui est le pire des cas. En entreprise, un rapport basé sur des données non inspectées peut orienter une décision coûteuse dans la mauvaise direction. Le réflexe « shape → info → describe → value_counts → observations » est le premier geste attendu de tout data analyst, et la capacité à formuler des observations pertinentes à partir de cette inspection est directement évaluée en test technique data.
