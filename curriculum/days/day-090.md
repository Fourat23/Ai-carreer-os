## 🎯 Objectif du jour
Clôturer le trimestre 1 (fondations + full-stack + SQL + sécurité), figer les acquis, préparer la data et l'IA.

## 📖 Cours approfondi
**Concepts abordés :** Bilan trimestriel · Mise à jour des scores · Portfolio à date (2 projets) · Projection mois 4-12.

Quatre-vingt-dix jours : tu es passé de « quelques notions de JavaScript » à développeur full-stack junior — terminal, Git, algorithmique, structures de données, TypeScript, API REST sécurisée et testée, SQL, et un front React branché sur TON backend. C'est déjà un profil employable sur des rôles full-stack juniors.

La suite change de registre : Python et la data (mois 4-5), le ML honnête (mois 6), puis l'IA appliquée (mois 7-12) qui te différenciera. Tout ce qui vient s'appuie sur ces fondations — le RAG du mois 8 est « de l'ingestion de données + une API + de l'évaluation », trois choses que tu sais déjà faire à 70%.

Le rituel du bilan : relire le jour 1 (mesurer le chemin), réévaluer sans complaisance, nommer les peurs restantes (elles désignent les priorités), et écrire à ton toi du jour 180.

**Modèle mental : en 90 jours, tu es passé de « quelques notions de JavaScript » à développeur full-stack junior — terminal, Git, algorithmique, structures de données, TypeScript, API REST sécurisée et testée, SQL, et un front React branché sur TON backend. C'est déjà un profil EMPLOYABLE sur des rôles full-stack juniors. La suite change de registre : Python et la data (mois 4-5), le ML honnête (mois 6), puis l'IA appliquée (mois 7-12) qui te DIFFÉRENCIERA. Tout ce qui vient s'APPUIE sur ces fondations — le RAG du mois 8, c'est « de l'ingestion de données + une API + de l'évaluation », trois choses que tu sais déjà faire.** Clôturer le trimestre 1, c'est figer des acquis employables et lancer la phase qui rend « bankable IA ».

Pourquoi un bilan de clôture de trimestre. Un trimestre est une unité assez longue pour mesurer une VRAIE transformation. Le bilan de clôture (distinct du bilan mensuel du jour 83) prend le recul maximal : comparer le soi du jour 1 au soi d'aujourd'hui révèle un changement de NATURE (pas juste de degré) — de « personne qui bricole du JS » à « développeur qui construit du full-stack complet ». Nommer cette transformation la rend consciente et mobilisable en entretien.

Ce que tu es devenu, depuis les fondations. Trois mois couvrent : les FONDATIONS (terminal, Git, algorithmique, structures de données), le WEB FULL-STACK (TypeScript, POO, API REST, Express, React), la DONNÉE (SQL, modélisation, transactions), la QUALITÉ (tests, sécurité, doc, observabilité, refactoring), et la PENSÉE D'INGÉNIEUR (architecture, trade-offs). Avec deux projets (TaskFlow, LivreAPI) propres et démontrables. C'est objectivement un profil full-stack junior employable — un fait à intégrer, pas une flatterie.

Le portfolio à date, depuis les fondations. Deux projets sur GitHub, PROPRES (README utilisable, historique lisible, tests, sécurité) : un recruteur peut les regarder MAINTENANT. La règle : rendre ces projets vraiment propres avant de passer à la suite, car ils sont ta preuve actuelle. Un projet à 90 % non fini vaut moins qu'un projet fini — la finition (jours 47, 66, 85) est ce qui les rend crédibles.

La projection vers la data/IA, depuis les fondations. La suite s'APPUIE sur les fondations, elle ne repart pas de zéro : la data (mois 4-5) manipule des données comme tu as manipulé des tables SQL ; le ML (mois 6) est un processus rigoureux comme tes tests ; le RAG (mois 8) combine ingestion de données + API + évaluation — trois compétences déjà acquises. Voir cette CONTINUITÉ transforme l'appréhension (« tout un nouveau domaine ») en confiance (« je construis sur ce que je sais »). L'IA appliquée est ce qui te différenciera d'un full-stack junior classique — le « bankable IA ».

La lettre au soi du jour 1, un outil de conscience. Écrire au soi du jour 1 (et lire la lettre du jour 180 s'il y en a une) matérialise la transformation et ancre la motivation pour la suite. C'est un exercice d'honnêteté et de recul, pas une formalité.

Limites et compromis. « Employable full-stack junior » ne veut pas dire « expert » : il reste beaucoup à apprendre, et l'honnêteté (jour 83) reste de mise. Le bilan ne doit pas devenir de l'autosatisfaction qui freine — il célèbre pour mieux relancer. Et rendre les projets « vraiment propres » prend du temps qu'on est tenté de zapper pour foncer vers la data : c'est une erreur, car les projets sont la preuve actuelle.

La règle du jour : **acte ta transformation en 90 jours (profil full-stack junior employable, 2 projets démontrables), rends tes projets VRAIMENT propres sur GitHub (un recruteur peut regarder aujourd'hui), et projette la suite comme un APPUI : la data, le ML et l'IA appliquée s'appuient sur tes fondations (le RAG = ingestion + API + évaluation). C'est la phase qui te rendra bankable IA.**

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : acter la transformation du trimestre, vérifier que les 2 projets sont vraiment propres, et projeter la continuité vers la data/IA.

**Exemple simple** : la continuité, pas la rupture. « Le RAG, c'est un domaine IA inconnu » (appréhension) devient « le RAG = ingérer des données (comme mes ETL/SQL) + une API (comme LivreAPI) + de l'évaluation (comme mes tests) » (confiance). La data/IA s'appuie sur ce que je sais déjà.

**Raisonnement pas-à-pas** : (1) je compare le soi du jour 1 à aujourd'hui (transformation de nature) ; (2) je vérifie que TaskFlow et LivreAPI sont propres (un recruteur peut regarder) ; (3) je relie les mois à venir à mes fondations ; (4) je fixe mes priorités data/ML.

**Bilan de clôture** :
```text
TRANSFORMATION (jour 1 -> jour 90) :
  jour 1  : quelques notions de JavaScript
  jour 90 : développeur full-stack junior — API REST sécurisée/testée, SQL, React branché
  -> changement de NATURE, pas de degré. Profil employable full-stack junior.

PORTFOLIO À DATE (un recruteur peut regarder AUJOURD'HUI) :
  [ ] TaskFlow  : README utilisable en 5 min, tests, ADR, historique propre ?
  [ ] LivreAPI  : sécurité, tests d'intégration, observabilité, démo 2 min ?
  -> rendre VRAIMENT propres avant de passer à la data (ils sont ma preuve actuelle).

PROJECTION mois 4-12 (APPUI sur les fondations) :
  - data (m4-5)  : manipuler des données, comme mes tables SQL
  - ML (m6)      : un processus rigoureux, comme mes tests
  - RAG (m8)     : ingestion de données + API + évaluation -> je sais déjà les 3
  -> l'IA appliquée est ce qui me DIFFÉRENCIERA (bankable IA).

PRIORITÉS : 3 axes datés pour aborder la data avec des fondations consolidées.
```
Le bilan acte une transformation de nature (employable full-stack junior), vérifie que les 2 projets sont une preuve propre et inspectable, et projette la suite comme une continuité (le RAG s'appuie sur des briques déjà maîtrisées) — ce qui remplace l'appréhension du « nouveau domaine » par la confiance de construire sur ses acquis.

## ⚠️ Erreurs fréquentes
- Négliger de rendre les projets vraiment propres : un recruteur peut regarder MAINTENANT, un projet à 90 % vaut moins qu'un projet fini.
- Aborder la data sans consolider les fondations : accumulation de lacunes.
- Autosatisfaction qui freine : le bilan célèbre pour relancer, pas pour s'arrêter.
- Voir la data/IA comme une rupture effrayante au lieu d'une continuité (le RAG s'appuie sur des briques connues).

## 🏢 Cas métier
Faire un bilan de clôture de trimestre, entretenir un portfolio propre et projeter la suite avec confiance sont des pratiques qui structurent une progression de carrière et une recherche d'emploi efficaces. Après trois mois, être capable de reconnaître objectivement qu'on est devenu employable (profil full-stack junior) change la posture : on peut commencer à candidater, à se présenter, à se projeter — au lieu d'attendre une hypothétique « fin de formation ». Le portfolio propre est décisif : les recruteurs regardent GitHub, et deux projets finis, sécurisés, testés et bien documentés valent plus qu'une longue liste de technologies survolées. La capacité à relier les compétences acquises aux compétences à venir (le RAG s'appuie sur l'ingestion de données, les API et l'évaluation) est ce qui permet d'aborder de nouveaux domaines avec confiance plutôt qu'appréhension — une méta-compétence d'apprenant. Et se positionner sur l'IA appliquée en s'appuyant sur des fondations full-stack solides est exactement la stratégie « bankable » de ce parcours : un différenciateur réel sur le marché, où les développeurs qui maîtrisent à la fois le logiciel et l'IA sont rares et recherchés.
