## 🎯 Objectif du jour
Réordonner le top-k.

## 📖 Cours approfondi
**Modèle mental : le retrieval jette un filet large et rapide ; le reranker inspecte chaque prise une à une.** Toute ta chaîne actuelle (vectoriel, lexical, RRF) partage une limite structurelle : elle compare la question à des représentations PRÉ-CALCULÉES des chunks (vecteurs figés, index de termes). Un **cross-encoder** fait l'inverse : il lit la question ET le chunk ENSEMBLE, en un seul passage de transformer, et note leur pertinence mutuelle — l'attention croise chaque mot de la question avec chaque mot du chunk (le mécanisme du jour 192, appliqué à la paire). Résultat : une précision par paire bien supérieure… à un coût par paire prohibitif. Impossible de scorer 20 000 chunks ainsi à chaque question — mais 20, oui.

D'où l'architecture en deux étages, standard de l'industrie :
1. **Rappel** (rapide, large) : l'hybride RRF ramène le top-20 — sa mission n'est plus la précision mais la COUVERTURE : que le bon chunk soit QUELQUE PART dans le filet.
2. **Précision** (lent, étroit) : le reranker note les 20 paires (question, chunk) et réordonne ; on tronque au top-3 final.

Deux implémentations pratiques : un cross-encoder dédié (petit modèle local type MiniLM multilingue, ou API de reranking — rapide, calibré pour ça) ou un **LLM-as-reranker** (prompt : « note la pertinence de ce passage pour cette question, 0-10 » — plus coûteux et plus lent, mais zéro dépendance nouvelle et honorable en qualité ; parfait pour VALIDER l'intérêt avant d'installer l'outil dédié).

La mesure change de nature : le reranking n'améliore pas la présence dans le top-20 (le rappel est fixé en amont) — il améliore les RANGS. Ta métrique du jour : « bon chunk dans le top-3 » avant/après reranking, à top-20 d'entrée CONSTANT. Et ta question résiduelle d'hier (rang 12 vectoriel, absente lexical) est le cas d'école : présente dans le filet, mal classée — exactement ce qu'un reranker répare.

**Énoncé** : reranker le top-20 hybride vers le top-3, gain mesuré.

**Raisonnement** : commencer par le LLM-as-reranker (zéro installation, validation du concept), mesurer, puis décider si un cross-encoder dédié se justifie.

**Implémentation (LLM-as-reranker)** :
```python
def reranker_llm(question: str, chunks: list[dict]) -> list[dict]:
    scores = []
    for c in chunks:                      # 20 appels courts — batchables
        note = llm_call(                  # ton composant du jour 214
            system="Note de 0 à 10 la pertinence du PASSAGE pour répondre "
                   "à la QUESTION. Réponds UNIQUEMENT le nombre. "
                   "0 = hors sujet, 10 = contient la réponse complète.",
            prompt=f"QUESTION : {question}\n\nPASSAGE : {c['texte'][:1200]}",
            temp=0, max_tokens=4, schema=NoteEntiere,   # validé 0-10 !
        )
        scores.append((note.valeur, c))
    return [c for _, c in sorted(scores, key=lambda x: -x[0])]

def top_k_final(question: str, k=3):
    filet = top_k_hybride(question, k_final=20)     # RAPPEL : large
    return reranker_llm(question, filet)[:k]         # PRÉCISION : étroit
```

**La mesure (rangs, pas présence)** :
```
                      avant rerank   après rerank
bon chunk top-3         22/26          24/26   ← dont LA résiduelle d'hier
rang moyen du bon        2.8            1.6
latence p50             +0 ms          +900 ms  ← le PRIX, à afficher
coût/question           +0 €           +0,004 € (20 mini-appels)
```

**Explication** : le schéma \`NoteEntiere\` (validation jour 205) évite le reranker qui répond « Ce passage me semble... » — la sortie contrainte redevient critique dès qu'on boucle 20 fois. **Variante** : compare avec un cross-encoder local (sentence-transformers, modèle multilingue) sur les mêmes 20×26 paires — qualité proche, latence ÷10, coût 0 : la grille de décision du jour 243 s'applique telle quelle.

## 🏢 Cas métier
L'architecture rappel-large-puis-reranking est celle de TOUS les systèmes de recherche sérieux (moteurs web, e-commerce, RAG d'entreprise) — c'est le pattern « entonnoir de précision » : chaque étage est plus précis et plus cher que le précédent, sur moins de candidats. En entretien system design, dessiner cet entonnoir (20 000 → 20 → 3) avec les coûts par étage est une réponse-signature qui marche du poste RAG junior au poste search senior.

## 🎤 Question d'entretien
**« Qu'apporte un reranker que ton hybride n'a pas ? »** → L'hybride compare la question à des représentations pré-calculées ; le cross-encoder lit la paire (question, passage) ensemble — attention croisée mot à mot, précision par paire supérieure, coût par paire prohibitif. D'où l'entonnoir : rappel large et rapide (top-20 hybride), précision lente et étroite (rerank → top-3). La mesure porte sur les rangs à filet constant : 22→24/26 chez moi, pour +900 ms et +0,004 €/question — un arbitrage explicite, pas un upgrade gratuit.
