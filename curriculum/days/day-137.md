## 🎯 Objectif du jour
Requêtes complexes (sous-requêtes, window).

## 📖 Cours approfondi
**Modèle mental : les sous-requêtes et surtout les fonctions FENÊTRE (window functions) répondent aux questions que `GROUP BY` ne peut PAS — une window function calcule sur un groupe SANS écraser les lignes (rang, cumul, moyenne glissante, comparaison à la moyenne du groupe), là où `GROUP BY` RÉDUIT à une seule ligne par groupe.** Tu sais agréger (`GROUP BY`, jour 130 côté pandas). Mais beaucoup de questions analytiques ont besoin de GARDER chaque ligne tout en la reliant à son groupe : « le rang de chaque vente dans son mois », « le cumul des ventes jour après jour », « l'écart de chaque salaire à la moyenne de son département ». C'est le rôle des window functions.

Les outils analytiques :
1. **Les sous-requêtes** : une requête dans une requête. Dans le `WHERE` (`WHERE prix > (SELECT AVG(prix) FROM produits)`), dans le `FROM` (une table dérivée), ou corrélée (qui référence la requête externe). Elles composent des questions en plusieurs étapes.
2. **Les CTE (`WITH ... AS`)** : nomment une sous-requête pour rendre une requête complexe LISIBLE et réutilisable, de haut en bas. `WITH ventes_mois AS (...) SELECT ... FROM ventes_mois` — l'équivalent SQL d'une variable intermédiaire.
3. **Les fonctions fenêtre** : `fonction() OVER (PARTITION BY groupe ORDER BY colonne)`. La `PARTITION BY` définit le groupe (comme un GROUP BY), mais le résultat est calculé POUR CHAQUE LIGNE :
   - `ROW_NUMBER()` / `RANK()` : le rang dans le groupe (top N par catégorie).
   - `SUM(...) OVER (ORDER BY date)` : le cumul (running total).
   - `AVG(...) OVER (PARTITION BY dept)` : la moyenne du groupe, répétée sur chaque ligne pour comparaison.
   - `LAG`/`LEAD` : la valeur de la ligne précédente/suivante (évolution d'un mois à l'autre).

La distinction décisive : `GROUP BY` répond « une valeur PAR groupe » (le CA par mois) ; une window function répond « pour chaque ligne, sa relation à son groupe » (le rang de cette vente dans son mois, sans perdre la vente). Confondre les deux mène à des contorsions (auto-jointures compliquées) là où une window function fait le travail en une ligne.

La règle du jour : **utilise les sous-requêtes/CTE pour composer des questions en étapes lisibles, et les fonctions fenêtre pour calculer sur un groupe SANS écraser les lignes (rang, cumul, comparaison) — là où `GROUP BY` réduirait**. Ces outils transforment SQL d'un langage d'extraction en un langage d'ANALYSE.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : écrire 5 requêtes analytiques (CA/mois, top clients, produits jamais vendus, cumuls).

**Exemple simple** : la window function qui garde les lignes — `ROW_NUMBER() OVER (PARTITION BY mois ORDER BY montant DESC)`. Elle numérote les ventes DANS chaque mois par montant décroissant, sans réduire : filtrer sur `= 1` donne la meilleure vente de chaque mois, lignes intactes.

**Raisonnement pas-à-pas** : distinguer « une valeur par groupe » (GROUP BY) de « chaque ligne reliée à son groupe » (window) → composer les étapes avec des CTE → appliquer la bonne window function.

**Implémentation** :
```sql
-- 1. CA par mois (GROUP BY : une ligne par mois)
SELECT strftime('%Y-%m', date) AS mois, SUM(montant) AS ca
FROM ventes GROUP BY mois;

-- 2. Top 3 clients par CA (window : rang SANS perdre les lignes)
WITH par_client AS (
  SELECT client_id, SUM(montant) AS ca FROM ventes GROUP BY client_id)
SELECT client_id, ca,
       RANK() OVER (ORDER BY ca DESC) AS rang
FROM par_client
WHERE rang <= 3;   -- (via sous-requête si le SGBD n'accepte pas rang au WHERE)

-- 3. Produits JAMAIS vendus (sous-requête NOT IN / LEFT JOIN ... IS NULL)
SELECT nom FROM produits
WHERE id NOT IN (SELECT DISTINCT produit_id FROM ventes);

-- 4. Cumul des ventes jour après jour (running total)
SELECT date, SUM(montant) OVER (ORDER BY date) AS cumul FROM ventes;

-- 5. Écart de chaque vente à la moyenne de son mois (comparaison intra-groupe)
SELECT date, montant,
       montant - AVG(montant) OVER (PARTITION BY strftime('%Y-%m', date)) AS ecart_moyenne
FROM ventes;
```

**Mini-quiz** : (a) Quelle différence entre `GROUP BY` et une window function ? (b) À quoi sert une CTE ? (c) Comment calculer un cumul (running total) ?
→ (a) GROUP BY réduit à une ligne par groupe ; une window function calcule sur le groupe SANS écraser les lignes (rang, cumul, comparaison) ; (b) nommer une sous-requête pour rendre une requête complexe lisible et composable en étapes ; (c) `SUM(...) OVER (ORDER BY date)` — une somme fenêtrée ordonnée.

**Variante** : ajoute `LAG(ca) OVER (ORDER BY mois)` à ta requête de CA mensuel pour calculer la croissance d'un mois sur l'autre — tu obtiens une analyse d'évolution qu'un GROUP BY seul ne peut pas produire.

## 🏢 Cas métier
Les requêtes analytiques (window functions, CTE, sous-requêtes) sont le cœur du reporting et de l'analyse en entreprise : classements (top clients, produits), cumuls (CA cumulé, cohortes), comparaisons intra-groupe (performance vs moyenne d'équipe), évolutions (croissance mois sur mois). Les analysts qui maîtrisent les window functions répondent à ces questions en une requête lisible ; ceux qui ne les connaissent pas s'enlisent dans des auto-jointures compliquées et fragiles, ou exportent tout vers un tableur. La maîtrise des window functions est un différenciateur net en entretien data — c'est souvent LA question SQL avancée posée, précisément parce qu'elle sépare ceux qui « savent extraire » de ceux qui « savent analyser » directement en base.

## 🎤 Question d'entretien
**« Quelle est la différence entre `GROUP BY` et une fonction fenêtre ? »** → `GROUP BY` RÉDUIT : une ligne par groupe (le CA par mois). Une fonction fenêtre (`OVER (PARTITION BY ... ORDER BY ...)`) calcule sur le groupe SANS écraser les lignes : chaque ligne est conservée et reliée à son groupe. C'est ce qui permet le rang (`ROW_NUMBER`/`RANK` — top N par catégorie), le cumul (`SUM() OVER (ORDER BY date)` — running total), la comparaison intra-groupe (`AVG() OVER (PARTITION BY dept)` — écart à la moyenne du département), ou l'évolution (`LAG`/`LEAD`). Confondre les deux mène à des auto-jointures compliquées là où une window function fait le travail en une ligne. J'utilise aussi les CTE (`WITH`) pour découper une requête complexe en étapes lisibles. Ces outils font de SQL un langage d'analyse, pas seulement d'extraction.
