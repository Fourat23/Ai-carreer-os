### Synthèse de la semaine
Cette première semaine a posé les OUTILS avant le code. Compétences réellement évaluées :
- **Terminal (jours 1-2)** : se déplacer (`cd`, `ls`, `pwd`), créer/organiser (`mkdir`, `touch`), lancer un script avec `node` — le terminal comme cockpit du développeur, pas comme obstacle.
- **Git (jour 3)** : `add`/`commit`/`log`, la distinction working directory / zone de staging / historique, et l'idée qu'un commit RACONTE une intention (pas « sauvegarde »).
- **JavaScript — variables et types (jour 4)** : `let`/`const`, les types primitifs (number, string, boolean, null/undefined), les opérateurs, et le piège de coercition (`==` vs `===`).
- **Conditions (jour 5)** : `if`/`else if`/`else`, les comparaisons, et le piège des valeurs *falsy* (`0`, `''`, `null`, `undefined`, `NaN`).
- **Boucles + publication (jour 6)** : `for`/`while`, l'itération, et le premier code publié sur GitHub (push).

Le fil rouge : **maîtriser l'environnement (terminal + Git) rend tout le reste possible ; et un programme, c'est stocker des valeurs typées, décider (conditions), répéter (boucles)** — les trois briques de tout code.

### Grille de notation
**Test théorique (réponds sans notes, à l'oral si possible) :**
1. Quelle est la différence entre `cd ..` et `cd ~`, et à quoi sert `pwd` ?
2. Un fichier modifié n'apparaît pas dans `git log` : quelles sont les 2 étapes pour l'y faire figurer, et pourquoi cette séparation staging/commit existe-t-elle ?
3. Que renvoie `0 == '0'` et `0 === '0'` ? Explique la coercition.
4. Cite 4 valeurs *falsy* et donne un cas où confondre « absent » et « falsy » cause un bug.
5. Écris (au brouillon) une boucle `for` qui somme les nombres de 1 à 10 ; où se cache l'erreur *off-by-one* classique ?

### Questions d'entretien de la semaine
1. **« Que se passe-t-il exactement quand tu tapes `git commit` ? »** Attendu : Git fige un instantané du contenu STAGÉ (pas du working directory) dans un nouveau commit reliant au précédent ; d'où l'intérêt du staging pour composer des commits cohérents.
2. **« Quelle est la différence entre `==` et `===` en JavaScript ? »** Attendu : `==` compare après coercition de type (`0 == '0'` est vrai), `===` compare valeur ET type sans coercition ; on utilise `===` par défaut pour éviter les surprises.
3. **« Qu'est-ce qu'une valeur *falsy*, et pourquoi est-ce un piège ? »** Attendu : une valeur qui vaut `false` dans un contexte booléen (`0`, `''`, `null`, `undefined`, `NaN`) ; tester `if (x)` confond « absent » et « valeur falsy légitime » (ex. la quantité 0).
4. **« Comment lances-tu un fichier JavaScript et comment sais-tu qu'il a une erreur ? »** Attendu : `node fichier.js` ; lire le message d'erreur et la stack trace (fichier + ligne) plutôt que deviner.
