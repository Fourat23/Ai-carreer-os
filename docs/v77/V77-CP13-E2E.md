# V77 · CP13 — SIX CHAÎNES, TRAVERSÉES SUR LE PRODUIT QUI TOURNE

> Un produit n'est pas une somme de surfaces. Le défaut décisif du CP0 vivait
> **entre** deux d'entre elles, et aucune mesure locale ne l'aurait trouvé.

---

## 1. Ce qui est traversé, et comment

Six chaînes complètes, en **HTTP réel**, contre le produit reconstruit
(`npx next build` + `next start`), avec une progression hors du dépôt.

L'état est lu **par l'export du produit** (`/api/progress/export`), pas par le
fichier sur disque : une sonde qui lirait le fichier qu'elle vient d'écrire
mesurerait son propre appareil. V76 · CP14 a payé trois faux survivants pour
cette leçon.

Et la sonde **ne contourne aucune garantie** : les corrigés ne sont jamais servis
par l'API (V76), donc elle les lit dans les fixtures, comme un auteur. Ouvrir une
porte pour se faciliter la tâche invaliderait à la fois la mesure et la garantie.
Deux tests gardent ces deux points.

## 2. Les six chaînes

### C1 · exercice → mission → compétence — *la chaîne du défaut `A13`*

```
écrit : evidence +2 · evidenceQualifiantes +1 · exerciseAttempts +1 · missionSubmissions +3
  exercise:cicd-env-promotion   passed/exercise-tests        VALIDATED
  mission:cicd-blocked-delivery manual/mission-deliverables  DECLARED
```

Le CP0 mesurait **deux preuves qualifiantes** sur la même compétence à partir
d'un exercice résolu, d'un document délibérément faux et d'un clic. Il y en a
toujours **deux** — rien n'a été supprimé, la mission a bien eu lieu — mais
**une seule démontre**.

Les trois `missionSubmissions` sont le document, l'auto-évaluation et la
validation : ce que `passed` recouvrait abusivement est désormais écrit là où
c'est vrai.

### C2 · diagnostic échoué puis réussi

```
écrit : assessmentAttempts +2 · evidence +2 · evidenceQualifiantes +1
  assessment:async-messaging-queues  failed/assessment-grade  OBSERVED
  assessment:async-messaging-queues  passed/assessment-grade  VALIDATED
```

Avant le CP4, la seconde soumission était refusée comme doublon : il ne restait
que l'échec. La courbe existe maintenant, et **seule la réussite démontre**.

### C3 · capstone corrigé par le serveur

```
écrit : assessmentAttempts +1 · evidence +1 · evidenceQualifiantes +1
  capstone:agent-tool-loop-incident  passed/capstone-grade  VALIDATED
```

Avant le CP6 : archivé `self` — une auto-déclaration — tout en créditant
`demonstrated`. Deux phrases opposées sur le même objet.

### C4 · artefact : sans, puis posté, puis repris

```
sans artefact → RIEN
avec artefact → artifactAnalyses +2   (evidence : 0)
```

**La garde la plus facile à perdre du CP7**, vérifiée sur le produit qui tourne :
`analyze` sans artefact calcule les mêmes diagnostics et **n'écrit pas un
octet** ; deux versions postées font deux productions ; et aucune preuve n'en
naît.

### C5 · terminal + pipelines

```
écrit : usageEvents +2   (evidence 0 · exerciseAttempts 0 · assessmentAttempts 0)
```

Le moteur de pipeline a rendu `status: success`, et **le fait ne le porte pas** :
le statut mesure la fixture, pas la personne.

### C6 · consulter, réinitialiser, demander le corrigé

```
écrit : RIEN
```

**Et c'est une réponse valide.** Ouvrir une page n'est pas un fait de travail, et
`remediate` rend la correction **du produit**, pas celle de l'apprenant. Réparer
cette chaîne pour remplir un tableau serait exactement le piège que V77 passe son
temps à éviter.

## 3. Ce que la traversée confirme, et ce qu'elle ne peut pas confirmer

**Confirmé** : les décisions des CP3 → CP11 tiennent **ensemble**, sur le produit
assemblé, pas seulement dans leurs modules. Six chaînes, six résultats attendus,
zéro écart.

**Non confirmé, et non confirmable ici** : qu'un humain apprenne quoi que ce
soit. Ces chaînes prouvent que le système **observe proprement**. Ce que les
observations valent pédagogiquement est la question de V78, et aucune sonde de
V77 n'a le droit d'y répondre.

## 4. Le résultat est publié ET pinné

`docs/v77/cp13-e2e.json` contient le détail des six chaînes. Neuf tests en
gardent le contenu : ils **ne remplacent pas** la sonde — ils empêchent qu'un
comportement change sans que personne ne la rejoue. Si le produit change, le
fichier publié devient faux et les tests rougissent : c'est précisément le signal
qu'il faut relancer la traversée.
