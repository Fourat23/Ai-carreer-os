## 🎯 Objectif du jour

## 📖 Cours approfondi
**Modèle mental : un seul split train/test peut MENTIR par chance — un test facile gonfle le score, un test difficile le déprime. La validation croisée en k folds fait TOURNER le rôle du test sur toutes les données, donnant une estimation MOYENNE de la performance ET sa VARIABILITÉ, bien plus fiable pour comparer des modèles.** C'est le passage d'une mesure unique et fragile à une mesure robuste avec barre d'incertitude — indispensable dès qu'on compare des modèles ou qu'on règle des hyperparamètres, car une décision fondée sur un split chanceux est trompeuse.

Le mécanisme, depuis les fondations :
1. **Le k-fold** : on découpe les données en k parts (folds) égales. On entraîne k fois : à chaque tour, un fold différent sert de test et les k-1 autres d'entraînement. Chaque exemple sert donc UNE fois au test et k-1 fois à l'entraînement. On obtient k scores.
2. **Moyenne ET écart-type** : la performance estimée est la MOYENNE des k scores ; leur écart-type dit la VARIABILITÉ (à quel point le score dépend du découpage). Un modèle avec une moyenne de 0,80 ± 0,02 est plus fiable qu'un modèle à 0,82 ± 0,15 : le second est instable.
3. **Pourquoi c'est plus fiable** : un seul split utilise ~20 % des données pour tester, une seule fois — le résultat dépend fortement de QUELS exemples sont tombés dans le test. La CV utilise TOUTES les données pour tester (à tour de rôle) et moyenne, réduisant l'effet du hasard du découpage.
4. **Les courbes d'apprentissage** : tracer la performance en fonction de la TAILLE d'entraînement révèle si le modèle bénéficierait de plus de données (les courbes train et validation se rejoignent-elles ? un écart persistant = surapprentissage ; un plateau bas = sous-apprentissage).

La précaution cruciale — pas de leakage dans la CV : tout préprocessing (normalisation, imputation) doit être appris DANS chaque fold d'entraînement, jamais sur l'ensemble complet, sinon l'information fuit du fold de test (jour 157). C'est exactement pourquoi on encapsule préprocessing + modèle dans un Pipeline (jour 171) avant de faire une CV : le Pipeline garantit que chaque fold est traité proprement.

Quand l'utiliser : pour COMPARER des modèles ou régler des hyperparamètres (jour 179), la CV est la référence — un seul split ne suffit pas pour une décision. Pour l'évaluation finale, on garde en plus un jeu de test JAMAIS touché pendant la CV.

La règle du jour : **la validation croisée en k folds fait tourner le test sur toutes les données et donne moyenne + variabilité, bien plus fiable qu'un split unique pour comparer des modèles ; le préprocessing s'apprend dans chaque fold (via Pipeline) pour éviter le leakage. Une décision sur un seul split est un pari sur la chance du découpage**.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : évaluer un modèle en cross-validation 5 folds, tracer une courbe d'apprentissage, comparer des modèles.

**Exemple simple** : moyenne ET écart-type — `cross_val_score(...)` renvoie 5 scores comme `[0.79, 0.82, 0.77, 0.81, 0.80]` ; on rapporte `0,80 ± 0,02`. L'écart-type dit si le modèle est stable ou dépend du découpage.

**Raisonnement pas-à-pas** : encapsuler préprocessing + modèle dans un Pipeline (anti-leakage) → cross_val_score sur 5 folds → lire moyenne et écart-type → comparer plusieurs modèles sur la MÊME CV.

**Implémentation** :
```python
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier
import numpy as np

# Pipeline : le préprocessing est ré-appris dans CHAQUE fold (pas de leakage)
logreg = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
foret = RandomForestClassifier(n_estimators=300, random_state=42)

for nom, modele in [("logreg", logreg), ("forêt", foret)]:
    scores = cross_val_score(modele, X, y, cv=5, scoring="roc_auc")
    print(f"{nom}: {scores.mean():.3f} ± {scores.std():.3f}")   # moyenne ± variabilité
```

**Mini-quiz** : (a) Pourquoi un seul split train/test peut-il tromper ? (b) Qu'apporte l'écart-type des scores de CV ? (c) Pourquoi le préprocessing doit-il être dans un Pipeline pour la CV ?
→ (a) le score dépend de QUELS exemples sont tombés dans le test — un test chanceux ou difficile fausse la mesure unique ; (b) la VARIABILITÉ : un modèle à 0,80 ± 0,02 est plus fiable qu'à 0,82 ± 0,15 (instable) ; (c) pour que le préprocessing soit ré-appris sur le train de chaque fold seulement, sinon l'info fuit du fold de test (leakage).

**Variante** : compare deux modèles dont les moyennes sont proches mais les écarts-types différents. Le plus stable (écart-type faible) est souvent préférable, même à moyenne légèrement inférieure — la fiabilité compte autant que le score.

## ⚠️ Erreurs fréquentes
- Décider entre modèles sur un seul split : on parie sur la chance du découpage.
- Faire le préprocessing sur l'ensemble complet avant la CV : leakage qui surestime la performance — l'encapsuler dans un Pipeline.
- Ne rapporter que la moyenne : sans l'écart-type, on ignore si le modèle est stable.
- Confondre CV (comparaison/réglage) et test final : garder un jeu de test jamais touché pendant la CV.

## 🏢 Cas métier
La validation croisée est le standard pour comparer des modèles et régler des hyperparamètres de façon fiable : décider entre deux modèles sur un seul split, c'est parier sur la chance du découpage, et de mauvaises décisions coûteuses en découlent (déployer le modèle qui « semblait » meilleur par hasard). En compétition et en entreprise, la CV avec moyenne ± écart-type est la référence pour toute comparaison sérieuse. La précaution anti-leakage (préprocessing dans le Pipeline, ré-appris à chaque fold) est ce qui rend la CV honnête — une CV avec préprocessing global surestime la performance, comme un split unique avec leakage. Maîtriser la CV et sa mise en œuvre sans leakage est une compétence d'évaluation fondamentale, directement testée en entretien.

## 🎤 Question d'entretien
**« Pourquoi utiliser la validation croisée plutôt qu'un simple train/test split ? »** → Parce qu'un seul split peut mentir par chance : le score dépend de QUELS exemples sont tombés dans le test (un test facile gonfle, un test difficile déprime). La CV en k folds fait tourner le rôle du test sur toutes les données : on entraîne k fois, chaque fold sert une fois de test, et on obtient k scores. On rapporte la MOYENNE (performance estimée) ET l'écart-type (variabilité) — un modèle à 0,80 ± 0,02 est plus fiable qu'à 0,82 ± 0,15. C'est indispensable pour COMPARER des modèles ou régler des hyperparamètres : une décision sur un seul split est un pari. Précaution cruciale : le préprocessing doit être ré-appris dans chaque fold d'entraînement (via un Pipeline), sinon l'information fuit du fold de test — un leakage qui surestime la performance. On garde en plus un test final jamais touché pendant la CV.
