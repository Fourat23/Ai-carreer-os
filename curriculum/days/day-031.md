## 🎯 Objectif du jour
Résoudre la famille de problèmes 'chercher une paire/un complément' en O(n) avec une Map, et reconnaître ce pattern d'entretien omniprésent.

## 📖 Cours approfondi
**Concepts abordés :** twoSum · Complément · Map pour mémoriser le vu · O(n²) → O(n) · Reconnaissance de pattern.

Le pattern « complément » : au lieu de comparer chaque paire (double boucle, O(n²)), on parcourt UNE fois en se demandant à chaque élément « ai-je déjà vu la valeur qui me manque ? ». Une Map mémorise les valeurs vues avec leur index : la question coûte O(1), le total O(n).

Ce schéma (mémoriser le vu, interroger le passé) résout toute une famille de problèmes : paires de somme/différence donnée, doublons proches, sous-tableaux de somme cible (via les sommes cumulées : si cumul[j] - cumul[i] = 0, le sous-tableau i..j somme à zéro).

C'est LE réflexe attendu en entretien : dès que tu écris une double boucle de recherche, demande-toi si une Map ne supprime pas la boucle interne.

**Modèle mental : une Map ÉCHANGE de la mémoire contre du temps. Au lieu de re-parcourir le tableau pour chercher « la valeur qui me manque » (le complément), tu la mémorises au fur et à mesure et tu l'interroges en O(1). La double boucle O(n²) devient une seule passe O(n) parce que la recherche interne — le vrai coût — disparaît, absorbée par la table de hachage.** Ce n'est pas une astuce propre à twoSum : c'est LE réflexe qui transforme une famille entière de problèmes de « chercher une paire » de quadratique en linéaire.

Pourquoi ce pattern existe, depuis les fondations. Chercher un élément dans un tableau non trié coûte O(n) : tu dois potentiellement tout regarder. Une table de hachage range les éléments dans des « cases » calculées à partir de la valeur elle-même (la fonction de hachage) : retrouver une valeur ne demande plus de parcourir, mais de recalculer sa case — coût O(1) en moyenne. Le prix : de la mémoire supplémentaire (la table) et une hypothèse de bon hachage (les collisions dégradent vers O(n) dans le pire cas, rare en pratique).

Comment le pattern « complément » fonctionne concrètement. Pour `twoSum(arr, cible)`, à chaque élément `x` tu ne cherches pas « existe-t-il un `y` tel que `x + y = cible` » en re-balayant : tu demandes à la Map « ai-je DÉJÀ vu `cible - x` ? ». Si oui, la paire est trouvée ; sinon tu enregistres `x` et tu continues. Chaque valeur n'est vue qu'une fois pour l'écriture, une fois pour l'interrogation.

La différence avec les approches proches, pour ne pas confondre. Le **tri + deux pointeurs** résout aussi twoSum en O(n log n) et O(1) mémoire — meilleur si la mémoire est critique ou si le tableau est déjà trié, mais il DÉTRUIT l'ordre (donc les indices d'origine). La **double boucle** O(n²) reste acceptable pour de très petits tableaux (n < ~50) où la simplicité prime. Le choix hash map gagne quand n est grand ET qu'on peut payer la mémoire — le cas le plus fréquent en entretien.

Les limites et compromis à assumer. La Map coûte O(n) de mémoire : sur des volumes énormes contraints en RAM, le tri + deux pointeurs redevient pertinent. Et l'O(1) est amorti « en moyenne » : un adversaire ou de mauvaises clés peuvent provoquer des collisions. Enfin, attention au sens de la question — chercher le complément AVANT ou APRÈS avoir inséré l'élément courant change si l'on autorise `i == j`.

La règle du jour : **dès que tu écris une double boucle dont la boucle interne CHERCHE quelque chose, demande-toi si une Map (mémoriser le vu pour interroger le passé en O(1)) ne supprime pas cette boucle interne. C'est le réflexe d'entretien le plus rentable de tout le mois.**

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : écrire `twoSum(arr, cible)` en O(n) qui renvoie les deux INDICES dont les valeurs somment à la cible, puis comprendre pourquoi une variante (sous-tableau de somme nulle) réutilise le même réflexe via les sommes cumulées.

**Exemple simple** : sur `[2, 7, 11, 15]` avec cible `9`. La naïve teste `(2,7), (2,11), (2,15), (7,11)…` → 6 paires. Le réflexe complément : à l'élément `2`, je cherche `9 - 2 = 7` dans la Map (vide → j'enregistre `2→index 0`) ; à l'élément `7`, je cherche `9 - 7 = 2` → trouvé à l'index 0 → réponse `[0, 1]`. Deux éléments visités, zéro boucle interne.

**Raisonnement pas-à-pas** : (1) je parcours une seule fois ; (2) pour chaque `x`, je calcule le complément `cible - x` ; (3) je demande à la Map si ce complément a déjà été vu ; (4) si oui → paire trouvée ; (5) sinon j'enregistre `x → son index` et je continue. L'ordre « chercher PUIS enregistrer » garantit qu'on n'apparie pas un élément avec lui-même.

**Implémentation** :
```ts
function twoSum(arr: number[], cible: number): [number, number] | null {
  const vus = new Map<number, number>();   // valeur -> index
  for (let i = 0; i < arr.length; i++) {
    const complement = cible - arr[i];
    if (vus.has(complement)) {              // déjà vu -> paire trouvée
      return [vus.get(complement)!, i];
    }
    vus.set(arr[i], i);                     // sinon, mémoriser puis continuer
  }
  return null;                              // aucune paire
}

console.log(twoSum([2, 7, 11, 15], 9));     // [0, 1]
console.log(twoSum([3, 3], 6));             // [0, 1] : chercher AVANT d'insérer
console.log(twoSum([1, 2, 3], 100));        // null
```

**Le même réflexe, variante sous-tableau de somme nulle** : on parcourt en gardant la somme cumulée ; si une même somme cumulée réapparaît, le segment entre les deux positions somme à zéro. La Map mémorise `sommeCumulée → index`, initialisée à `{0: -1}` pour capter un préfixe entier.
```ts
function sousTableauSommeNulle(arr: number[]): [number, number] | null {
  const vues = new Map<number, number>([[0, -1]]);  // somme 0 "avant le début"
  let cumul = 0;
  for (let i = 0; i < arr.length; i++) {
    cumul += arr[i];
    if (vues.has(cumul)) return [vues.get(cumul)! + 1, i];
    vues.set(cumul, i);
  }
  return null;
}
console.log(sousTableauSommeNulle([3, 4, -7, 5]));   // [0, 2] : 3+4-7 = 0
```

## ⚠️ Erreurs fréquentes
- Chercher le complément APRÈS avoir inséré l'élément courant : on l'apparie avec lui-même (i == j) à tort.
- Sommes cumulées : oublier d'initialiser la Map avec {0: -1}, ce qui rate les préfixes qui somment à la cible.
- Confondre « renvoyer les valeurs » et « renvoyer les indices » : la Map doit stocker l'index, pas juste la présence.
- Croire que la Map garantit O(1) dans le PIRE cas : c'est O(1) amorti/moyen ; des collisions massives dégradent vers O(n).

## 🏢 Cas métier
Le réflexe hash map est omniprésent dès qu'un système doit « rapprocher » des données à grand volume : dédoublonnage de contacts (a-t-on déjà vu cet email ?), rapprochement bancaire (associer un débit à un crédit du même montant), détection de doublons dans un flux d'événements, jointure en mémoire de deux jeux de données. Un développeur qui écrit une double boucle sur 100 000 lignes fait ramer le service pendant des secondes ; celui qui indexe un côté dans une Map répond en millisecondes. En entretien technique, twoSum et ses variantes sont un filtre de premier tour quasi systématique — savoir passer du naïf à l'optimal EN EXPLIQUANT le compromis mémoire/temps est exactement ce que le recruteur mesure.

## 🎤 Question d'entretien
**« On te donne un tableau et une cible. Renvoie les indices de deux éléments dont la somme vaut la cible. Optimise. »** → Je pars de la solution naïve pour cadrer : deux boucles imbriquées testent toutes les paires, O(n²). Je l'optimise avec le réflexe complément : une seule passe, et pour chaque élément `x` je demande à une Map « ai-je déjà vu `cible - x` ? » — la Map répond en O(1), donc le total tombe à O(n) en temps contre O(n) en mémoire. Un détail important : je cherche le complément AVANT d'insérer l'élément courant, pour ne pas l'apparier avec lui-même. Le compromis à assumer : j'échange de la mémoire contre du temps ; si la RAM était critique, un tri + deux pointeurs ferait O(n log n) et O(1) mémoire, mais détruirait les indices d'origine. **Relance possible** : « et pour trouver un sous-tableau CONTIGU de somme nulle ? » → même réflexe avec les sommes cumulées : si une somme cumulée réapparaît, le segment entre les deux positions somme à zéro (Map initialisée à `{0: -1}`).
