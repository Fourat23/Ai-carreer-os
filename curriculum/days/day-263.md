## 🎯 Objectif du jour
Répondre 'je ne sais pas'.

## 📖 Cours approfondi
**Modèle mental : le refus n'est pas un échec du système, c'est une FONCTIONNALITÉ qui préserve la confiance — un RAG qui répond toujours est un RAG qui ment parfois.** Tu as construit le refus au jour 220 ; aujourd'hui tu le traites comme une feature de premier plan, calibrée et testée, parce que c'est elle qui détermine si un professionnel peut se FIER au système. La logique : mieux vaut « je ne trouve pas cette information dans les documents » qu'une réponse plausible mais infondée. Dans les domaines à enjeu, un refus honnête vaut mieux que dix bonnes réponses gâchées par une hallucination confiante.

Les trois situations qui doivent déclencher un refus :
1. **Hors corpus** : la question porte sur quelque chose d'absent du corpus. Détecté par des scores de retrieval faibles (sous le seuil de refus, jour 227) — le cas vicieux étant la question PROCHE du corpus sans y être (jour 236).
2. **Corpus insuffisant** : le sujet est dans le corpus mais les extraits ne contiennent pas de quoi répondre complètement. Réponse honnête : « les documents mentionnent X mais ne précisent pas Y ».
3. **Après échec de vérification** : les citations ne tiennent pas (jour 262) — l'ancrage échoue, donc on refuse plutôt que d'afficher du non-ancré.

Le calibrage est l'enjeu central — c'est un arbitrage entre deux erreurs symétriques :
- **Refus trop laxiste** (le système répond même quand il ne devrait pas) : hallucinations habillées de citations, la confiance s'effondre au premier mensonge découvert.
- **Refus trop strict** (le système refuse des questions qu'il pourrait traiter) : l'utilisateur est frustré, contourne l'outil, l'abandonne.

Le bon seuil se règle sur les DEUX types d'erreurs mesurés sur le golden set — les questions hors corpus (doivent être refusées) ET les questions couvertes (ne doivent PAS l'être). Ton golden set a les deux (jour 253). Et un bon refus n'est pas un mur : il EXPLIQUE (pourquoi il ne peut pas répondre) et ORIENTE (reformuler ? le corpus couvre tel thème ? contacter qui ?). Le refus est une conversation, pas une porte fermée.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : le refus comme feature calibrée — déclencheurs, message utile, calibrage sur golden set.

**Raisonnement** : implémenter les trois déclencheurs, soigner le message, calibrer le seuil sur les deux types d'erreurs.

**Implémentation** :
```python
def repondre_avec_refus(question: str) -> str:
    top = retrieve_avec_scores(question)
    if top[0].score < SEUIL_REFUS:                       # 1. hors corpus
        return refus_utile("hors_corpus", question, corpus_themes())
    reponse = generer(question, top)
    if reponse.dit_information_absente():                # 2. corpus insuffisant
        return refus_utile("insuffisant", question, ce_qui_manque=reponse.manque)
    if not citations_valides(reponse, top):              # 3. échec vérification (j.262)
        return refus_utile("non_ancre", question)
    return reponse

def refus_utile(cause, question, *args):
    # EXPLIQUE + ORIENTE, jamais un simple "je ne sais pas"
    return {
        "hors_corpus": f"Je ne trouve pas cette information dans les documents. "
                       f"Le corpus couvre : {corpus_themes()}. Reformulez ou vérifiez le périmètre.",
        "insuffisant": f"Les documents abordent le sujet mais ne précisent pas {args}. ",
        "non_ancre":   "Je ne peux pas répondre de façon sourcée à cette question.",
    }[cause]
```

**Le calibrage (les deux erreurs)** :
```
Sur le golden set : questions hors corpus (doivent refuser) + couvertes (ne doivent pas)
  seuil trop bas (0,30) : 0 hors-corpus refusé (répond à tout, hallucine)
  seuil trop haut (0,65): 4 questions COUVERTES refusées à tort (frustrant)
  seuil calibré (0,45)  : 3/3 hors-corpus refusés, 0 couverte refusée -> optimal
Matrice : refus justifiés / refus injustifiés / réponses justifiées / hallucinations
```

**Explication** : le calibrage sur les DEUX types d'erreurs est ce qui distingue un seuil réfléchi d'un nombre au hasard — trop strict et trop laxiste sont deux échecs symétriques. **Variante** : ajoute un niveau intermédiaire « réponse avec avertissement » (« d'après les documents, probablement X, mais l'information est partielle ») pour les cas limites entre répondre et refuser — souvent plus utile que le binaire.

## ⚠️ Erreurs fréquentes
- Traiter le refus comme un échec à minimiser : c'est une feature — un système qui répond toujours est un système qui ment parfois.
- Calibrer le seuil sur les seuls cas hors-corpus : sans les questions COUVERTES, tu ne vois pas les refus injustifiés (le côté frustrant).
- Un refus-mur (« je ne sais pas ») sans explication ni orientation : l'utilisateur ne sait pas quoi faire, il abandonne.
- Régler le seuil sur les questions évidentes : le vrai test est la question PROCHE du corpus (jour 236) — c'est elle qui piège les seuils naïfs.

## 🏢 Cas métier
Les assistants documentaires qui gagnent la confiance des professionnels partagent un trait : ils savent dire « je ne sais pas ». Un juriste qui teste un assistant et le prend en flagrant délit d'invention (une jurisprudence plausible mais fausse) ne l'utilisera plus jamais — un seul mensonge découvert détruit la confiance. À l'inverse, un système qui refuse honnêtement quand il ne sait pas gagne le droit d'être cru quand il répond. Le refus calibré est littéralement ce qui rend un RAG déployable auprès d'experts — un argument produit majeur.

## 🎤 Question d'entretien
**« Pourquoi et comment ton RAG refuse-t-il de répondre ? »** → Le refus est une feature qui préserve la confiance : un système qui répond toujours hallucine parfois, et un seul mensonge découvert détruit la crédibilité. Trois déclencheurs : hors corpus (scores faibles), corpus insuffisant (le sujet est là mais pas la réponse), échec de vérification des citations. Le seuil se calibre sur les DEUX erreurs symétriques — trop laxiste (hallucine) et trop strict (frustre) — mesurées sur le golden set. Et un bon refus explique et oriente, il n'est pas un mur.

## 🧩 Questions de réflexion (à faire seul)
- Ton RAG répond « je ne sais pas » quand le corpus ne contient pas la réponse : pourquoi est-ce une FEATURE et non un aveu d'échec, et que vaut-elle mieux qu'une réponse inventée ?
- Côté système, comment distingues-tu « l'info n'est pas dans le corpus » de « le retrieval a raté un chunk qui existait » — deux causes de refus qui n'appellent pas la même réaction ?
- Un refus trop fréquent rend le RAG inutile, un refus trop rare le rend dangereux : sur quoi calibres-tu ce seuil, et comment le mesures-tu ?
