## 🎯 Objectif du jour
Chaînage, parallélisation, routage, évaluateur.

## 📖 Cours approfondi
**Modèle mental : presque tous les systèmes LLM se construisent avec quatre patterns de workflow — les connaître, c'est avoir un vocabulaire de composition au lieu de réinventer à chaque fois.** Une fois qu'on renonce à l'autonomie totale de l'agent (jour 278), les tâches se composent à partir de quatre briques fondamentales, combinables. Les maîtriser transforme « comment structurer ce système ? » en « quel(s) pattern(s) appliquer ? ».

Les quatre patterns :
1. **Chaînage (prompt chaining)** : décomposer une tâche complexe en étapes séquentielles où chaque sortie nourrit la suivante (résumer → traduire → reformater). On l'utilise quand une tâche est trop complexe pour un seul prompt fiable : la découper en étapes simples et vérifiables augmente la fiabilité (chaque étape peut être validée avant de continuer). Ton vérificateur du jour 281 en est un.
2. **Parallélisation** : exécuter plusieurs appels INDÉPENDANTS en même temps, puis agréger. Deux variantes — le sectionnement (découper une tâche en sous-tâches parallèles : analyser 10 documents à la fois) et le vote (poser la même question N fois et agréger pour la fiabilité). Gain : latence (les appels ne s'attendent pas) et parfois qualité (le vote).
3. **Routage** : classer l'entrée puis l'aiguiller vers le traitement spécialisé adapté (une question technique → prompt technique, une facturation → prompt facturation). C'est ce qui donne au workflow sa flexibilité SANS l'autonomie de l'agent : les branches sont PRÉVUES, pas décidées librement. Le routeur est souvent lui-même un petit appel LLM de classification.
4. **Évaluateur-optimiseur (evaluator-optimizer)** : un générateur produit, un évaluateur critique, le générateur corrige — en boucle jusqu'à un critère de qualité. C'est un cycle CONTRÔLÉ (contrairement à l'agent, le rôle de chaque appel est fixe) utile quand la qualité s'améliore par itération (rédaction, code) et qu'on a un critère d'évaluation clair.

La compétence n'est pas de réciter les quatre mais de RECONNAÎTRE lequel s'applique : tâche trop complexe pour un prompt → chaînage ; sous-tâches indépendantes → parallélisation ; entrées de natures différentes → routage ; qualité perfectible par itération avec critère → évaluateur-optimiseur. Et de les COMBINER : un système réel route l'entrée, chaîne le traitement, parallélise une étape lourde, et fait évaluer la sortie. Chacun garde les vertus du workflow (prévisibilité, testabilité) tout en couvrant des besoins variés.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : implémenter les 4 patterns sur des cas simples et comprendre quand chacun s'applique.

**Exemple simple** : le routage en une image — `categorie = classer(entree); resultat = traitements[categorie](entree)`. Un appel pour classer, puis le bon traitement. C'est le if/else, mais la condition est un jugement LLM.

**Raisonnement pas-à-pas** : un cas minimal par pattern, en notant le SIGNAL qui déclenche son choix.

**Les 4 patterns** :
```python
# 1. CHAÎNAGE : tâche complexe → étapes séquentielles vérifiables
out = reformater(traduire(resumer(texte)))            # signal : trop pour un prompt

# 2. PARALLÉLISATION : sous-tâches indépendantes, agrégées
resultats = await gather(*[analyser(doc) for doc in docs])   # signal : indépendance
synthese = agreger(resultats)

# 3. ROUTAGE : classer puis aiguiller
cat = classer_llm(question)                           # signal : entrées hétérogènes
reponse = traitements[cat](question)

# 4. ÉVALUATEUR-OPTIMISEUR : générer → critiquer → corriger, en boucle bornée
draft = generer(tache)
for _ in range(3):
    critique = evaluer(draft)                          # signal : qualité itérable
    if critique.ok: break
    draft = corriger(draft, critique)
```

**Mini-quiz** : (a) Quel pattern pour « analyser 500 documents indépendants » ? (b) Quel pattern donne au workflow sa flexibilité sans l'autonomie de l'agent ? (c) En quoi l'évaluateur-optimiseur diffère-t-il d'un agent ?
→ (a) parallélisation (sectionnement) ; (b) le routage (branches prévues, pas décidées librement) ; (c) les rôles sont FIXES (générer/évaluer/corriger) et la boucle est bornée — pas de décision libre de flux.

**Variante** : combine deux patterns sur un cas réel (router les tickets PUIS chaîner le traitement de chaque catégorie) — les systèmes réels sont des COMPOSITIONS de patterns, rarement un seul.

## 🏢 Cas métier
Ces quatre patterns couvrent l'écrasante majorité des systèmes LLM en production — les frameworks d'orchestration ne font que les outiller. Un modérateur de contenu ROUTE par type, PARALLÉLISE l'analyse de plusieurs critères, et CHAÎNE décision → justification. Un assistant de rédaction utilise l'ÉVALUATEUR-OPTIMISEUR. Reconnaître le pattern adapté (au lieu de tout jeter dans un agent ou un mégaprompt) est ce qui produit des systèmes prévisibles et maintenables. Les ingénieurs qui pensent en patterns composables construisent plus vite et plus fiable — un vocabulaire d'architecture directement valorisé.

## 🎤 Question d'entretien
**« Quels patterns de workflow LLM connais-tu et quand les appliques-tu ? »** → Quatre : le chaînage (décomposer une tâche trop complexe pour un prompt en étapes vérifiables), la parallélisation (sous-tâches indépendantes exécutées ensemble puis agrégées — sectionnement ou vote), le routage (classer l'entrée puis aiguiller vers le traitement spécialisé — la flexibilité du workflow sans l'autonomie de l'agent), et l'évaluateur-optimiseur (générer → critiquer → corriger en boucle bornée, quand la qualité s'améliore par itération). Le signal de choix : complexité → chaînage, indépendance → parallélisation, hétérogénéité → routage, qualité itérable → évaluateur. Et je les COMPOSE : les systèmes réels combinent plusieurs patterns.
