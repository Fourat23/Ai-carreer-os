## 📖 Cours approfondi
**Modèle mental : la génération avec citations vérifiables + refus honnête est ce qui transforme DocSense de « chatbot qui répond » en « assistant en qui on peut avoir confiance » — c'est la fonctionnalité qui rend le projet DÉPLOYABLE, pas juste démontrable.** Tu as construit la génération citée (jour 220), la vérification des citations (262) et le refus calibré (263) au fil du programme ; ici tu les assembles dans DocSense en une génération de qualité production : chaque affirmation ancrée dans une source vérifiable, un refus propre quand l'information est absente, un format soigné.

Les trois piliers d'une génération fiable :
1. **Les citations vérifiables** : chaque affirmation de la réponse cite sa source [n], et cette citation est VÉRIFIÉE automatiquement (la source citée contient bien l'affirmation, jour 262). L'utilisateur peut cliquer et vérifier ; le système garantit l'ancrage. C'est le mécanisme de CONFIANCE — sans lui, l'utilisateur doit croire aveuglément.
2. **Le refus si absent** : quand le retrieval ne rapporte rien de pertinent (scores faibles) ou que la génération ne peut pas s'ancrer, DocSense REFUSE honnêtement (« les documents ne permettent pas de répondre ») plutôt que d'inventer. Un système qui refuse honnêtement gagne le droit d'être cru quand il répond (jour 263). Le refus est une feature, pas un échec.
3. **Le format soigné** : la réponse est structurée (concise pour une factuelle, structurée pour une synthèse), les citations sont lisibles et cliquables, le refus est un message utile (pas une erreur brute). Le soin du format fait la différence entre un outil qu'on utilise et un gadget qu'on abandonne.

Pourquoi c'est la fonctionnalité qui rend DocSense déployable : un assistant documentaire qui invente avec aplomb est dangereux (rappelle l'affaire des jurisprudences inventées, jour 201) ; un assistant qui cite des sources vérifiables et refuse quand il ne sait pas est un outil qu'un professionnel (juriste, développeur) ose utiliser. Les citations vérifiables sont ce qui permet de FAIRE CONFIANCE au système — et donc de le déployer dans un contexte réel. C'est aussi la démonstration la plus vendeuse de DocSense en entretien : montrer une réponse citée vérifiable puis une question piège refusée proprement prouve que tu construis des systèmes IA responsables, pas des perroquets confiants.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : la génération de DocSense avec citations vérifiables, refus si absent, format soigné.

**Exemple simple** : le contrat de génération en une consigne — « réponds UNIQUEMENT à partir des extraits, cite [n] chaque affirmation, et si les extraits ne suffisent pas, dis-le ». Le refus est dans le contrat, pas une exception.

**Raisonnement pas-à-pas** : contrat de génération strict, vérification des citations en aval, refus sur ancrage insuffisant, format soigné.

**Implémentation** :
```python
def generer(question, chunks) -> ReponseCitee:
    if not chunks or chunks[0].score < SEUIL_REFUS:      # refus si rien de pertinent
        return ReponseCitee(refus=True, message=REFUS_UTILE)
    reponse = llm_call(system=CONTRAT_STRICT,            # sources uniquement + citations
                       prompt=format_sources(chunks) + question, temp=0)
    if not verifier_citations(reponse, chunks):          # vérification aval (jour 262)
        return ReponseCitee(refus=True, message=REFUS_NON_ANCRE)
    return ReponseCitee(texte=reponse.texte, citations=reponse.citations)  # format soigné
```

**Mini-quiz** : (a) Pourquoi les citations doivent-elles être VÉRIFIÉES, pas juste présentes ? (b) Pourquoi le refus est-il une feature ? (c) Qu'est-ce qui rend DocSense déployable auprès d'un professionnel ?
→ (a) le modèle peut citer décorativement ou mal ; la vérification garantit que la source soutient vraiment l'affirmation ; (b) un système qui refuse honnêtement gagne le droit d'être cru quand il répond ; (c) les citations vérifiables + le refus honnête — l'utilisateur peut faire confiance et vérifier.

**Variante** : teste les 3 régimes sur le corpus DocSense — une question répondable (réponse + citations vérifiées), une question hors corpus (refus propre), une question dont la réponse est répartie sur 2 documents (les deux cités). C'est la démo qui prouve la fiabilité.

## 🏢 Cas métier
Les citations vérifiables et le refus honnête sont ce qui sépare un assistant documentaire déployable d'un gadget dangereux : dans les domaines à enjeu (juridique, médical, technique), un professionnel n'utilisera un assistant que s'il peut VÉRIFIER ses réponses et compter sur lui pour dire « je ne sais pas » plutôt qu'inventer. Une démo de deux assistants — l'un qui répond à tout avec assurance, l'autre qui cite des sources cliquables et refuse honnêtement — montre lequel obtient le budget : le second, parce qu'on peut lui faire confiance. Pour DocSense, cette fonctionnalité est le cœur de la valeur, et « regarde, je vérifie cette citation en un clic, et cette question piège est refusée proprement » est la démonstration la plus vendeuse du projet en entretien.

## 🎤 Question d'entretien
**« Qu'est-ce qui rend un assistant documentaire digne de confiance ? »** → Trois choses : des citations VÉRIFIABLES (chaque affirmation cite sa source, et je vérifie automatiquement que la source la soutient vraiment — le modèle peut citer décorativement), un refus HONNÊTE quand l'information est absente (scores faibles ou ancrage impossible → « les documents ne permettent pas de répondre » plutôt qu'inventer), et un format soigné. Le refus est une feature : un système qui refuse honnêtement gagne le droit d'être cru quand il répond. Ces mécanismes rendent DocSense déployable auprès d'un professionnel qui peut vérifier et faire confiance — la différence entre un outil et un perroquet confiant dangereux.
