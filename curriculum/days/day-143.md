## 🎯 Objectif du jour
Nettoyer et transformer.

## 📖 Cours approfondi
**Modèle mental : la transformation de DataPulse est un pipeline de FONCTIONS PURES documentées qui produit, en plus des données propres, un RAPPORT DE QUALITÉ — c'est le jour 132 (fonctions pures) et le jour 128 (nettoyage justifié) appliqués à ta VRAIE source, avec la traçabilité qui rend ton analyse défendable devant un tiers.** Le transform est le cœur métier du pipeline : il prend le brut extrait (jour 142) et le prépare pour répondre aux 3 questions du cadrage (jour 141). Rien n'y est écrit en base (c'est le load), tout se fait en mémoire, en fonctions pures et testables.

Ce que le transform de DataPulse doit accomplir :
1. **Valider** (jour 132) : vérifier les invariants attendus et échouer tôt si la source, même bien formée, contient des données aberrantes qui invalideraient l'analyse.
2. **Nettoyer avec justification** (jour 128) : traiter manquants, doublons, formats et valeurs impossibles — chaque décision JUSTIFIÉE, car chaque décision introduit un biais. Ici, les décisions sont GUIDÉES par les questions : on nettoie ce qui sert les réponses (une question sur l'évolution mensuelle exige une colonne date propre et typée).
3. **Dériver les colonnes nécessaires aux questions** : si une question porte sur le jour de la semaine, on le calcule ; si une autre porte sur une catégorie, on la normalise. Le transform PRÉPARE les agrégations du dashboard.
4. **Produire le rapport de qualité** : le livrable qui accompagne les données — combien de lignes en entrée/sortie, quels manquants traités et comment, quelles lignes rejetées et pourquoi. Ce rapport rend l'analyse REPRODUCTIBLE et DÉFENDABLE : un lecteur sait exactement ce qui a été fait aux données avant les conclusions.

Pourquoi les fonctions pures ici : le transform doit être TESTÉ (une transformation fausse produit une analyse fausse silencieusement) et REJOUABLE. Des fonctions pures (jour 132) se testent avec pytest sur des cas connus et se rejouent de façon déterministe — indispensable pour un pipeline fiable.

Le lien avec les questions : chaque transformation doit SERVIR une question. Une colonne dérivée qui ne sert aucune des 3 questions est du travail inutile ; une question sans la transformation qui la prépare ne pourra pas être répondue au dashboard. Le transform est le pont entre la source brute et les réponses.

La règle du jour : **transforme en fonctions pures testées, guidées par les 3 questions, avec chaque décision de nettoyage justifiée et un rapport de qualité qui rend l'analyse reproductible et défendable ; le transform prépare les réponses, il ne fait rien d'inutile**.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : nettoyer et transformer la source de DataPulse (fonctions pures) avec un rapport de qualité.

**Exemple simple** : une transformation GUIDÉE par une question — la question « évolution par mois » impose `df["mois"] = pd.to_datetime(df["date"]).dt.to_period("M")`. On ne dérive que ce que les questions exigent ; le reste serait du bruit.

**Raisonnement pas-à-pas** : valider (échec tôt) → nettoyer chaque problème par une décision justifiée guidée par les questions → dériver les colonnes des questions → produire le rapport avant/après.

**Implémentation** :
```python
import pandas as pd

def transform(brut: pd.DataFrame) -> tuple[pd.DataFrame, dict]:
    avant = len(brut)
    df = brut.copy()                                     # PUR (jour 132)

    # 1. Nettoyage justifié, guidé par les questions (jour 128)
    df["date"] = pd.to_datetime(df["date"], errors="coerce")  # Q1 exige une date propre
    rejets = df[df["date"].isna()]                       # dates illisibles → dead-letter
    df = df.dropna(subset=["date"])                       # décision : sans date, inexploitable pour Q1
    df = df[df["valeur"] >= 0]                            # valeurs impossibles retirées

    # 2. Dérivations pour les questions (et RIEN d'autre)
    df["mois"] = df["date"].dt.to_period("M").astype(str)      # Q1 : évolution mensuelle
    df["jour_semaine"] = df["date"].dt.day_name()             # Q3 : répartition hebdo

    rapport = {"lignes_entree": avant, "lignes_sortie": len(df),
               "rejetees": len(rejets), "decisions": [
                   "dates illisibles retirées (inexploitables pour l'évolution)",
                   "valeurs négatives retirées (impossibles)"]}
    return df, rapport                                    # données + rapport de qualité
```

**Mini-quiz** : (a) Qu'est-ce qui guide les transformations à faire ? (b) Pourquoi un rapport de qualité ? (c) Pourquoi des fonctions pures ?
→ (a) les 3 questions du cadrage — on ne prépare que ce qui sert à y répondre ; (b) il rend l'analyse reproductible et défendable : un tiers sait exactement ce qui a été fait aux données ; (c) pour tester (une transformation fausse fausse l'analyse silencieusement) et rejouer de façon déterministe.

## ⚠️ Erreurs fréquentes
- Transformer sans se référer aux questions : colonnes dérivées inutiles (bruit) ou colonne clé mal préparée (question sans réponse).
- Nettoyer sans justifier ni rapporter : l'analyse devient indéfendable — un décideur ne peut pas faire confiance.
- Écrire en base dans le transform : c'est le rôle du load ; le transform reste en mémoire, pur.
- Ne pas tester le transform : une transformation fausse produit une analyse fausse sans planter.

## 🏢 Cas métier
Le transform est là où une analyse gagne ou perd sa crédibilité : des données mal nettoyées ou des décisions non documentées produisent des conclusions fausses ou indéfendables. En entreprise, un rapport de qualité (combien de lignes, quelles décisions, quels rejets) est ce qui permet à un décideur de FAIRE CONFIANCE à l'analyse — sans lui, « voici les chiffres » n'est pas défendable. Guider le nettoyage par les questions évite le travail inutile (nettoyer des colonnes qu'on n'utilisera pas) et les oublis (une colonne clé mal préparée). Un transform en fonctions pures testées et accompagné d'un rapport de qualité est exactement le livrable qui distingue un analyste fiable — et c'est directement démontrable et valorisé dans un projet de portfolio.

## 🎤 Question d'entretien
**« Comment transformes-tu des données pour une analyse fiable ? »** → En fonctions PURES testées (une transformation fausse fausse l'analyse silencieusement), GUIDÉES par les questions à répondre : je ne prépare que ce qui sert (une colonne dérivée inutile est du bruit). Je valide d'abord (échec tôt sur données aberrantes), je nettoie ensuite avec chaque décision JUSTIFIÉE — car chaque décision (supprimer, imputer, corriger) introduit un biais — et je dérive les colonnes que les questions exigent. Surtout, je produis un RAPPORT DE QUALITÉ : lignes en entrée/sortie, décisions prises, lignes rejetées et pourquoi. Ce rapport rend l'analyse reproductible et DÉFENDABLE : un décideur sait exactement ce qui a été fait aux données avant les conclusions. Sans lui, « voici les chiffres » n'est pas crédible.
