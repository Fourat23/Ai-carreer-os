### Plan de remédiation (si un critère échoue)
- **Pas de socle marchant / commits géants** : rejoue le jour 113 — construis le chemin le plus fin de bout en bout d'abord, en commits atomiques lisibles (les recruteurs lisent ton historique).
- **CRUD fragile** (UI qui ment, suppression sans confirmation, état muté) : reprends le jour 114 — valider → api → mise à jour immuable → gérer l'échec ; confirmer toute suppression.
- **Liste filtrée stockée en state** : jour 115 — stocke les critères, dérive les résultats ; compose des prédicats indépendants.
- **Tests absents ou mal ciblés** : jour 116 — couvre les parcours critiques (créer/supprimer/rechercher) avec le bon type de test ; vise la confiance, pas 100 %.
- **États non-heureux oubliés** : jour 117 — tableau écran × état, parcours en adversaire, loading/error/empty partout.
- **Projet illisible de l'extérieur** : jour 118 — README (pourquoi + valeur + lancement), schéma 3-tiers, ADR arbitrée, démo ; passe le test du regard neuf.
