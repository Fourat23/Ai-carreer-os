## 🎯 Objectif du jour
Être à l'aise avec les flux (>, >>, |), les droits, la recherche de fichiers, et écrire un premier script Node.js qui lit des arguments.

## 📖 Cours approfondi
**Concepts abordés :** Redirections > et >> · Pipe | · grep, find, wc, head, tail · Variables d'environnement (PATH) · process.argv dans Node · Codes de sortie.

Hier tu as appris à te déplacer. Aujourd'hui : faire COOPÉRER les commandes.

- **Redirection** : `commande > fichier` envoie la sortie dans un fichier (écrase) ; `>>` ajoute à la fin.
- **Pipe** : `commande1 | commande2` branche la sortie de la première sur l'entrée de la seconde. Exemple : `ls | wc -l` compte les fichiers. C'est LA grande idée d'Unix : des petits outils composables — tu retrouveras cette philosophie dans les fonctions pures (jour 26) et les pipelines de données (mois 5).
- **grep** cherche du texte : `grep "erreur" log.txt`. **find** cherche des fichiers : `find . -name "*.js"`.
- **Variables d'environnement** : des valeurs globales lues par les programmes (`echo $PATH`). Le PATH liste les dossiers où le shell cherche les commandes. Tu les utiliseras pour les clés d'API (mois 8) : les secrets vivent dans l'environnement, jamais dans le code.
- Côté Node : `process.argv` contient les arguments de la ligne de commande — c'est comme ça qu'un script devient un OUTIL paramétrable.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : écris `double.js` qui prend un nombre en argument et affiche son double ; sans argument, affiche un mode d'emploi et sort en erreur.

**Raisonnement** : pattern universel *parser → valider → traiter*. Les arguments sont dans `process.argv` (à partir de l'index 2).

**Solution** :
```js
const n = Number(process.argv[2]);
if (Number.isNaN(n)) {
  console.error("Usage : node double.js <nombre>");
  process.exit(1);
}
console.log(n * 2);
```

**Explication** :
- `process.argv[2]` = le premier vrai argument (0 = node, 1 = le script).
- `Number(...)` convertit ; `Number.isNaN` détecte l'échec (« abc » → NaN).
- `process.exit(1)` signale un échec au shell (utile en CI et pour enchaîner des commandes).

**Variante** : accepter PLUSIEURS nombres et tous les doubler — remplace `argv[2]` par `argv.slice(2)` et boucle.

## 🎤 Question d'entretien
**Mise en situation : « Tu veux enregistrer la liste des fichiers d'un dossier dans un fichier `inventaire.txt`, sans ouvrir d'éditeur. Puis tu veux AJOUTER une seconde liste à la suite. Comment fais-tu, et quelle est la différence entre les deux opérations ? »**

*Ce que la question évalue :* la compréhension des flux (redirection, pipe) — pas juste la syntaxe, mais quand chacun s'applique.

**Réponse attendue :** `ls > inventaire.txt` redirige la sortie vers le fichier en l'ÉCRASANT ; `ls >> inventaire.txt` AJOUTE à la fin sans écraser. Un `|` (pipe) est différent : il branche la sortie d'une commande sur l'ENTRÉE d'une autre (ex. `ls | grep .js` pour ne garder que les fichiers .js).

**Débutant / correct / excellent :** débutant = connaît `>` mais pas `>>` ni la différence écrase/ajoute ; correct = distingue `>` et `>>` ; excellent = ajoute le pipe `|` et un exemple (`ls | grep`), et sait qu'un script Node peut lire des arguments avec `process.argv`.

**Relance possible :** « et si tu voulais compter combien de fichiers `.js` il y a ? » → `ls | grep .js | wc -l` (chaîne de pipes).

**À éviter :** confondre `>` (écrase, danger de perte) et `>>` (ajoute) — une erreur qui détruit un fichier ; croire qu'un pipe et une redirection font la même chose.

**Formulation orale naturelle :** « `>` écrit dans un fichier en l'écrasant, `>>` ajoute à la suite, et le pipe `|` enchaîne des commandes en branchant la sortie de l'une sur l'entrée de l'autre. »

## 🧠 À retenir
- `process.argv` transforme un script en outil paramétrable (les arguments commencent à l'index 2).
- Toujours *parser → valider → traiter* : valider AVANT de traiter évite la moitié des bugs.
- Un code de sortie non nul (`process.exit(1)`) signale un échec — indispensable pour la CI plus tard.
