## 🎯 Objectif du jour
Regarder les erreurs individuellement.

## 📖 Cours approfondi
**Modèle mental : une métrique agrégée cache OÙ et POURQUOI le modèle se trompe — regarder les erreurs UNE PAR UNE révèle des PATTERNS (une sous-population systématiquement ratée, un type d'entrée problématique, des étiquettes erronées) qu'aucun chiffre global ne montre, et oriente la prochaine amélioration bien mieux qu'un réglage aveugle.** Après avoir mesuré (métriques) et validé (CV), l'analyse d'erreurs qualitative est ce qui transforme « mon modèle fait 82 % » en « voici ce qui cloche et comment l'améliorer ». C'est du travail de détective, pas de calcul.

La démarche, depuis les fondations :
1. **Sortir les erreurs et les REGARDER** : lister les cas où le modèle s'est trompé (faux positifs et faux négatifs), avec leurs features, la vraie classe et la prédiction. On ne se contente pas du taux d'erreur : on ouvre les exemples.
2. **Chercher des PATTERNS** : les erreurs sont-elles concentrées sur une sous-population (une région, une tranche d'âge, une catégorie) ? Sur un type d'entrée (valeurs extrêmes, données manquantes) ? Un pattern révèle une faiblesse SYSTÉMATIQUE, pas du hasard.
3. **Distinguer les causes** :
   - **Modèle** : il manque un signal, une feature, de la complexité pour ce cas.
   - **Données** : étiquettes erronées (le modèle a « raison », le label est faux), features manquantes, biais d'échantillonnage (jour 152).
   - **Problème intrinsèquement dur** : des cas ambigus qu'aucun modèle ne trancherait.
4. **Orienter l'action** : chaque pattern suggère une amélioration CIBLÉE — créer une feature pour la sous-population ratée (jour 169), corriger des étiquettes, collecter plus de données sur un segment, ou accepter une limite. C'est bien plus efficace que régler des hyperparamètres à l'aveugle en espérant que le score monte.

Pourquoi c'est décisif : une métrique globale est une moyenne qui NOIE l'information. Deux modèles à 82 % peuvent se tromper sur des cas complètement différents — l'un sur les nouveaux clients, l'autre sur les gros comptes. Seule l'analyse qualitative dit LESQUELS, donc lequel choisir selon l'enjeu métier, et QUOI améliorer. C'est aussi là qu'on attrape les problèmes de DONNÉES (étiquettes fausses, leakage résiduel) invisibles dans les chiffres.

La règle du jour : **regarde tes erreurs une par une pour trouver des patterns (sous-population, type d'entrée, étiquettes fausses) ; une métrique agrégée cache où et pourquoi le modèle échoue, et l'analyse qualitative oriente l'amélioration bien mieux qu'un réglage aveugle. C'est du travail de détective, pas de calcul**.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : analyser 10 erreurs de ton modèle une par une et identifier des patterns.

**Exemple simple** : un pattern révélé — sur 10 faux négatifs, 7 concernent des clients de moins de 3 mois d'ancienneté. Ce n'est pas du hasard : le modèle rate SYSTÉMATIQUEMENT les nouveaux clients, sans doute par manque de features sur eux. Un chiffre global ne l'aurait jamais montré.

**Raisonnement pas-à-pas** : extraire les erreurs avec leur contexte → les regarder une par une → chercher un pattern (segment, type d'entrée) → remonter à la cause (modèle/données/problème dur) → proposer une action ciblée.

**Implémentation** :
```python
import pandas as pd
proba = clf.predict_proba(X_te)[:, 1]
preds = (proba >= 0.5).astype(int)

# Rassembler les erreurs avec leur contexte
df_err = X_te.copy()
df_err["vrai"], df_err["prédit"], df_err["proba"] = y_te, preds, proba
erreurs = df_err[df_err["vrai"] != df_err["prédit"]]

# Chercher un pattern : les erreurs se concentrent-elles sur un segment ?
print(erreurs["anciennete_mois"].describe())         # ex. surtout des faibles anciennetés ?
print(erreurs.groupby("segment").size())              # concentrées sur un segment ?

# Regarder les 10 erreurs les plus confiantes (proba loin de 0,5) : le modèle est sûr et se trompe
print(erreurs.reindex((erreurs["proba"] - 0.5).abs().sort_values(ascending=False).index).head(10))
```

**Mini-quiz** : (a) Pourquoi une métrique globale ne suffit-elle pas ? (b) Que peut révéler un pattern d'erreurs ? (c) Que faire d'une erreur où le modèle est très confiant et se trompe ?
→ (a) c'est une moyenne qui noie l'information ; deux modèles à 82 % peuvent se tromper sur des cas très différents ; (b) une faiblesse systématique (sous-population ratée, type d'entrée problématique) ou un problème de données (étiquettes fausses) ; (c) l'examiner de près : soit une étiquette erronée (le modèle a raison), soit un cas où il manque un signal — les deux orientent une action ciblée.

**Variante** : vérifie si certaines « erreurs » sont en fait des ÉTIQUETTES fausses dans les données. Corriger des labels erronés peut améliorer le modèle plus qu'un réglage d'hyperparamètres — l'analyse qualitative attrape ce que les chiffres cachent.

## 🏢 Cas métier
L'analyse d'erreurs qualitative est ce qui débloque les vraies améliorations en ML appliqué : plutôt que de régler des hyperparamètres à l'aveugle (gains marginaux), regarder les erreurs révèle qu'un modèle rate systématiquement un segment, ou que 20 % des « erreurs » sont des étiquettes fausses. Les équipes ML matures consacrent un temps important à cette analyse (Andrew Ng en a fait un pilier du ML appliqué), car elle oriente l'effort là où il paie : une feature ciblée, des données supplémentaires sur un segment, une correction de labels. En entretien, « comment améliorerais-tu ce modèle ? » attend précisément cette démarche (regarder les erreurs, trouver des patterns, agir ciblé), pas « j'augmenterais n_estimators ». C'est un marqueur de maturité de praticien.

## 🎤 Question d'entretien
**« Ton modèle fait 82 %. Comment décides-tu quoi améliorer ? »** → Je ne règle pas des hyperparamètres à l'aveugle : je fais une analyse d'erreurs QUALITATIVE. Je sors les cas où le modèle se trompe (faux positifs et négatifs) avec leur contexte, et je les REGARDE un par un pour chercher des PATTERNS : les erreurs se concentrent-elles sur une sous-population (nouveaux clients, une région), un type d'entrée (valeurs extrêmes, manquants) ? Un pattern révèle une faiblesse systématique. Je remonte à la cause : modèle (manque un signal/une feature), données (étiquettes fausses — parfois le modèle a raison et le label est faux —, biais), ou problème intrinsèquement dur. Chaque pattern suggère une action CIBLÉE (créer une feature, corriger des labels, collecter des données sur un segment). Une métrique globale est une moyenne qui noie l'information ; l'analyse qualitative dit OÙ et POURQUOI ça échoue, ce qui oriente l'effort bien mieux qu'un réglage aveugle.
