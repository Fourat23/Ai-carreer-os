### Plan de remédiation (si un critère échoue)
- **Projet parti des données sans questions** : rejoue le jour 141 — 3 questions précises qui dictent extract/transform/dashboard ; une question vague ne guide rien.
- **Extraction fragile** : jour 142 — gère indisponibilité, rate limit (backoff sur transitoire), contrôle de forme tôt, staging ; conçois pour l'échec.
- **Transform non tracé** : jour 143 — fonctions pures testées, nettoyage justifié guidé par les questions, rapport de qualité qui rend l'analyse défendable.
- **Load non rejouable** : jour 144 — schéma pensé, transactionnel, idempotent, un point d'entrée unique ; deux exécutions = base identique.
- **Dashboard fourre-tout** : jour 145 — une question par visualisation, forme adaptée (évolution→ligne, comparaison→barres), axes honnêtes ; supprime le bruit.
- **Projet illisible de l'extérieur** : jour 146 — README orienté questions + rapport qualité + ADR (SQLite/Postgres) + démo de reproductibilité ; passe le test du regard neuf.
