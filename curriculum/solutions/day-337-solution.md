# Correction — Jour 337 : README DocSense exemplaire

[← Retour au jour 337](../days/day-337.md)

> ⛔ **Ne lis cette correction qu'après avoir vraiment tenté seul.** Une correction n'est pas une réponse à copier : c'est un outil pour comprendre ta démarche.

## 🧠 La logique attendue
Solution simple : documenter comment lancer le projet. Solution améliorée : un README qui VEND — problème et valeur d'abord (pas la stack), démo GIF, chiffres du rapport qualité, installation en 5 minutes (docker), architecture avec lien ADR, limites honnêtes. Écrit pour un recruteur pressé (90 secondes), testé avec un regard neuf. Le README est l'interface entre le travail et le marché — un excellent projet avec un README illisible est invisible.

## ⚠️ Erreurs probables et points à vérifier
- Commencer par la stack technique : le recruteur ne sait pas POURQUOI le projet existe — commencer par le problème et la valeur.
- Pas de démo visuelle : un GIF montre instantanément que ça marche — le texte seul ne capte pas.
- Pas de chiffres : sans les résultats d'évaluation, le lecteur ne peut pas juger la qualité — les inclure.
- Pas de limites : un README qui ne montre que du positif est suspect — l'honnêteté crédibilise.

## 🔍 Comment vérifier ta solution
- Le README commence par le problème et la valeur (pas la stack).
- Il contient une démo visuelle (GIF).
- Les chiffres d'évaluation (rapport qualité) sont présents.
- L'installation en 5 minutes (docker) est documentée.
- Les limites honnêtes sont assumées.
- Le test du regard neuf (90 secondes) est passé (variante).

## 🎤 À savoir expliquer à l'oral
Explique le README comme interface avec le marché : « un recruteur lit mon README en premier, pas mon code, et décide en 90 secondes ; donc je commence par le problème et la valeur, je montre un GIF, je prouve par les chiffres, et je permets de lancer en 5 minutes ». Un excellent projet avec un README illisible est invisible — savoir rendre son travail VISIBLE est une compétence aussi importante que le code.
