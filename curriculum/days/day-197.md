## 🎯 Objectif du jour
Comprendre ce qu'un LLM prédit.

## 📖 Cours approfondi
**Modèle mental : un LLM est une machine à continuer du texte.** Il ne « répond » pas, il ne « sait » pas : il calcule, token par token, la suite la plus plausible du texte qu'on lui donne. Tout le reste — le ton d'assistant, la politesse, l'apparence de raisonnement — émerge de cette unique opération, répétée.

Trois conséquences structurent TOUT le métier :

1. **La fenêtre de contexte est la seule mémoire.** Le modèle ne voit que ce qui est dans le contexte de CET appel : system prompt + historique + ta question. Rien d'autre. Pas de mémoire entre les appels, pas d'accès à « ses données d'entraînement » comme à une base de données. Ce qui n'est pas dans le contexte n'existe pas pour lui.
2. **Le system prompt est du texte comme un autre**, mais placé en position d'autorité : il conditionne toutes les continuations qui suivent. C'est ta poignée de contrôle principale.
3. **La plausibilité n'est pas la vérité.** Le modèle optimise « qu'est-ce qui SUIT bien ce texte », pas « qu'est-ce qui est VRAI ». Quand la suite plausible et la suite vraie divergent, il choisit la plausible : c'est le mécanisme de l'hallucination (jour 201), pas un bug.

Tu as construit l'intuition interne au mois 7 (tokens, embeddings, attention). Aujourd'hui tu bascules du côté UTILISATEUR-ingénieur : que voit le modèle, que peut-il faire, qu'est-ce qui est structurellement hors de portée.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : rédiger la note « ce qu'un LLM voit vraiment » à partir de 3 expériences.

**Raisonnement** : chaque affirmation de ta note doit être PROUVÉE par une manipulation, pas recopiée d'un article.

**Protocole** :
```
1. Mémoire : pose une question, ouvre une NOUVELLE conversation, fais-y référence
   (« comme je te l'ai dit... ») → le modèle invente ou avoue. Conclusion : la
   mémoire, c'est le contexte, rien d'autre.
2. Contexte : donne un texte de 2 pages, pose une question sur la ligne 3.
   Puis pose la MÊME question sans le texte → réponse générique ou inventée.
   Conclusion : il répond depuis le contexte quand il l'a, depuis la
   plausibilité statistique sinon.
3. Continuation : donne un début de phrase absurde mais grammaticalement
   engageant (« La capitale de la France depuis 2023 est ») → observe la force
   de la continuation plausible.
```

**Explication** : ces trois expériences fondent les trois règles d'ingénierie : tout mettre dans le contexte, contrôler le contexte, ne jamais confondre plausible et vrai. **Variante** : mesure la limite — combien de texte peux-tu mettre avant que le modèle « perde » le début ?

## 🏢 Cas métier
Un product manager demande : « pourquoi le chatbot ne se souvient pas des préférences du client ? » Ta réponse d'ingénieur : le modèle n'a AUCUNE mémoire — si on veut qu'il se souvienne, c'est NOTRE code qui doit stocker les préférences et les réinjecter dans le contexte à chaque appel. Cette phrase, dite clairement en réunion, est exactement ce qu'on attend d'un dev IA.

## 🎤 Question d'entretien
**« Explique ce que fait réellement un LLM quand il répond. »** → Il prédit le token suivant le plus plausible, en boucle, conditionné par tout le contexte (system prompt + historique + question). Il n'a ni mémoire entre les appels, ni accès à des faits : ce qui n'est pas dans le contexte n'existe pas pour lui, et la plausibilité n'implique pas la vérité.

## 🚀 Pourquoi ça comptera plus tard
- **Bankable** : « la mémoire d'un LLM, c'est le contexte » est LA phrase qui distingue en entretien ceux qui ont compris de ceux qui ont joué avec ChatGPT.
- Tout le RAG (mois 9) découle de la règle n°1 : mettre la bonne information dans le contexte au bon moment.
- Les décisions d'architecture LLM (quoi stocker, quoi injecter, quoi tronquer) se raisonnent entièrement avec ce modèle mental.
