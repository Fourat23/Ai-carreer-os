## 🎯 Attendu de la semaine
Thème : **React : composants, props, state, événements**. Première semaine de React. Le modèle mental à acquérir : l'UI est une fonction de l'état.

## ✅ Grille d'évaluation (note chaque axe de 0 à 5)
- **Test pratique réussi** dans le temps imparti : 75 min : app Vite+React+TS — un compteur avancé (pas, min/max, reset), une liste de courses (ajout, suppression, case cochée), le tout typé proprement.
- **Test théorique** (réponds de mémoire puis auto-corrige) : Qu'est-ce qu'un composant ; props vs state ; pourquoi ne JAMAIS muter le state ; que déclenche setState ; qu'est-ce que le rendu conditionnel ; pourquoi une `key` sur les listes ?
- **Mini-projet / livrable** conforme : 'Kanban minimal' : 3 colonnes (à faire/en cours/fait), déplacer des cartes via boutons, état en mémoire.
- **Exercice d'architecture** fait sérieusement : Pour le Kanban : dessine l'arbre des composants et décide OÙ vit l'état (dans quelle branche). Explique pourquoi le remonter trop haut ou trop bas pose problème.

## 📋 Checklist de validation
- [ ] Je pense en composants (je découpe les maquettes)
- [ ] State minimal (je ne stocke pas ce qui se calcule)
- [ ] Aucune mutation directe
- [ ] Props typées

## 🚦 Critères de passage à la semaine suivante
- [ ] Les 2 apps du test fonctionnent
- [ ] Kanban : déplacements corrects et state immuable
- [ ] Auto-éval React ≥ 2.5

## ⚠️ Erreurs fréquentes en revue
- Se sur-noter (familiarité ≠ maîtrise) : ne compte que ce que tu produis SEUL et sais EXPLIQUER.
- Bâcler le test théorique en le relisant au lieu de répondre de mémoire (rappel actif).
- Avancer malgré des critères non atteints : mieux vaut consolider 2-3 jours que bâtir sur du sable.
- Oublier de mettre à jour ses scores de compétences dans l'application.
