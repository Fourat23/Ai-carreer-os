## 📖 Cours approfondi
**Modèle mental : un projet ML non reproductible n'existe pas.** Si un tiers ne peut pas relancer ton pipeline et obtenir les MÊMES chiffres, tes résultats sont des anecdotes. La reproductibilité tient à quatre verrous : les données figées (ou leur téléchargement scripté), les seeds fixées partout, l'environnement déclaré (requirements.txt), et UNE commande d'entrée (`python run.py`). Le README raconte ensuite l'histoire : question métier → méthode → chiffres → limites. C'est la dernière ligne droite qui transforme ChurnScope de « notebook qui a marché une fois » en pièce de portfolio.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : verrouiller la reproductibilité de ChurnScope.

**Raisonnement** : chaque source de hasard ou d'implicite doit être fixée ou déclarée.

**Checklist exécutable** :
```
1. random_state=42 partout (split, modèles, CV) → 2 runs = mêmes scores ?
2. pip freeze > requirements.txt ; venv documenté.
3. run.py enchaîne : données → features → entraînement → éval → rapport.
4. Clone frais dans /tmp : suivre le README à la lettre. Chaque écart = bug de doc.
```

**Explication** : le test du clone frais est le seul juge honnête. **Variante** : demande à quelqu'un d'autre de le faire (ou refais-le demain, de mémoire).

## ⚠️ Erreurs fréquentes
- Seed fixée au split mais pas au modèle (RandomForest a son propre hasard).
- Données « déjà là » sur TA machine mais non téléchargeables par le lecteur.
- README écrit de mémoire sans re-suivre les étapes sur un clone frais.

## 🏢 Cas métier
En entreprise, un modèle part en revue avant mise en production : si le reviewer ne peut pas reproduire tes métriques, la revue s'arrête là. La reproductibilité n'est pas du confort, c'est la condition d'entrée.

## 🎤 Question d'entretien
**« Je clone ton projet ML : comment je vérifie tes chiffres ? »** → Une commande (`python run.py`), seeds fixées, données scriptées, mêmes scores affichés que dans le README — et si un écart apparaît, c'est un bug que je veux connaître.

## 🚀 Pourquoi ça comptera plus tard
- **Bankable** : 90 % des portfolios ML sont des notebooks non rejouables — le tien se relance en une commande, chiffres identiques.
- L'évaluation RAG (mois 9) exigera la même discipline : scores versionnés et reproductibles.
- En entretien, « teste-le toi-même » est l'argument qui clôt le scepticisme.

## 🧩 Questions de réflexion (à faire seul)
- Un tiers clone ton projet et obtient des chiffres légèrement différents des tiens : quelles sources de hasard non fixées (seed du split, du modèle) l'expliquent le plus souvent ?
- Ton pipeline tourne « chez toi » mais pas ailleurs : quels implicites (chemins, versions de librairies, données non téléchargeables) dois-tu rendre explicites pour qu'une seule commande suffise ?
- Pourquoi la reproductibilité est-elle la condition d'ENTRÉE d'une revue de modèle en entreprise, et que se passe-t-il si le relecteur ne peut pas rejouer tes métriques ?
