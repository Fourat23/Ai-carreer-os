## 🎯 Objectif du jour
Cadrer le projet RAG évalué.

## 📖 Cours approfondi
**Modèle mental : un projet évalué commence par définir ce que « réussi » veut dire — sinon il ne finit jamais.** DocQA v0 était une exploration ; le Projet 6 est un LIVRABLE : un système de questions-réponses documentaire dont la qualité sera MESURÉE. Et la différence entre les deux se joue aujourd'hui, dans le cadrage, avant toute ligne de code.

Les trois piliers du cadrage :
1. **Le corpus, figé.** Un périmètre documentaire précis (quels documents, quelle version, gelés pour la durée du projet). Un corpus qui bouge pendant l'évaluation rend toute mesure incomparable — c'est le random_state=42 du RAG (jour 181, même discipline).
2. **La taxonomie de questions.** Tu sais depuis les jours 225-226 que toutes les questions ne se valent pas : factuelle simple, synthèse multi-passages, reformulée, hors corpus, ambiguë. Le projet DÉCLARE quels types il promet de bien traiter (factuelle, reformulée), lesquels il traite en mode dégradé (synthèse), lesquels il refuse par conception (hors corpus → refus explicite). Cette déclaration de périmètre est ce qui rend l'évaluation JUSTE : on note le système sur ses promesses, pas sur des espoirs.
3. **Le plan d'évaluation, écrit AVANT d'améliorer.** Le golden set (démarré au jour 237, exploité au mois 9) : combien de questions par type, comment les verdicts sont rendus (les 3 colonnes de ta grille du jour 225), quels seuils feraient dire « v1 est meilleur que v0 ». Décider des critères APRÈS avoir vu les résultats est le péché capital de l'évaluation — tu le sais depuis le banc d'essai LLM (jour 202).

La maquette du livrable final complète le cadrage : à quoi ressemble une réponse (texte + citations + confiance), qu'est-ce qu'un utilisateur voit quand le système refuse, quelles limites sont documentées. Un jour de cadrage économise deux semaines d'errance — c'est vrai en entreprise, c'est vrai ici.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : le document de cadrage du Projet 6 (2 pages max).

**Raisonnement** : chaque section du cadrage répond à une question qu'un évaluateur (ou un futur toi) posera — corpus ? promesses ? mesure ? limites ?

**Gabarit** :
```
# Projet 6 — DocQA évalué : cadrage
1. Corpus : [liste des documents, version, taille en chunks estimée]
   Figé le : [date]. Toute modification = nouvelle version d'index (j.223).
2. Périmètre par type de question :
   | Type          | Promesse                  | Exemple concret        |
   | factuelle     | réponse exacte + citation | « quel délai pour X ? »|
   | reformulée    | robuste aux synonymes     | [exemple]              |
   | synthèse      | best effort, multi-cité   | [exemple]              |
   | hors corpus   | refus explicite           | [exemple]              |
   | ambiguë       | demande de précision OU   | [exemple]              |
   |               | réponse la plus probable  |                        |
3. Plan d'évaluation :
   - golden set : 30 questions (12 factuelles, 6 reformulées, 6 synthèse,
     3 hors corpus, 3 ambiguës), réponses attendues écrites À LA CRÉATION
   - verdicts : réponse OK / citations OK / bon chunk dans top-k (grille j.225)
   - baseline : score v0 mesuré AVANT toute amélioration
   - objectif v1 : [seuils par type, ex. factuelles ≥ 10/12]
4. Maquette de réponse : [réponse type avec citations + comportement de refus]
5. Hors périmètre assumé : tableaux complexes, calculs, questions temps réel.
```

**Explication** : la ligne « baseline mesurée AVANT toute amélioration » est le garde-fou méthodologique central — sans point de départ chiffré, « v1 est meilleur » restera une impression. **Variante** : écris dès aujourd'hui 5 des 30 questions du golden set (une par type) avec leur réponse attendue — tu valideras que le format des verdicts tient la route avant d'en écrire 30.

## ⚠️ Erreurs fréquentes
- Cadrer « toutes les questions » : sans taxonomie, l'évaluation mélangera des choses incomparables et le score global ne voudra rien dire.
- Écrire les questions du golden set d'après ce que le système sait DÉJÀ faire : elles doivent venir du besoin utilisateur, pas des capacités actuelles.
- Sauter la baseline v0 : améliorer sans point de départ chiffré = naviguer sans position.
- Un cadrage de 10 pages : 2 pages max — un cadrage qu'on ne relit pas est un cadrage mort.

## 🏢 Cas métier
Différence entre un POC et un produit en entreprise : le POC « répond aux questions », le produit « répond aux questions factuelles avec 90 % d'exactitude mesurée sur un jeu de référence, et refuse proprement le reste ». Le second se vend à un comité, se maintient, se compare. Les chefs de projet IA passent leur vie à transformer des POC en produits — arriver avec le réflexe de cadrage déjà installé te rend immédiatement utile.

## 🎤 Question d'entretien
**« On te confie un projet d'assistant documentaire : par quoi commences-tu ? »** → Par le cadrage : figer le corpus (versionné), déclarer le périmètre par TYPE de question (ce qu'on promet, ce qu'on refuse par conception), et écrire le plan d'évaluation AVANT d'améliorer — golden set par type, verdicts définis, baseline mesurée. Le système sera jugé sur ses promesses explicites, pas sur des attentes implicites. Un jour de cadrage économise des semaines d'errance.
