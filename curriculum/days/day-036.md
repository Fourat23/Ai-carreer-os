## 🎯 Objectif du jour
Installer TS, comprendre pourquoi typer, annoter les types de base, lire les erreurs du compilateur comme des alliées.

## 📖 Cours approfondi
**Concepts abordés :** tsc / tsconfig · Types primitifs · Inférence · any (à fuir) vs unknown · strict mode.

TypeScript ajoute un vérificateur de types AU-DESSUS de JavaScript : le code s'exécute pareil, mais un compilateur (tsc) relit tout avant et signale les incohérences (appeler une fonction avec le mauvais type, accéder à une propriété qui n'existe pas, oublier un cas null).

Le typage est une DOCUMENTATION VÉRIFIÉE : la signature `function payer(montant: number): Recu` dit le contrat, et le compilateur garantit qu'il est respecté partout, pour toujours. En mode strict, les null/undefined implicites deviennent des erreurs : la moitié des bugs du mois 1 auraient été attrapés à la compilation.

`any` désactive la vérification (à bannir) ; `unknown` dit « je ne sais pas encore » et FORCE une validation avant usage — c'est la bonne réponse aux données externes.

## ⚠️ Erreurs fréquentes
- `any` pour faire taire le compilateur = désactiver l'outil. Utilise `unknown` + validation.
- Croire que tsc exécute : il VÉRIFIE, node exécute après compilation (ou tsx).
