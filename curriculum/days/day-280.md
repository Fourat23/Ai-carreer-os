### Bilan
Les agents démystifiés : une boucle while + function calling + un budget. Tu la codes toi-même pour ne plus jamais subir le mot 'agent'.

### Test pratique
90 min : code un agent maison (SANS framework) — boucle plan/act/observe avec 3 outils (recherche dans tes docs, calcul, lecture de fichier), budget de 10 itérations, trace complète de chaque étape affichée, arrêt propre (réussite, échec, budget épuisé).

### Test théorique
Différence agent vs workflow (définition opérationnelle) ; pourquoi limiter les itérations ; que mettre dans l'observation renvoyée au modèle ; 3 modes d'échec classiques d'un agent (boucle, dérive d'objectif, outil mal utilisé) ?

### Mini-projet / livrable
Ton agent appliqué à un cas utile : 'vérificateur de cohérence de documentation' (il lit tes docs et signale les contradictions), avec ses traces.

### Synthèse de la semaine
La semaine 40 a posé les fondations des agents, à nu et avec jugement : la boucle plan/act/observe avec ses garde-fous — budget, arrêt propre, traces (jour 274), le catalogue des trois modes d'échec provoqués et bornés — boucle, dérive d'objectif, mauvais usage d'outil (275), un cas d'usage réel et vérifiable — vérificateur de cohérence documentaire (276), la gestion de la mémoire et du contexte par état structuré et résumé (277), les critères de décision script/workflow/agent avec le courage de ne PAS faire d'agent (278), et la doctrine ancrée dans la pratique (279). ### Plan de remédiation (si un critère échoue)
- **Boucle sans garde-fous** : un agent sans budget/traces/arrêt propre n'est pas déployable. Rejoue le jour 274 — la boucle fait 30 lignes, les garde-fous sont non négociables.
- **Modes d'échec non provoqués** : les nommer sans les avoir VUS ne les rend pas diagnosticables. Reprends le jour 275 : provoque chaque mode, lis les traces, teste une parade. Sans cette pratique, tu ne débuggeras pas un agent réel.
- **Décision agent/workflow floue** : c'est LE jugement du mois. Refais le jour 278 sur 5 tâches, applique les critères dans l'ordre, et force-toi à ré-exprimer une tâche « agent » en workflow. « Quand NE PAS faire d'agent » est la compétence différenciante.
- **Gestion du contexte absente** : un agent qui laisse l'historique brut grossir devient cher et confus. Reprends le jour 277 : état structuré, résumé, persistance, et MESURE le trade-off (avec/sans résumé).

### Questions d'entretien de la semaine
1. **« Qu'est-ce qu'un agent, concrètement ? »** Attendu : une boucle plan/act/observe où le MODÈLE décide de la prochaine action, avec garde-fous obligatoires (budget, arrêt propre, traces) ; le code exécute, le modèle propose.
2. **« Quels sont les modes d'échec d'un agent et comment les gères-tu ? »** Attendu : boucle / dérive d'objectif / mauvais usage d'outil ; causes identifiées ; parades (détection de répétition, réinjection d'objectif, descriptions durcies) ; détecter et limiter, pas éliminer.
3. **« Quand fais-tu un agent, et quand n'en fais-tu PAS ? »** Attendu : niveau le plus simple d'abord (script → workflow → agent), agent réservé aux flux imprévisibles ; justification coût/fiabilité/reproductibilité ; le courage de refuser l'autonomie.
4. **« Comment gères-tu la mémoire d'un agent ? »** Attendu : le modèle n'a rien, le code gère le contexte ; état structuré compact + résumé au débordement + persistance ; trade-off coût/complétude/fiabilité.
