## 🎯 Objectif du jour
Mesurer chaque étage.

## 📖 Cours approfondi
**Modèle mental : l'ablation attribue le mérite — chaque étage doit payer sa place avec des chiffres.** Ton pipeline a maintenant quatre configurations empilables : vectoriel seul, lexical seul, hybride RRF, hybride + reranking. L'ablation les mesure TOUTES sur le même golden set et répond à la seule question qui compte : **qu'est-ce que chaque étage apporte, et pour quel prix ?** Sans elle, ton pipeline est un empilement de bonnes idées ; avec elle, c'est une architecture justifiée ligne à ligne.

La discipline du tableau d'ablation :
1. **Tout constant sauf la configuration** : même golden set (le set étendu v1.1, désormais ta référence), même k final, mêmes seuils. Les mesures des jours 246-248 se recyclent — l'ablation COMPILE plus qu'elle ne re-mesure.
2. **Trois familles de colonnes** : qualité (top-3 global ET par type), latence (p50 par configuration), coût par question. Un étage se juge sur les trois — le reranking gagne en qualité et perd en latence : c'est le tableau qui montre l'arbitrage, pas une opinion.
3. **La lecture marginale** : chaque ligne se compare à la PRÉCÉDENTE (le gain marginal de l'étage), pas au début. +3 pour l'hybride puis +2 pour le reranking racontent deux investissements distincts, avec deux prix distincts.
4. **L'honnêteté des cas dégradés** : un étage peut faire PERDRE des questions même quand il gagne en global (l'hybride peut diluer un top-1 vectoriel parfait). La colonne « questions perdues » par étage est la partie la plus instructive du tableau — et la plus rare dans les portfolios.

Le produit final dépasse le RAG : savoir monter un tableau d'ablation est LA compétence d'évaluation de systèmes composites (pipelines ML, features produit, optimisations perf). C'est aussi, très directement, le format de réponse attendu à la question d'entretien « comment sais-tu que chaque partie de ton système sert à quelque chose ? ».

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : le tableau d'ablation complet, avec lecture marginale et questions perdues.

**Raisonnement** : compiler les mesures existantes, compléter les manquantes, lire les marges — puis décider de la configuration PAR DÉFAUT.

**Le tableau (livrable central)** :
```
Configuration        top-3   fact.  reform.  ident.  synth. | p50     €/q     perdu
vectoriel seul       19/26   11/12   5/6     1/4     2/4    | 380ms  0,0038   —
lexical seul         15/26    9/12   2/6     4/4     0/4    | 95ms   0,0009   —
hybride RRF          22/26   11/12   5/6     4/4     2/4    | 410ms  0,0041   -1 (q.14)
hybride + rerank     24/26   12/12   6/6     4/4     2/4    | 1310ms 0,0081   0

Lecture marginale :
  hybride vs vectoriel : +3 (les identifiants), prix +30 ms — ÉVIDENT
  rerank vs hybride    : +2, prix +900 ms et ×2 en coût — DÉPEND DU PRODUIT
  q.14 perdue par l'hybride, récupérée par le rerank : documentée
  synthèses : 2/4 PARTOUT → confirmation du jour 244 : le retrieval n'est
  pas le coupable — transmis au diagnostic génération (mois d'éval)
```

**La décision de configuration** :
```
Défaut : hybride + rerank (la qualité prime pour DocQA, usage interactif toléré
à ~1,3 s). Mode dégradé : hybride seul si budget latence < 500 ms (jour 250).
Les DEUX configs restent dans configs/ — le choix est un paramètre, pas un fork.
```

**Explication** : la ligne des synthèses inchangées à travers TOUTES les configurations est une découverte méthodologique majeure — quatre expériences concordantes valent une preuve : le problème est ailleurs. **Variante** : ajoute la ligne « hybride + rerank à k_moteur=50 » — le rappel élargi gagne-t-il encore, ou le filet de 20 suffisait-il ? (Réponse habituelle : plateau — et tu l'auras MESURÉ.)

## 🏢 Cas métier
Dans les publications et les blogs d'ingénierie RAG sérieux, le tableau d'ablation est la pièce qui sépare l'article crédible du storytelling — même norme en entretien. Un candidat qui dit « le reranking améliore le retrieval » récite ; celui qui dit « +2 questions sur 26, pour +900 ms et ×2 le coût — justifié pour mon usage interactif, pas pour une API à fort volume » démontre. Le tableau d'ablation est littéralement la différence entre les deux phrases.

## 🎤 Question d'entretien
**« Comment sais-tu que chaque étage de ton pipeline sert à quelque chose ? »** → Par ablation : toutes les configurations (vectoriel, lexical, hybride, +rerank) mesurées sur le même golden set, en qualité PAR TYPE, latence et coût. Lecture marginale : chaque étage se compare au précédent — l'hybride apporte +3 pour +30 ms (évident), le rerank +2 pour +900 ms (arbitrage produit). Et la colonne « questions perdues » par étage : un gain global peut cacher des régressions locales. Bonus : ce que le tableau montre d'INCHANGÉ partout localise les problèmes hors retrieval.
