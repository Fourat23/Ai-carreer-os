## 🎯 Objectif du jour
Valider le juge.

## 📖 Cours approfondi
**Modèle mental : ton harnais mesure ton RAG — mais qui mesure ton harnais ? Un évaluateur non validé peut être plus faux que le système qu'il juge.** C'est le jour méta : tu retournes l'évaluation vers l'ÉVALUATEUR lui-même. Un LLM-as-judge qui se trompe systématiquement te fait optimiser vers ses erreurs — tu crois améliorer le système, tu l'ajustes en réalité aux biais du juge. Valider le juge n'est pas un raffinement académique : c'est ce qui rend TOUTES tes autres mesures dignes de confiance.

La méthode de validation d'un juge (un mini-projet d'évaluation en soi) :
1. **Un jeu de jugements HUMAINS de référence** : tu juges toi-même 15-20 réponses variées (dont des cas limites : fidèle-mais-inexact, pertinent-mais-infidèle, réponses longues, réponses courtes). Ces jugements humains sont la vérité-terrain DU JUGE.
2. **La mesure d'accord** : fais juger le LLM les mêmes cas, compare. Le taux d'accord brut ne suffit pas — si 90 % des réponses sont « fidèles », un juge qui dit toujours « fidèle » a 90 % d'accord sans rien évaluer. Il faut une métrique qui corrige le hasard : **Cohen's kappa** (κ). κ > 0,6 = accord substantiel, > 0,8 = quasi-parfait ; κ proche de 0 = le juge ne fait pas mieux que le hasard, même avec un « bon » taux brut.
3. **L'analyse des DÉSACCORDS** : chaque cas où juge ≠ humain est une donnée en or. Le juge est-il trop sévère ? trop laxiste ? aveugle à un type de cas (les réponses courtes, les nuances) ? Les désaccords SYSTÉMATIQUES révèlent un biais à corriger (dans le prompt du juge) ; les désaccords aléatoires révèlent une échelle mal ancrée.
4. **Le protocole ÉCRIT et rejouable** : combien de cas, qui juge, quelle métrique, quel seuil d'acceptation — pour pouvoir REVALIDER le juge quand le modèle sous-jacent change (dérive, jour 209) ou quand tu modifies son prompt. Un juge validé une fois n'est pas validé pour toujours.

La leçon de fond : l'évaluation est RÉCURSIVE — on évalue le système avec un juge, on évalue le juge avec l'humain, et on assume que l'humain lui-même a une variance (deux humains peuvent diverger : c'est le plafond de ce qu'on peut attendre du juge). Savoir où s'arrête la chaîne de validation, et l'assumer, est une marque de maturité.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : valider ton juge de fidélité contre l'humain, avec kappa et analyse des désaccords.

**Raisonnement** : constituer la référence humaine, mesurer l'accord corrigé du hasard, disséquer les désaccords, écrire le protocole.

**La validation** :
```python
def valider_juge(cas_humains: list) -> dict:
    # cas_humains = [{question, reponse, extraits, verdict_humain}, ...] 15-20 cas
    verdicts_llm = [juger_fidelite(c["question"], c["reponse"], c["extraits"]).verdict
                    for c in cas_humains]
    verdicts_hum = [c["verdict_humain"] for c in cas_humains]
    return {
        "accord_brut": accord_brut(verdicts_hum, verdicts_llm),
        "kappa": cohen_kappa(verdicts_hum, verdicts_llm),   # corrige le hasard !
        "desaccords": [(c, l) for c, h, l in zip(cas_humains, verdicts_hum, verdicts_llm)
                       if h != l],
    }
```

**L'analyse (le vrai travail)** :
```
Résultat type : accord brut 0,80 · kappa 0,58 (juste sous « substantiel »)
Désaccords (4/20) — chercher le PATTERN :
  - 3 cas : juge dit "fidele", humain dit "partiel" sur des réponses LONGUES
    -> BIAIS DE LONGUEUR confirmé : le juge se laisse impressionner par le volume
  - 1 cas : désaccord sur une nuance ambiguë -> variance humaine acceptable
Action : durcir le prompt du juge (« une SEULE affirmation non soutenue = partiel,
  quelle que soit la longueur »), re-valider -> kappa 0,71.
```

**Explication** : le kappa à 0,58 avec un accord brut de 0,80 est LA leçon — l'accord brut flatteur cachait un juge à peine meilleur que le hasard sur les cas discriminants ; seul le kappa l'a révélé. **Variante** : fais juger 3 des cas par une deuxième personne — mesure l'accord HUMAIN-humain : c'est le plafond que ton juge peut atteindre (si deux humains sont à κ=0,75, exiger κ=0,9 du juge est absurde).

## ⚠️ Erreurs fréquentes
- Se fier à l'accord brut : sur des classes déséquilibrées (90 % « fidèle »), un juge trivial obtient 90 % sans rien mesurer — kappa obligatoire.
- Analyser les désaccords cas par cas sans chercher le PATTERN : 3 désaccords sur des réponses longues = un biais systématique corrigeable, pas 3 anomalies.
- Exiger du juge un accord parfait : deux humains divergent aussi — l'accord humain-humain est le plafond réaliste.
- Valider une fois et oublier : le modèle du juge dérive, son prompt évolue — la revalidation est déclenchée par tout changement (jour 209).

## 🏢 Cas métier
Une équipe optimise son RAG pendant un mois vers son LLM-judge, gagne 15 points de « fidélité »… mesurés par un juge biaisé vers les réponses longues. Résultat réel : le système écrit plus long, pas mieux — et les utilisateurs se plaignent de verbosité. Le juge non validé a détourné un mois d'effort. Valider le juge (kappa, analyse des désaccords) AVANT de l'utiliser à l'échelle est ce qui évite ce gâchis. « Je valide mon évaluateur contre l'humain avec un kappa » est une phrase qui signale un niveau d'évaluation que très peu de candidats atteignent.

## 🎤 Question d'entretien
**« Ton évaluation repose sur un LLM-judge : comment sais-tu qu'il est fiable ? »** → Je le valide contre des jugements humains de référence (15-20 cas dont des cas limites), avec Cohen's kappa — pas l'accord brut, qui est flatté par les classes déséquilibrées (un juge qui dit toujours « fidèle » a 90 % d'accord et κ≈0). J'analyse les désaccords pour trouver les biais SYSTÉMATIQUES (souvent la longueur), je corrige le prompt du juge, je revalide. Et je mesure l'accord humain-humain comme plafond : exiger du juge mieux que ce que deux humains obtiennent est absurde. Un juge validé une fois se revalide quand le modèle ou le prompt change.
