## 🎯 Objectif du jour
Prouver les affirmations.

## 📖 Cours approfondi
**Modèle mental : une citation non vérifiée est une décoration ; une citation vérifiée est une preuve.** Ton RAG cite ses sources depuis le jour 220 — mais rien ne garantit que la source citée [2] contient RÉELLEMENT l'affirmation qu'elle est censée soutenir. Le modèle peut citer par habitude, citer le mauvais chunk, ou affirmer quelque chose d'absent de TOUTES les sources tout en collant une citation plausible. La vérification automatique des citations transforme la citation de promesse en garantie — et c'est la couche d'ancrage (C4 du jour 261) qui neutralise l'injection indirecte.

Le mécanisme : après génération, pour CHAQUE affirmation de la réponse, vérifier qu'un extrait cité la soutient effectivement. Deux niveaux de rigueur :
1. **Vérification de présence (simple)** : l'affirmation a-t-elle un recouvrement textuel/sémantique suffisant avec le chunk cité ? Rapide, mais faible sur les paraphrases (le modèle reformule légitimement).
2. **Vérification par entailment (robuste)** : un juge (le LLM-as-judge de fidélité du jour 255, réutilisé !) vérifie que le chunk cité IMPLIQUE l'affirmation — gère les reformulations. Plus cher, plus fiable. On l'a déjà construit : la vérification de citations EST une application de la mesure de fidélité, appliquée affirmation par affirmation avec sa source explicite.

La politique quand une citation est invalide : ne PAS afficher l'affirmation non soutenue. Options selon le cas — retirer l'affirmation, marquer « non vérifié », ou refuser la réponse entière si le cœur n'est pas ancré. Le choix dépend du domaine (un assistant juridique refuse ; un assistant de brainstorming marque). Ce qui compte : une affirmation non ancrée n'atteint JAMAIS l'utilisateur avec l'apparence d'un fait sourcé.

Le coût et le trade-off : vérifier chaque affirmation ajoute de la latence et du coût (un appel de juge par affirmation, ou par réponse). On arbitre : vérification systématique pour les domaines sensibles, échantillonnée ou déclenchée par un score de confiance faible ailleurs. Et la limite honnête : la vérification garantit l'ANCRAGE (l'affirmation vient des sources), pas la VÉRITÉ (une source fausse produit une affirmation ancrée mais fausse — d'où l'importance de la qualité du corpus, jour 256, cas « fidèle mais inexact »).

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : vérification automatique que chaque affirmation citée est soutenue par sa source.

**Raisonnement** : décomposer la réponse en affirmations sourcées, vérifier chacune contre son chunk cité (réutiliser le juge de fidélité), appliquer la politique de non-affichage.

**Implémentation** :
```python
def verifier_citations(reponse: str, chunks_cites: dict) -> Verification:
    affirmations = decomposer_avec_citations(reponse)   # [(texte, [ids cités])]
    resultats = []
    for texte, ids in affirmations:
        if not ids:                                      # affirmation SANS citation
            resultats.append((texte, "non_sourcee"))
            continue
        sources = [chunks_cites[i] for i in ids]
        # réutilise la logique de fidélité (jour 255) : la source implique-t-elle l'affirmation ?
        soutenue = juge_entailment(texte, sources).verdict == "soutenue"
        resultats.append((texte, "verifiee" if soutenue else "non_soutenue"))
    return Verification(resultats)

def appliquer_politique(rep, verif, mode="sensible"):
    non_ancrees = [t for t, v in verif.resultats if v != "verifiee"]
    if mode == "sensible" and non_ancrees:
        return REFUS if est_coeur(non_ancrees) else retirer(rep, non_ancrees)
    return marquer_non_verifie(rep, non_ancrees)         # mode tolérant
```

**Le test (dont un cas d'injection)** :
```
1. Réponse normale bien sourcée -> toutes affirmations vérifiées, affichée intacte.
2. Réponse où le modèle a ajouté une affirmation de sa mémoire (non dans les sources)
   -> détectée "non_soutenue", retirée ou refus.
3. La réponse à l'injection INDIRECTE du jour 260 (« contactez le 06-XX »)
   -> cette affirmation n'est soutenue par AUCUNE source légitime -> bloquée.
4. Paraphrase légitime (source dit "quatorze jours", réponse dit "2 semaines")
   -> l'entailment doit la valider (sinon trop strict) : ajuste le juge.
```

**Explication** : le cas 3 est la démonstration que la vérification de citations EST une défense anti-injection — l'affirmation injectée n'a pas de source légitime, donc elle ne passe pas. Le cas 4 rappelle l'arbitrage : trop strict rejette les paraphrases valides. **Variante** : mesure le surcoût (latence, €) de la vérification systématique sur ton golden set, et conçois un déclenchement conditionnel (vérifier seulement si le score de retrieval est faible ou si l'affirmation contient des chiffres/entités).

## ⚠️ Erreurs fréquentes
- Vérification trop stricte (présence textuelle exacte) : elle rejette les paraphrases légitimes — l'entailment gère les reformulations, un simple grep non.
- Oublier les affirmations SANS citation : ce sont les plus suspectes (le modèle affirme sans source) — elles doivent être traitées, pas ignorées.
- Croire que la vérification garantit la vérité : elle garantit l'ancrage dans les sources ; une source fausse passe (cas fidèle-mais-inexact, jour 256).
- Ignorer le coût : vérifier chaque affirmation par un juge ajoute latence et €  — arbitrer (systématique en domaine sensible, conditionnel ailleurs).

## 🏢 Cas métier
Dans les domaines à enjeu (juridique, médical, financier), la vérification des citations n'est pas optionnelle : une affirmation non sourcée présentée comme sourcée est une responsabilité légale (rappelle l'affaire des jurisprudences inventées, jour 201). Les produits sérieux affichent des citations CLIQUABLES et VÉRIFIÉES — l'utilisateur peut contrôler, et le système garantit l'ancrage en amont. C'est ce qui fait la différence entre un assistant qu'un professionnel ose utiliser et un gadget. Savoir construire cette vérification est une compétence directement facturable.

## 🎤 Question d'entretien
**« Comment garantis-tu qu'une réponse RAG est vraiment fondée sur ses sources ? »** → Vérification automatique des citations : après génération, chaque affirmation est vérifiée contre le chunk qu'elle cite, par entailment (le juge de fidélité réutilisé — la source implique-t-elle l'affirmation ?). Une affirmation non soutenue n'atteint pas l'utilisateur : retirée, marquée, ou refus selon le domaine. Ça neutralise aussi l'injection indirecte (l'affirmation injectée n'a pas de source légitime). Limite honnête : ça garantit l'ancrage, pas la vérité — une source fausse produit une affirmation ancrée mais fausse.
