## 🎯 Objectif du jour
Visualiser la qualité.

## 📖 Cours approfondi
**Modèle mental : un dashboard de qualité rend la TENDANCE visible — et en évaluation IA, la tendance (est-ce que ça s'améliore ?) compte plus que la valeur absolue (le score du jour).** Après le harnais (jour 317), tu construis un dashboard qui affiche les scores par version de DocSense. Le point clé, contre-intuitif : ce qui importe n'est pas « fidélité = 0,88 » dans l'absolu (difficile à interpréter seul) mais « fidélité 0,81 → 0,85 → 0,88 sur trois versions » (une trajectoire claire). Visualiser la tendance transforme des chiffres isolés en histoire de progrès.

Ce que le dashboard apporte :
1. **La tendance par version** : chaque campagne d'évaluation (jour 317) produit des scores horodatés/versionnés (le modèle de données du jour 304 les porte) ; le dashboard les affiche dans le temps. Une courbe montante rassure et guide ; une courbe plate ou descendante alerte. La tendance est le signal, la valeur absolue le bruit.
2. **La décomposition par dimension et par type** : le dashboard sépare retrieval vs génération, et par type de question (les synthèses vs les factuelles). Une amélioration globale peut cacher une régression sur un type — le dashboard la révèle (le principe du jour 256).
3. **Le récit de progrès** : au-delà du diagnostic, le dashboard RACONTE l'histoire de l'amélioration de DocSense — c'est ce qui alimentera le rapport qualité (jour 334) et la démo (« regarde, la fidélité est passée de 0,81 à 0,92 en 4 versions »). Un dashboard qui raconte une trajectoire est plus convaincant qu'un tableau de chiffres.

Pourquoi la tendance prime : un score absolu est difficile à juger (0,85 est-il bon ? ça dépend du corpus, des questions, du juge) ; une tendance est sans ambiguïté (ça monte ou ça descend). En pilotant par la tendance, tu sais si tes changements AMÉLIORENT réellement, indépendamment de la difficulté absolue du benchmark. C'est aussi ce qui rend la communication de la qualité puissante : montrer une courbe qui monte est immédiatement compris par un manager ou un recruteur, là où un chiffre isolé demande un contexte. Le dashboard est l'outil qui transforme l'évaluation d'une mesure technique en un récit de valeur.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : un dashboard de qualité DocSense affichant les scores par version (tendance > absolu).

**Exemple simple** : la visualisation clé est une courbe — fidélité par version (v0, v1, v2...) dans le temps. Une ligne qui monte dit « ça s'améliore » sans ambiguïté ; un chiffre isolé demande un contexte.

**Raisonnement pas-à-pas** : stocker les rapports versionnés, les afficher en tendance, décomposer par dimension et type, raconter le progrès.

**Structure du dashboard** :
```
Source : les rapports du harnais (j.317), versionnés (modèle de données j.304)
Affichage :
  1. Tendance par métrique : courbe rappel@3, fidélité, exactitude par version
  2. Décomposition par type : factuelles vs reformulées vs synthèses par version
     → révèle les régressions locales cachées par un gain global (j.256)
  3. Coût et latence par version (l'amélioration de qualité ne doit pas les exploser)
Principe : la TENDANCE (ça monte/descend) prime sur la valeur absolue (le score du jour)
```

**Mini-quiz** : (a) Pourquoi la tendance prime-t-elle sur la valeur absolue ? (b) Que révèle la décomposition par type qu'un score global cache ? (c) Que raconte un bon dashboard au-delà du diagnostic ?
→ (a) un score absolu est ambigu (0,85 bon ou pas ?), une tendance est sans ambiguïté (monte ou descend) ; (b) une régression locale cachée par un gain global ; (c) l'histoire du progrès de DocSense — convaincant pour un manager/recruteur.

**Variante** : ajoute au dashboard une annotation par version (« v2 : ajout du reranking ») — relier chaque saut de courbe au changement qui l'a causé transforme le dashboard en journal d'amélioration.

## 🏢 Cas métier
Le dashboard de tendance est l'outil de pilotage des équipes ML : il rend visible si les efforts d'amélioration paient (courbe montante) ou non (courbe plate), et il communique la valeur bien mieux qu'un tableau de chiffres. En entreprise, un dashboard qui montre la qualité s'améliorer version après version est ce qui justifie de continuer à investir dans un projet — un manager comprend une courbe montante instantanément. Pour DocSense, le dashboard raconte l'histoire du progrès (fidélité de 0,81 à 0,92 en 4 versions) qui alimentera le rapport final et la démo. Privilégier la tendance sur la valeur absolue est un réflexe d'évaluation mûr : ce qui compte est de savoir si on progresse, pas de contempler un score isolé difficile à interpréter.

## 🎤 Question d'entretien
**« Comment suis-tu la qualité d'un système IA dans le temps ? »** → Par un dashboard de TENDANCE, pas de valeur absolue : chaque campagne d'évaluation produit des scores versionnés, le dashboard les affiche dans le temps (courbes de rappel@k, fidélité, exactitude par version). Ce qui compte est la tendance (ça monte ou descend, sans ambiguïté), pas le score du jour (0,85 est difficile à juger dans l'absolu). Je décompose par dimension et par type pour révéler les régressions locales qu'un gain global cache, et j'annote chaque version par le changement qui l'a causée. Le dashboard raconte l'histoire du progrès — convaincant pour un manager comme en démo.
