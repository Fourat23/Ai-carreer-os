## 🎯 Objectif du jour
Remplacer le stockage mémoire par SQLite avec requêtes paramétrées.

## 📖 Cours approfondi
**Concepts abordés :** better-sqlite3 / node:sqlite · Requêtes paramétrées · Schéma/init versionné · Injection SQL et prévention · Couche data isolée.

L'injection SQL est la faille historique n°1 : si tu CONCATÈNES l'entrée utilisateur dans ta requête (`"SELECT * WHERE nom = '" + input + "'"`), un input malin (`' OR 1=1 --`) devient du code SQL exécuté. Vol de données, destruction de tables : tout devient possible.

La défense est simple et absolue : les requêtes PARAMÉTRÉES. `SELECT * WHERE nom = ?` + la valeur passée séparément — le moteur traite l'entrée comme une DONNÉE, jamais comme du code. Règle à vie : zéro concaténation de SQL, sans exception.

La couche data isolée (un module qui contient TOUT le SQL) prépare la suite : le jour où SQLite devient PostgreSQL, un seul fichier change. C'est ton interface Store du projet 1, appliquée à une vraie base.

## ⚠️ Erreurs fréquentes
- Concaténer des strings dans le SQL = faille béante.
- Schéma non versionné (irreproductible).
