## 🎯 Objectif du jour
Coder un agent sans framework.

## 📖 Cours approfondi
**Modèle mental : un agent est une BOUCLE qui décide de sa prochaine action à chaque tour — pas un mégaprompt magique.** Tu as construit un assistant à outils (jours 207, 213) où TON code décidait du flux ; un agent inverse la commande : c'est le MODÈLE qui décide, à chaque itération, quelle action entreprendre en fonction de ce qu'il observe. La boucle canonique est **plan → act → observe**, répétée jusqu'à ce que l'objectif soit atteint ou qu'un budget soit épuisé :
1. **Plan/décide** : le modèle, voyant l'objectif et l'historique, choisit la prochaine action (appeler tel outil avec tels arguments, ou conclure).
2. **Act** : TON code exécute l'action choisie (l'outil) — le modèle ne touche jamais l'exécution (frontière de confiance, jour 207).
3. **Observe** : le résultat de l'action est réinjecté dans le contexte ; le modèle observe et re-décide.

Ce qui rend un agent DIFFÉRENT d'un simple appel à outils : l'itération pilotée par le modèle (le nombre de tours n'est pas fixé d'avance) et donc le besoin de GARDE-FOUS structurels, non négociables dès la v1 :
- **Un budget d'itérations** (une limite dure) : sans lui, un agent qui n'atteint pas son but boucle à l'infini — et chaque tour COÛTE un appel LLM.
- **Un arrêt propre** : conditions de terminaison claires (objectif atteint, budget épuisé, échec irrécupérable), jamais un plantage.
- **Des traces** : chaque tour affiche ce que l'agent a décidé, exécuté, observé — sans traces, un agent est une boîte noire indébuggable (jour 275 en dépend).

Le coder SANS framework (LangChain, etc.) est délibéré : la boucle fait 30 lignes, et la comprendre à nu te permettra de débugger les frameworks au lieu de les subir — exactement comme coder un neurone en NumPy avant PyTorch (jour 183). L'agent n'est pas de la magie : c'est une boucle while avec un LLM comme décideur et des garde-fous.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : un agent plan/act/observe à 3 outils, avec budget, traces et arrêt propre.

**Exemple simple** : la boucle nue, sans outils, tient en une image — `while tour < budget: action = modèle(objectif, historique); if action == "fini": break; observation = exécuter(action); historique += observation`. Tout le reste est du détail.

**Raisonnement pas-à-pas** : le modèle décide, ton code exécute et trace, la boucle s'arrête sur objectif atteint OU budget épuisé.

**Implémentation** :
```python
def agent(objectif: str, outils: dict, budget=8) -> str:
    historique = [f"OBJECTIF : {objectif}"]
    for tour in range(budget):
        decision = llm_call(                       # le modèle DÉCIDE
            system="Choisis la prochaine action : soit un appel d'outil "
                   "(nom + arguments JSON), soit TERMINER avec la réponse finale.",
            prompt="\n".join(historique), temp=0, schema=Decision)
        trace(tour, decision)                      # TRACE : indispensable (jour 275)
        if decision.type == "terminer":
            return decision.reponse                 # ARRÊT propre : objectif atteint
        if decision.outil not in outils:
            historique.append(f"ERREUR : outil inconnu {decision.outil}")
            continue
        resultat = outils[decision.outil](**decision.args)   # TON code exécute
        historique.append(f"OBSERVATION (tour {tour}) : {resultat}")
    return "BUDGET ÉPUISÉ sans conclusion"          # ARRÊT propre : garde-fou
```

**Mini-quiz** : (a) Qui décide de la prochaine action dans un agent ? (b) Que se passe-t-il sans budget d'itérations ? (c) Pourquoi les traces sont-elles non négociables ?
→ (a) le modèle, à chaque tour ; (b) boucle infinie possible, chaque tour coûtant un appel ; (c) sans elles l'agent est une boîte noire indébuggable — impossible de voir POURQUOI il a mal agi.

**Variante** : donne à l'agent un objectif atteignable en 2 outils (ex. « quelle est la météo à la capitale de la France ? » → outil capitale puis outil météo) et REGARDE ses traces : décide-t-il l'enchaînement correct ? C'est le premier signe qu'il PLANIFIE.

## 🏢 Cas métier
Tous les produits « agents » (assistants qui réservent, cherchent, orchestrent) sont cette boucle avec plus d'outils et de garde-fous. Les équipes qui ont d'abord construit la boucle à nu débuggent les comportements erratiques en minutes (« le budget est trop bas », « la trace montre qu'il a mal lu l'observation du tour 3 ») ; celles qui ont directement branché un framework regardent des logs opaques sans comprendre. Savoir ce que le framework fait POUR toi — et donc ce qui casse quand il casse — est exactement le profil recherché pour construire des agents fiables.

## 🎤 Question d'entretien
**« Qu'est-ce qui distingue un agent d'un simple appel à un LLM avec des outils ? »** → La boucle pilotée par le modèle : à chaque tour, c'est le MODÈLE qui décide de la prochaine action (plan → act → observe), le nombre de tours n'est pas fixé d'avance. D'où les garde-fous obligatoires dès la v1 : budget d'itérations (sinon boucle infinie, chaque tour coûte un appel), arrêt propre (objectif atteint ou budget épuisé, jamais un plantage), et traces (sinon l'agent est une boîte noire indébuggable). Mon code exécute les actions ; le modèle ne fait que les proposer.
