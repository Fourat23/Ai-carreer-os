### Synthèse de la semaine
La semaine 15 a fait passer React du composant isolé à l'APPLICATION structurée : routing avec l'URL comme état partageable et 404 propre (jour 99), placement de l'état par déduction — lever l'état au plus petit ancêtre commun (100), Context pour l'état global et stable sans props drilling (101), performance par la mesure et l'élimination des re-rendus inutiles (102), accessibilité par le HTML sémantique et le clavier (103), et cadrage complet de BiblioApp — arbre, plan d'état, backlog (104). ### Plan de remédiation (si un critère échoue)
- **État de navigation en mémoire** (pas partageable, retour cassé) : rejoue le jour 99 — l'URL est un état ; `<Link>` pas `<a>` ; paramètres via useParams ; route 404 attrape-tout.
- **État mal placé / props drilling** : reprends le jour 100 — déduis la place de l'état de ses lecteurs et modificateurs (plus petit ancêtre commun) ; données vers le bas, événements vers le haut.
- **Abus de Context** (re-rendus massifs) : jour 101 — Context uniquement pour un état global ET stable ; un état changeant reste local.
- **Optimisation à l'aveugle** : jour 102 — mesure au Profiler AVANT ; la cause est souvent une référence instable ; ne mémoïse que le prouvé.
- **Interface inaccessible** : jour 103 — HTML sémantique dès le départ, audit clavier sans souris, focus visible, labels.
- **Pas de cadrage** : jour 104 — sans arbre + plan d'état + backlog, BiblioApp partira dans le mur ; produis-les avant de coder.

### Questions d'entretien de la semaine
1. **« Pourquoi mettre l'état de navigation dans l'URL ? »** Attendu : URL = état partageable/bookmarkable, bouton retour, rafraîchissement ; `<Link>` pas `<a>` ; 404 attrape-tout.
2. **« Où places-tu un état partagé par deux composants ? »** Attendu : au plus petit ancêtre commun de ses lecteurs et modificateurs ; données vers le bas, événements vers le haut ; props drilling = signal d'un mauvais placement.
3. **« Quand Context, quand des props ? »** Attendu : Context pour du global + stable (thème, utilisateur) car tous les consommateurs re-rendent quand la valeur change ; props pour le local ; savoir refuser Context.
4. **« Comment optimises-tu un re-rendu coûteux ? »** Attendu : mesurer au Profiler d'abord, diagnostiquer la référence instable, memo + useCallback/useMemo ciblés, re-profiler ; jamais par principe.
5. **« Comment démarres-tu une app front ? »** Attendu : arbre de composants, plan d'état (placement + circulation), backlog d'incréments livrables — cadrer avant de coder.
