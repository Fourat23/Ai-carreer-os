## 🎯 Objectif du jour

## 📖 Cours approfondi
**Modèle mental : une probabilité CONDITIONNELLE P(A|B) répond à « sachant B, quelle chance pour A ? », et le théorème de Bayes INVERSE la question — il passe de « quelle est la proba d'un test positif si on est malade » à « quelle est la proba d'être malade si le test est positif ». Cette inversion révèle pourquoi un test très fiable peut produire surtout des FAUX positifs quand la maladie est rare.** Les probabilités ne sont pas un détour mathématique avant le ML : elles sont le langage dans lequel un modèle exprime sa confiance (une régression logistique renvoie P(classe|données)), et le raisonnement bayésien est ce qui permet d'interpréter honnêtement une prédiction.

Les trois notions à maîtriser :
1. **La probabilité conditionnelle** : `P(A|B) = P(A et B) / P(B)`. Elle restreint l'univers à « les cas où B est vrai ». Piège fréquent : confondre `P(A|B)` et `P(B|A)` — « la plupart des malades ont ce symptôme » ne dit RIEN sur « la plupart des gens qui ont ce symptôme sont malades ».
2. **L'indépendance** : A et B sont indépendants si `P(A|B) = P(A)` (savoir B ne change rien à A). Beaucoup de modèles simples (Naive Bayes) SUPPOSENT l'indépendance des features — hypothèse fausse mais souvent utile.
3. **Le théorème de Bayes** : `P(A|B) = P(B|A) · P(A) / P(B)`. Il combine une croyance a priori `P(A)` (le TAUX DE BASE) avec une nouvelle observation. C'est le cœur du « base rate fallacy » : ignorer le taux de base mène à des conclusions absurdes.

L'exemple qui change tout — le test médical : une maladie touche 1 personne sur 1000 (`P(malade)=0,001`). Un test détecte 99 % des malades (`P(+|malade)=0,99`) avec 5 % de faux positifs (`P(+|sain)=0,05`). Si ton test est positif, quelle chance d'être malade ? L'intuition dit « 99 % » ; Bayes dit ~2 %. Pourquoi : sur 1000 personnes, ~1 vraie malade détectée, mais ~50 faux positifs parmi les 999 sains. Les faux positifs ÉCRASENT les vrais parce que la maladie est rare. C'est exactement pourquoi un classifieur à 99 % d'accuracy sur une classe rare peut être inutile (jour 162).

La règle du jour : **raisonne toujours avec le TAUX DE BASE ; ne confonds jamais P(A|B) et P(B|A) ; et souviens-toi qu'un test/modèle très précis sur une population où la cible est rare produit surtout des faux positifs**. Ce réflexe bayésien est ce qui distingue une lecture honnête d'un résultat d'une lecture naïve.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : calculer et interpréter P(malade | test positif) avec Bayes, sur le cas du test médical.

**Exemple simple** : la formule de Bayes en une ligne — `P(A|B) = P(B|A)·P(A) / P(B)`, où `P(B)` (proba d'un test positif) se décompose en « vrais positifs + faux positifs ». C'est ce dénominateur qui contient le taux de base.

**Raisonnement pas-à-pas** : poser les probabilités connues → décomposer P(test+) en vrais + faux positifs → appliquer Bayes → interpréter le résultat au regard du taux de base.

**Implémentation** :
```python
p_malade = 0.001                 # taux de base (prévalence)
p_pos_si_malade = 0.99           # sensibilité (vrais positifs)
p_pos_si_sain = 0.05             # taux de faux positifs

# P(test+) = vrais positifs + faux positifs
p_pos = p_pos_si_malade * p_malade + p_pos_si_sain * (1 - p_malade)

# Bayes : P(malade | test+)
p_malade_si_pos = (p_pos_si_malade * p_malade) / p_pos
print(round(p_malade_si_pos, 3))   # ~0.019 -> ~2 %, pas 99 % !

# Vérification par les effectifs (plus intuitif) sur 100 000 personnes :
#   malades = 100 -> 99 détectés (vrais +)
#   sains  = 99 900 -> ~4 995 faux positifs
#   P(malade|+) = 99 / (99 + 4995) ~ 0.019
```

**Mini-quiz** (réponds sans regarder) : (a) Pourquoi le résultat est-il ~2 % et non 99 % ? (b) Quelle est la différence entre P(test+|malade) et P(malade|test+) ? (c) Qu'est-ce que le « taux de base » et pourquoi l'ignorer trompe ?
→ (a) la maladie est rare : les faux positifs (5 % de 99 900 sains) écrasent les vrais positifs (99 malades) ; (b) la première est la fiabilité du test, la seconde la proba d'être malade sachant un test positif — Bayes les relie via le taux de base ; (c) c'est la prévalence a priori P(malade) ; l'ignorer fait croire qu'un test positif implique presque sûrement la maladie.

**Variante** : refais le calcul si la prévalence passe à 10 % (population à risque) — P(malade|+) grimpe autour de 69 %. Le MÊME test devient bien plus concluant : la fiabilité d'un positif dépend du taux de base, pas seulement du test.

## 🏢 Cas métier
Le raisonnement bayésien et le piège du taux de base gouvernent l'interprétation de tout classifieur en entreprise : un modèle de détection de fraude « à 99 % de précision » testé sur une population où la fraude est rare (0,1 %) noiera les vraies fraudes sous les faux positifs, saturant les équipes d'enquête. Les data scientists qui raisonnent en taux de base calibrent leurs seuils et communiquent honnêtement (« sur 1000 alertes, ~50 vraies ») ; ceux qui lisent l'accuracy naïvement déploient des modèles inutiles ou nuisibles. Comprendre P(cible|signal) vs P(signal|cible) est la base de l'évaluation honnête des modèles et une question d'entretien récurrente en data science.

## 🎤 Question d'entretien
**« Un test dépiste une maladie rare (1/1000) avec 99 % de sensibilité et 5 % de faux positifs. Le test est positif : quelle chance d'être malade ? »** → Environ 2 %, pas 99 %. Raisonnement bayésien : sur 100 000 personnes, ~100 malades (99 détectés) et ~99 900 sains (~4 995 faux positifs) ; donc P(malade|+) ≈ 99 / (99 + 4995) ≈ 2 %. Le piège est le « base rate fallacy » : la maladie est si rare que les faux positifs écrasent les vrais, même avec un test précis. Il ne faut jamais confondre P(test+|malade), la fiabilité du test, avec P(malade|test+), ce qui nous intéresse — Bayes les relie via le taux de base. C'est exactement pourquoi l'accuracy trompe sur les classes déséquilibrées.
