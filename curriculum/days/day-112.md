## 🔁 Revue hebdomadaire

**Thème de la semaine :** Full-stack réel : front + API + auth simple, tests unitaires

### Bilan
Assembler les deux mondes proprement, protéger des routes avec un token simple, et écrire tes premiers vrais tests automatisés.

### Test pratique
90 min : ajoute à l'ensemble citations — un token d'API simple (header vérifié par middleware), le front qui l'envoie, et 6 tests Vitest sur la logique métier (validation, formatage, filtres).

### Test théorique
Pourquoi l'auth par header et pas dans l'URL ; qu'est-ce que CORS et pourquoi ton front le déclenche ; que teste un test unitaire vs un test d'intégration ; qu'est-ce qu'un mock ?

### Mini-projet / livrable
Suite de tests du squelette d'API (semaine 11) : au moins 10 tests couvrant validation et services.

### Checklist
- [ ] CORS compris et configuré (pas copié)
- [ ] Secrets hors du code (fichier .env, .gitignore)
- [ ] Tests qui échouent si je casse le code (vérifié !)
- [ ] La logique testable est séparée d'Express

### Critères de passage à la semaine suivante
- [ ] Auth fonctionnelle front→API
- [ ] 10+ tests verts, et rouges quand on sabote
- [ ] Auto-éval se ≥ 3

### Exercice de réflexion architecturale
Pourquoi la logique métier dans les routes Express est-elle difficile à tester ? Refactore UNE route pour extraire la logique en fonction pure testée. Mesure : nombre de lignes de test nécessaires avant/après.
