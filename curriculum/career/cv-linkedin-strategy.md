# Stratégie CV / LinkedIn / GitHub

Douze mois de travail ne servent à rien s'ils sont invisibles. Ce guide transforme tes acquis en assets de candidature. À travailler surtout en semaine 49-50.

## Principe directeur : preuves, pas promesses
Un recruteur voit des centaines de « motivé, passionné, autonome ». Ces mots sont du **bruit**. Le **signal**, ce sont des preuves chiffrées et vérifiables :
- ❌ « Passionné par l'IA et le machine learning »
- ✅ « Application RAG (DocSense) avec pipeline d'évaluation : fidélité mesurée +18 % après reranking, 40 questions de golden set, suite de tests adverses »

## Le CV (1 page)
### Structure
1. **Titre** : ton objectif clair (« AI / LLM Engineer junior — RAG, évaluation, full-stack »).
2. **Accroche** (2-3 lignes) : qui tu es, ta valeur, orienté preuves. Assume la reconversion comme une force (rigueur, projets concrets).
3. **Projets** (le cœur — avant l'expérience si tu es en reconversion) : 3-4 projets, chacun avec problème → stack → **résultat chiffré** → lien GitHub.
4. **Compétences** : techniques réelles (celles à ≥ 3 sur ta scorecard), groupées (langages, data/ML, LLM/RAG, outils).
5. **Expérience** : ton parcours, reformulé pour valoriser les transférables (rigueur, gestion de projet, communication).
6. **Formation** : ce programme de 12 mois compte (« Formation intensive autodidacte en ingénierie IA — 1500+ h, 7 projets »).

### Règles
- **Une page.** Impitoyable.
- **Verbes d'action + chiffres** : « conçu », « implémenté », « mesuré +X % ».
- **Lisible par un ATS** (pas de colonnes exotiques, mots-clés des offres).
- Un lien **GitHub** et un lien vers **DocSense** en évidence.
- Zéro faute. Fais relire (2 personnes, ou communautés en ligne).

## LinkedIn
- **Titre** : le même que le CV, avec les mots-clés que les recruteurs cherchent (« LLM », « RAG », « Python », « TypeScript »).
- **Section À propos** : ton histoire en 3 paragraphes (d'où tu viens, ce que tu as construit, ce que tu cherches), orientée preuves.
- **Projets épinglés** : DocSense en premier, avec démo.
- **Publie** : ta note « un LLM expliqué à un dev backend » (mois 7), ton retour d'expérience sur l'évaluation RAG, un post sur ton année-programme. La visibilité attire les opportunités.
- **Connecte-toi** à des ingénieurs IA, recruteurs tech, alumni de bootcamps. Interagis (commentaires utiles), ne fais pas que consommer.

## GitHub (ton portfolio vivant)
- **7 repos propres** : description, topics, README exemplaire, licence.
- **README de profil** : sobre, qui te présente et met DocSense en avant.
- **Historique de commits régulier** : la « heatmap » verte prouve la constance sur 12 mois.
- **DocSense en vitrine** : épinglé, README avec chiffres et démo, `docker compose up` qui marche.
- **Pas de code mort ni de secrets commités** (audite avant de rendre public).

## Le README d'un projet (ce qu'un recruteur regarde en 30 secondes)
1. Une phrase : c'est quoi et pour qui.
2. Un **GIF/vidéo** de démo (accroche immédiate).
3. Les **chiffres** (éval, tests, perf).
4. L'architecture (un schéma).
5. Install en 5 minutes.
Les 5 questions du recruteur : *ça fait quoi ? ça marche ? c'est propre ? c'est compris ? ça prouve quoi ?*

## Stratégie de ciblage (30 entreprises, 3 cercles)
- **Cercle 1** (10) : postes juniors IA explicitement ouverts aux reconvertis / autodidactes.
- **Cercle 2** (10) : postes full-stack orientés IA (tu as le profil hybride).
- **Cercle 3** (10) : entreprises « stretch » où tu candidates pour t'entraîner et parfois surprendre.
Personnalise chaque candidature (2-3 lignes montrant que tu connais l'entreprise). Trace tout dans un tableau (entreprise, date, statut, relance).

## Le calendrier (ne pas repousser)
- Semaine 49-50 : CV + LinkedIn + GitHub finalisés.
- Semaine 51 : préparation entretiens + dossier.
- **Jour 358 (semaine 52) : premières candidatures ENVOYÉES**, quoi qu'il arrive. « Prêt » ne suffit pas ; « envoyé » compte. Le perfectionnisme est l'ennemi.

## Négociation (junior IA)
- Renseigne-toi sur les fourchettes réalistes de ton marché/région pour un junior IA.
- Ne donne pas le premier chiffre si tu peux l'éviter ; connais ta fourchette.
- La première offre est un point de départ, pas une fatalité — mais reste réaliste pour un premier poste.
