## 📖 Cours approfondi
**Modèle mental : passer de JavaScript à Python, ce n'est pas apprendre une nouvelle syntaxe pour faire les mêmes gestes — c'est adopter un STYLE IDIOMATIQUE. Le même algorithme s'écrit différemment parce que Python a d'autres idiomes naturels, et écrire du Python « avec un accent JavaScript » fonctionne mais trahit un débutant.** Tu sais déjà programmer (4 mois de JS/TS) ; tu n'apprends pas à penser, tu apprends à t'exprimer dans une nouvelle langue. Python sera ta langue pour la data et l'IA (mois 5+) — d'où l'importance de l'écrire idiomatiquement dès le départ.

Les différences JS → Python qui comptent le plus :
1. **Les blocs : indentation, pas accolades.** En Python, l'indentation EST la syntaxe — pas de `{}`, pas de `;`. Un bloc mal indenté est une erreur, pas un détail de style. C'est déroutant au début, discipline ensuite.
2. **Les boucles-transformations : comprehensions, pas `for...push`.** Là où tu écrivais `const out = []; for (const x of xs) out.push(f(x))`, Python écrit `out = [f(x) for x in xs]` — une COMPREHENSION. Pour filtrer : `[x for x in xs if cond]`. C'est l'idiome le plus caractéristique : un JS-teur écrit des boucles là où un pythoniste écrit des comprehensions.
3. **Les structures : `dict` et `list`, pas objets et tableaux.** L'objet JS `{cle: valeur}` devient le `dict` Python `{'cle': valeur}` (accès `d['cle']` ou `d.get('cle')`). Le tableau devient la `list`. S'ajoutent le `tuple` (séquence immuable, `(a, b)`) et le `set` (ensemble unique) — des structures que JS n'a pas nativement au même niveau.
4. **L'itération : `enumerate` et `zip`, pas les index.** Pour l'indice ET la valeur : `for i, x in enumerate(xs)` (pas `for (let i...)`). Pour parcourir deux listes ensemble : `zip(a, b)`. Itérer par index à la JS est un anti-idiome en Python.
5. **Le nommage et le style (PEP 8)** : `snake_case` pour les variables/fonctions (pas `camelCase`), et une préférence pour le code explicite et lisible.

Et l'outillage indispensable : le **venv** (environnement virtuel). Contrairement à npm qui isole par projet via `node_modules`, Python installe globalement par défaut — le venv crée un environnement isolé par projet (`python -m venv .venv`) pour que les dépendances d'un projet ne polluent pas les autres. Travailler sans venv est la première mauvaise habitude à éviter.

La règle du jour : **écris du Python idiomatique, pas du JavaScript traduit — comprehensions au lieu de boucles-push, dict/tuple/set, enumerate/zip, snake_case, et un venv par projet**. Le même algorithme, exprimé dans les idiomes de la langue.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : réécrire 5 exercices JS du mois 1 en Python IDIOMATIQUE, dans un venv.

**Exemple simple** : la traduction la plus révélatrice — une boucle-push JS devient une comprehension. JS : `const carres = []; for (const n of nums) carres.push(n*n);` → Python : `carres = [n*n for n in nums]`. Si tu écris la version avec `for ... .append()`, tu écris du JS en Python.

**Raisonnement pas-à-pas** : créer le venv → pour chaque exercice, repérer l'idiome JS → le remplacer par l'idiome Python (comprehension, dict, enumerate) → vérifier que c'est lisible et pythonique.

**Solution** :
```python
# venv d'abord : python -m venv .venv && source .venv/bin/activate

# 1. Transformer (JS: map/for-push) → comprehension
carres = [n * n for n in nombres]

# 2. Filtrer (JS: filter/for-if-push) → comprehension conditionnelle
pairs = [n for n in nombres if n % 2 == 0]

# 3. Compter les occurrences (JS: objet + for) → dict
compte = {}
for mot in mots:
    compte[mot] = compte.get(mot, 0) + 1        # .get(cle, defaut) : pas de KeyError

# 4. Indice + valeur (JS: for(let i...)) → enumerate
for i, mot in enumerate(mots):
    print(f"{i}: {mot}")                         # f-string, snake_case

# 5. Deux listes en parallèle (JS: for + index) → zip, et dédoublonner → set
for titre, auteur in zip(titres, auteurs):
    print(f"{titre} — {auteur}")
auteurs_uniques = set(auteurs)                   # ensemble unique
```

**Mini-quiz** : (a) Comment écrit-on `xs.map(f)` idiomatiquement en Python ? (b) Pourquoi `compte.get(mot, 0)` plutôt que `compte[mot]` ? (c) À quoi sert le venv, et en quoi diffère-t-il de npm ?
→ (a) une comprehension : `[f(x) for x in xs]` ; (b) `compte[mot]` lève une KeyError si la clé n'existe pas ; `.get(mot, 0)` renvoie un défaut ; (c) il isole les dépendances par projet, là où Python installe globalement par défaut (npm isole déjà via node_modules).

**Variante** : prends ta version « JS traduit » (avec des boucles-push) et ta version idiomatique côte à côte — la différence de lisibilité EST la leçon. Fais relire par quelqu'un : la version pythonique se lit d'un coup d'œil.

## ⚠️ Erreurs fréquentes
- Écrire des boucles `for ... .append()` là où une comprehension s'impose : du JavaScript traduit, pas du Python.
- Accéder à un dict par `d[cle]` sans gérer la clé absente : KeyError — utiliser `.get(cle, defaut)`.
- Itérer par index (`range(len(xs))`) au lieu d'`enumerate`/`zip` : anti-idiome peu lisible.
- Travailler sans venv : les dépendances polluent l'installation globale (Python installe globalement par défaut, contrairement à npm).

## 🏢 Cas métier
Python est la langue dominante de la data science et de l'IA : pandas, NumPy, scikit-learn, PyTorch — tout ton mois 5 et au-delà s'écrira en Python. Un code écrit idiomatiquement (comprehensions, dict, enumerate) est non seulement plus court mais aussi plus lisible et plus performant que sa traduction littérale depuis JavaScript, et c'est ce que les relecteurs et recruteurs attendent. À l'inverse, du « JavaScript déguisé en Python » (boucles-push partout, camelCase, index manuels) signale immédiatement quelqu'un qui n'a pas intégré la langue.
