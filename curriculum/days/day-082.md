Python sera ta langue du ML (mois 5-7) : quasi toute la stack data/ML (pandas, scikit-learn, PyTorch) est Python. Bonne nouvelle : tu sais déjà PROGRAMMER — c'est un changement de syntaxe, pas de paradigme.

Les correspondances : l'objet JS → le dict, le tableau → la list, les backticks → les f-strings, map/filter → les COMPREHENSIONS (`[x*2 for x in nombres if x > 0]` — le style idiomatique), null → None. Les pièges qui mordent : l'indentation EST la syntaxe (pas d'accolades), `==` compare les valeurs et `is` l'identité, les arguments par défaut mutables sont un piège célèbre.

Le VENV isole les dépendances de chaque projet (l'équivalent du node_modules local) : `python -m venv .venv` puis activation — systématique, sinon les projets se polluent mutuellement. requirements.txt = le package.json de Python.

**Modèle mental : Python sera ta langue du ML (mois 5-7) — quasi toute la stack data/ML (pandas, scikit-learn, PyTorch) est en Python. Bonne nouvelle : tu sais déjà PROGRAMMER. C'est un changement de SYNTAXE, pas de PARADIGME — tu penses déjà en programmeur, tu apprends une nouvelle façon d'écrire les mêmes idées. Les correspondances sont directes (l'objet JS → le dict, le tableau → la list, map/filter → les COMPREHENSIONS), et les pièges sont peu nombreux mais nets (l'indentation EST la syntaxe, `is` vs `==`, les arguments par défaut mutables).** Poser les bases de Python, c'est préparer la data et le ML sur des fondations que tu possèdes déjà.

Pourquoi Python pour la data. L'écosystème data/ML s'est construit en Python : pandas (manipulation de données), scikit-learn (ML classique), PyTorch/TensorFlow (deep learning), tout est là. Apprendre Python n'est pas repartir de zéro — c'est acquérir la SYNTAXE qui te donne accès à cet écosystème, en réutilisant tout ce que tu sais déjà (variables, boucles, fonctions, structures de données, la pensée algorithmique). Le paradigme est le même ; seule l'écriture change.

Les correspondances JS → Python, depuis les fondations. L'OBJET JS (`{clé: valeur}`) devient le **dict** Python. Le TABLEAU devient la **list**. Les BACKTICKS (template strings) deviennent les **f-strings** (`f"valeur = {x}"`). `map`/`filter` deviennent les **COMPREHENSIONS** (`[x*2 for x in nombres if x > 0]`) — le style IDIOMATIQUE de Python, plus concis qu'une boucle. `null` devient **None**. Écrire du Python idiomatique, c'est utiliser ces constructions natives, pas transposer mot à mot du JavaScript.

Les pièges qui mordent, depuis les fondations. **L'indentation EST la syntaxe** : pas d'accolades, les blocs sont définis par l'indentation — une indentation incohérente est une erreur. **`==` vs `is`** : `==` compare les VALEURS, `is` compare l'IDENTITÉ (le même objet en mémoire) — les confondre donne des bugs subtils. **Les arguments par défaut MUTABLES** : un piège célèbre — un argument par défaut `[]` est créé UNE fois et PARTAGÉ entre tous les appels, accumulant les modifications. **Le venv** : oublier d'isoler l'environnement mélange les dépendances des projets.

Le venv, l'hygiène indispensable. Un environnement virtuel (`venv`) ISOLE les dépendances d'un projet : chaque projet a ses propres bibliothèques, sans conflit avec les autres. `requirements.txt` liste ces dépendances pour reproduire l'environnement. C'est l'équivalent Python du `node_modules`/`package.json`, et un réflexe à prendre dès le premier projet.

La différence « JS en Python » vs Python idiomatique. Écrire une boucle `for i in range(len(liste))` avec un index (réflexe JS) au lieu d'une comprehension ou d'un `for x in liste` (idiomatique Python) « marche » mais trahit qu'on n'a pas adopté le langage. Le Python idiomatique (comprehensions, dicts, itération directe) est plus lisible et attendu — apprendre le langage, c'est apprendre ses idiomes, pas seulement sa syntaxe.

Limites et compromis. Python est plus lent que des langages compilés (compensé par des bibliothèques natives optimisées pour la data). Le typage dynamique (comme JS) offre de la souplesse au prix de bugs de type (d'où les type hints, optionnels). Et transposer sans adopter les idiomes produit du code « JS déguisé » qui fonctionne mais n'est pas Python.

La règle du jour : **Python est un changement de SYNTAXE, pas de paradigme — tu sais déjà programmer. Utilise les correspondances (dict, list, comprehensions, f-strings, None) pour écrire du Python IDIOMATIQUE, pas du « JS déguisé ». Attention aux pièges (indentation-syntaxe, `is` vs `==`, arguments par défaut mutables) et isole toujours avec un venv.**

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : transposer une transformation JS (map/filter) en Python IDIOMATIQUE (comprehension), et repérer un piège.

**Exemple simple** : JS vs Python idiomatique. En JS : `nombres.filter(x => x > 0).map(x => x * 2)`. En Python idiomatique : `[x * 2 for x in nombres if x > 0]` — une comprehension, pas une boucle avec index. Le même geste, la syntaxe idiomatique de Python.

**Raisonnement pas-à-pas** : (1) j'identifie le geste (filtrer puis transformer) ; (2) je l'écris en comprehension (idiomatique), pas en boucle indexée (JS déguisé) ; (3) j'utilise un dict pour ce qui serait un objet JS ; (4) je note les pièges rencontrés.

**Implémentation** :
```python
# map/filter JS -> COMPREHENSION Python (idiomatique)
nombres = [1, -2, 3, -4, 5]
doubles_positifs = [x * 2 for x in nombres if x > 0]   # [2, 6, 10]

# objet JS -> dict Python ; f-string pour l'interpolation
livre = {"titre": "Python", "pages": 300}
print(f"{livre['titre']} a {livre['pages']} pages")     # f-string (pas de backticks)

# PIÈGE célèbre : argument par défaut MUTABLE (créé une fois, PARTAGÉ)
def ajouter(element, liste=[]):        # DANGER : le [] est partagé entre appels !
    liste.append(element)
    return liste
print(ajouter(1))   # [1]
print(ajouter(2))   # [1, 2] ?!  -> la liste par défaut a accumulé

# CORRECTION : None comme défaut, créer la liste dans la fonction
def ajouter_ok(element, liste=None):
    if liste is None:      # 'is None', pas '== None' : comparaison d'identité
        liste = []
    liste.append(element)
    return liste
print(ajouter_ok(1))   # [1]
print(ajouter_ok(2))   # [2]  -> corrigé
```

```bash
source .venv/bin/activate
pip install pandas
pip freeze > requirements.txt   # documenter l'environnement (comme package.json)
```
Le même raisonnement de programmeur, en syntaxe Python idiomatique (comprehension, dict, f-string), avec le piège de l'argument par défaut mutable désamorcé (None + is) et l'isolation par venv.
