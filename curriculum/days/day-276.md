## 🎯 Objectif du jour
Appliquer l'agent.

## 📖 Cours approfondi
**Modèle mental : un agent n'est utile que s'il résout un VRAI problème mieux qu'un script — et le bon terrain d'essai est une tâche que tu comprends et peux vérifier.** Après la boucle (274) et ses modes d'échec (275), tu appliques l'agent à un cas concret : un vérificateur de cohérence de documentation qui LIT tes docs (README, ADR, notes) et signale les CONTRADICTIONS — un ADR qui dit « on utilise Chroma » quand le README dit « JSON », une commande de lancement qui a divergé entre deux fichiers. C'est une tâche parfaite pour un agent : elle demande de LIRE plusieurs sources, de RAISONNER sur leur cohérence, et de PRODUIRE un rapport — un enchaînement d'actions dont le nombre dépend du contenu (donc pas un script fixe), et dont TU peux vérifier le résultat (tu connais tes docs).

Ce que ce cas d'usage enseigne au-delà de la boucle :
1. **Le choix des outils façonne l'agent** : lister les documents, lire un document, comparer deux affirmations. Des outils bien pensés (granularité, descriptions claires) rendent l'agent efficace ; des outils flous provoquent les modes d'échec du jour 275.
2. **L'objectif doit être VÉRIFIABLE** : « signale les contradictions » avec un format de sortie précis (fichier, affirmation A, affirmation B, nature du conflit) permet de juger le résultat. Un objectif vague (« améliore ma doc ») invite à la dérive.
3. **Les traces racontent le raisonnement** : sur un cas réel, les traces montrent l'agent LIRE, COMPARER, CONCLURE — tu vois s'il a raté une contradiction (rappel) ou inventé un faux conflit (précision). C'est ta première évaluation d'agent (préfigure jour 285+).

La règle qui gouverne le choix d'un cas d'usage d'agent : il doit être RÉEL (utile pour toi), VÉRIFIABLE (tu peux juger), et JUSTIFIÉ (un agent y apporte quelque chose qu'un script n'apporte pas — ici, le raisonnement sur la cohérence sémantique, qu'un diff textuel ne capte pas). Un agent sur un cas jouet ne prouve rien ; un agent qui trouve une vraie contradiction dans TES docs prouve sa valeur.

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : un agent vérificateur de cohérence de documentation, avec traces.

**Exemple simple** : l'outil le plus simple est `lister_docs()` → renvoie les chemins ; puis `lire(chemin)` → renvoie le texte. Avec ces deux-là et la boucle du jour 274, l'agent peut déjà lire tout ton corpus doc.

**Raisonnement pas-à-pas** : outils de lecture → objectif vérifiable avec format de sortie → l'agent lit, compare, rapporte → tu vérifies le rapport contre ta connaissance des docs.

**Implémentation** :
```python
outils = {
  "lister_docs": lambda: [str(p) for p in Path("docs").glob("**/*.md")],
  "lire": lambda chemin: Path(chemin).read_text()[:3000],
}
objectif = ("Lis tous les documents et signale les CONTRADICTIONS FACTUELLES "
  "entre eux (ex. une techno mentionnée différemment, une commande divergente). "
  "Format : [fichier A] dit X / [fichier B] dit Y / nature du conflit. "
  "Si aucune contradiction : dis-le.")
rapport = agent(objectif, outils, budget=12)   # la boucle du jour 274
# Vérification : compare le rapport à TA connaissance des docs
#   - vraies contradictions trouvées ? (rappel)
#   - faux conflits inventés ? (précision)
```

**Mini-quiz** : (a) Pourquoi cette tâche justifie-t-elle un agent plutôt qu'un script ? (b) Pourquoi l'objectif impose-t-il un format de sortie ? (c) Comment évalues-tu l'agent ?
→ (a) le nombre de lectures/comparaisons dépend du contenu et exige du raisonnement sémantique qu'un diff textuel ne capte pas ; (b) pour rendre le résultat vérifiable et éviter la dérive ; (c) rappel (vraies contradictions trouvées) et précision (faux conflits évités), contre ta connaissance des docs.

**Variante** : glisse VOLONTAIREMENT une contradiction dans tes docs (change une techno dans un seul fichier) et vérifie que l'agent la trouve — c'est ton test de rappel, comme une injection contrôlée (jour 260).

## 🏢 Cas métier
La vérification de cohérence documentaire est un vrai besoin d'entreprise : dans un projet de 50 documents (specs, ADR, runbooks), les contradictions s'accumulent silencieusement (une décision changée mais pas propagée) et causent des bugs et des incidents. Un agent qui signale ces divergences fait un travail qu'un humain ne fait jamais entièrement (trop fastidieux) et qu'un diff ne peut pas faire (il faut comprendre le SENS). C'est un cas d'usage d'agent défendable — utile, vérifiable, et impossible à faire proprement avec un simple script.

## 🎤 Question d'entretien
**« Donne un exemple de tâche où un agent est justifié, et pourquoi. »** → Un vérificateur de cohérence de documentation : il lit plusieurs documents et signale les contradictions sémantiques (une techno mentionnée différemment, une commande divergente). C'est justifié car le nombre de lectures/comparaisons dépend du contenu (pas un script fixe) et il faut RAISONNER sur le sens (un diff textuel ne capte pas qu'« on utilise Chroma » contredit « stockage JSON »). Objectif vérifiable (format précis), et je l'évalue en rappel (vraies contradictions trouvées) et précision (faux conflits évités) contre ma connaissance des docs.

## 🚀 Pourquoi ça comptera plus tard
- **Bankable** : un agent qui trouve de VRAIES contradictions dans une documentation est une démo concrète et vérifiable — bien plus convaincante qu'un agent jouet, et un cas d'usage que les recruteurs comprennent immédiatement.
- Le réflexe « choisir un cas RÉEL, VÉRIFIABLE, JUSTIFIÉ » guide tout choix d'agent — et prépare la décision agent/workflow (jour 278).
- L'évaluation rappel/précision d'un agent préfigure l'évaluation d'agents (thème récurrent) et réutilise ta grille du mois 9.
