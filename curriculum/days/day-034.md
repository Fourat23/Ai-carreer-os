## 🎯 Objectif du jour
Implémenter une liste chaînée et un arbre binaire de recherche, comprendre leurs coûts et parcours (DFS/BFS).

## 📖 Cours approfondi
**Concepts abordés :** Nœud et pointeur · Insertion O(1) / accès O(n) · BST : insert/contains/inorder · DFS vs BFS.

Une liste chaînée est une suite de nœuds où chacun pointe vers le suivant. Insérer en tête = créer un nœud qui pointe vers l'ancienne tête : O(1), là où un tableau doit tout décaler (O(n)). Mais accéder au n-ième élément exige de suivre n pointeurs : O(n), là où le tableau est O(1).

Un arbre binaire de recherche (BST) range chaque valeur : plus petites à gauche, plus grandes à droite. Chercher = éliminer une moitié à chaque étage (la recherche binaire du jour 16, en structure) : O(hauteur). Le parcours « in-order » (gauche, nœud, droite) ressort les valeurs TRIÉES — c'est la propriété qui rend les BST utiles.

Piège célèbre : insérer des valeurs déjà triées dégénère le BST en liste chaînée (O(n)). Les arbres auto-équilibrés (AVL, rouge-noir — à connaître de nom) corrigent ça.

**Modèle mental : une structure de données est un COMPROMIS matérialisé — elle rend certaines opérations rapides en en rendant d'autres lentes. La liste chaînée échange l'accès indexé (O(n)) contre l'insertion en tête (O(1)). Le BST échange l'ordre d'insertion contre une recherche O(log n) — À CONDITION d'être équilibré. Il n'existe pas de structure « meilleure » dans l'absolu : il n'y a que des compromis adaptés (ou non) à un profil d'accès.** Comprendre une structure, c'est savoir ce qu'elle rend cher pour comprendre ce qu'elle rend gratuit.

La liste chaînée, depuis les fondations. Un tableau stocke ses éléments CONTIGUS en mémoire : l'index i se calcule (adresse de base + i × taille) → accès O(1), mais insérer en tête oblige à DÉCALER tout le reste → O(n). Une liste chaînée stocke des NŒUDS dispersés, chacun pointant vers le suivant : insérer en tête = créer un nœud qui pointe l'ancienne tête → O(1), mais accéder au n-ième = suivre n pointeurs → O(n). Le tableau et la liste sont donc des MIROIRS : ce que l'un rend rapide, l'autre le rend lent.

Le BST, depuis les fondations. Un arbre binaire de recherche range chaque valeur selon une règle : plus petites À GAUCHE, plus grandes À DROITE. Chercher revient à la recherche binaire du jour 16, mais EN STRUCTURE : à chaque nœud, on élimine une moitié du sous-arbre → O(hauteur). Si l'arbre est équilibré, hauteur ≈ log₂(n) → recherche O(log n). Le parcours « in-order » (gauche, nœud, droite) ressort les valeurs TRIÉES — c'est LA propriété qui justifie le BST : il maintient un ordre trié tout en permettant insertion et recherche rapides.

La différence entre les parcours (DFS vs BFS). Le **DFS** (parcours en profondeur) plonge dans une branche jusqu'au bout avant de remonter — c'est la récursion naturelle de l'arbre (in-order, pre-order, post-order selon QUAND on visite le nœud). Le **BFS** (parcours en largeur) visite niveau par niveau, à l'aide d'une QUEUE (jour 33) : on enfile la racine, puis on défile un nœud en enfilant ses enfants. DFS utilise la pile (implicite via récursion), BFS utilise la file : le choix dépend de si l'on cherche « en profondeur » (un chemin) ou « au plus proche » (le niveau le plus court).

Le piège majeur et son remède. Insérer des valeurs DÉJÀ TRIÉES dans un BST le fait DÉGÉNÉRER en liste chaînée : chaque insertion va toujours à droite, la hauteur devient n, la recherche retombe à O(n). C'est pourquoi les BST « auto-équilibrés » (AVL, rouge-noir — à connaître de NOM) existent : ils réorganisent l'arbre à chaque insertion pour garantir une hauteur logarithmique.

Limites et compromis en pratique. En réalité, le tableau bat SOUVENT la liste chaînée malgré une meilleure complexité théorique de la liste, à cause du CACHE CPU : les éléments contigus d'un tableau se chargent par blocs, alors que les nœuds dispersés d'une liste provoquent des défauts de cache. La complexité asymptotique n'est pas toute la vérité — le matériel compte.

La règle du jour : **choisis une structure selon son PROFIL D'ACCÈS : liste chaînée pour l'insertion/suppression fréquente sans besoin d'index ; BST (équilibré !) pour maintenir un ensemble trié avec recherche O(log n). Connais le piège du BST dégénéré (données triées) et le rôle du cache CPU qui favorise souvent le tableau en pratique.**

## 🧭 Exemple guidé
*Étudie ce pas-à-pas, puis FERME-le et attaque la pratique autonome de mémoire.*

**Énoncé** : implémenter un BST minimal (insert, contains, inorder) et PROUVER que le parcours in-order ressort les valeurs triées.

**Exemple simple** : insérer `5, 3, 8, 1, 4`. On part de 5 (racine). 3 < 5 → à gauche. 8 > 5 → à droite. 1 < 5, < 3 → à gauche de 3. 4 < 5, > 3 → à droite de 3. In-order (gauche, nœud, droite) parcourt : 1, 3, 4, 5, 8 → TRIÉ. La structure encode l'ordre ; le parcours le révèle.

**Raisonnement pas-à-pas** : (1) insert : comparer la valeur au nœud courant, descendre à gauche si plus petite, à droite si plus grande, s'arrêter à la place vide ; (2) contains : même descente, on élimine une moitié à chaque étape → O(hauteur) ; (3) inorder : récursion gauche → visiter le nœud → récursion droite ; comme tout le sous-arbre gauche est plus petit et le droit plus grand, l'ordre de visite est croissant.

**Implémentation** :
```ts
class Noeud {
  constructor(public valeur: number,
              public gauche: Noeud | null = null,
              public droite: Noeud | null = null) {}
}

class BST {
  private racine: Noeud | null = null;

  insert(v: number): void {
    this.racine = this.inserer(this.racine, v);
  }
  private inserer(n: Noeud | null, v: number): Noeud {
    if (n === null) return new Noeud(v);           // place vide trouvée
    if (v < n.valeur) n.gauche = this.inserer(n.gauche, v);
    else if (v > n.valeur) n.droite = this.inserer(n.droite, v);
    return n;                                      // (doublons ignorés)
  }

  contains(v: number): boolean {
    let n = this.racine;
    while (n) {                                    // O(hauteur) : on élimine une moitié
      if (v === n.valeur) return true;
      n = v < n.valeur ? n.gauche : n.droite;
    }
    return false;
  }

  inorder(): number[] {
    const out: number[] = [];
    const parcourir = (n: Noeud | null) => {
      if (!n) return;
      parcourir(n.gauche);   // 1. tout ce qui est plus petit
      out.push(n.valeur);    // 2. le nœud
      parcourir(n.droite);   // 3. tout ce qui est plus grand
    };
    parcourir(this.racine);
    return out;
  }
}

const arbre = new BST();
[5, 3, 8, 1, 4].forEach(v => arbre.insert(v));
console.log(arbre.inorder());     // [1, 3, 4, 5, 8]  -> trié, PROUVÉ
console.log(arbre.contains(4));   // true
console.log(arbre.contains(7));   // false
```

**La démonstration du piège** : insère `1, 2, 3, 4, 5` (déjà triés) → chaque valeur va à droite → l'arbre est une ligne, hauteur 5 = n → `contains` devient O(n). Tu VOIS pourquoi les arbres auto-équilibrés existent.

## 🏢 Cas métier
Les structures chaînées et arborescentes fondent des systèmes bien réels. Arbres de recherche équilibrés : les INDEX de bases de données (B-trees, cousins des BST) qui rendent une requête SQL sur des millions de lignes quasi instantanée (jour 58) reposent exactement sur « chaque comparaison élimine une fraction des données ». Le système de fichiers, le DOM d'une page web, l'arbre de syntaxe d'un compilateur sont des arbres parcourus en DFS/BFS. Listes chaînées : les files de messages, les historiques, certaines implémentations de LRU cache. Comprendre le piège du BST dégénéré, c'est comprendre pourquoi un index sur une colonne auto-incrémentée mal géré peut se déséquilibrer. En entretien, « inverse un arbre binaire », « trouve la profondeur », « parcours en largeur » sont des grands classiques ; savoir choisir DFS vs BFS et raisonner sur la hauteur est directement évalué.

## 🎤 Question d'entretien
**« Explique la différence de coûts entre un tableau et une liste chaînée, puis pourquoi un BST permet une recherche en O(log n). »** → Le tableau et la liste sont des miroirs. Le tableau range ses éléments contigus : accès indexé O(1) (l'adresse se calcule), mais insertion en tête O(n) (il faut tout décaler). La liste chaînée range des nœuds dispersés reliés par des pointeurs : insertion en tête O(1) (on crée un nœud qui pointe l'ancienne tête), mais accès au n-ième O(n) (suivre n pointeurs). Pour le BST : il range plus petit à gauche, plus grand à droite, donc chercher élimine une moitié du sous-arbre à chaque niveau — c'est la recherche binaire en structure, O(hauteur), soit O(log n) SI l'arbre est équilibré. Le parcours in-order (gauche, nœud, droite) en ressort les valeurs triées. Le piège crucial : insérer des données déjà triées dégénère le BST en liste chaînée (hauteur n, recherche O(n)), d'où les arbres auto-équilibrés comme AVL ou rouge-noir. **Relance possible** : « et en pratique, le tableau ne bat-il pas souvent la liste ? » → si, à cause du cache CPU : les éléments contigus d'un tableau se chargent par blocs, alors que les nœuds dispersés d'une liste provoquent des défauts de cache — la complexité asymptotique ne dit pas tout, le matériel compte.
